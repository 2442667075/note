# whoami 命令笔记（Linux 终端｜查看当前执行用户）

> 作用：打印**当前有效用户名**，也就是你执行这条命令时对应的用户身份。 重点区分：
> 
> - `whoami`：当前**有效用户**（sudo 后执行 whoami，输出 root）
> - `who`：查看所有登录会话
> - `id`：查看 UID、GID、用户组完整信息

## 语法

```
whoami
```

无任何参数

## 实战示例

```
# 查询当前执行命令的用户名
whoami
```

示例输出：

```
liangxu
```

```
# sudo切换身份后再查看
sudo whoami
# 输出 root
```

## ⚠️ 嵌入式 Linux 重点注意

1. 嵌入式系统经常使用 root 直接登录，`whoami`直接输出`root`。
2. `sudo`、`su`会改变有效用户，`whoami`反映**当前进程身份**，不是最初登录的账号。
3. BusyBox 内置 whoami，嵌入式 rootfs 一般默认自带，无需额外安装。

### 用户相关命令对比

表格

|命令|作用|
|---|---|
|whoami|输出当前有效用户名|
|who|列出所有终端登录会话|
|id|查看 uid/gid/ 所属用户组，信息最全|

## 面试背诵要点

whoami 用于输出当前有效执行用户。使用 sudo 切换身份后，whoami 会显示 root，它展示的是进程当前身份，不是原始登录用户；BusyBox 嵌入式系统默认自带 whoami。如果想看完整 UID、GID 信息，用 id 命令。

## 易错坑

- whoami 看的是**有效用户**，不是登录用户。`sudo whoami`得到 root，而不是你登录的普通账号。
- 和`who`不要混淆：who 是查看所有登录主机的会话，不是当前执行身份。

# who 命令笔记（Linux 终端｜查看系统登录会话）

> 作用：查看**当前所有登录到系统的会话信息**，包含用户名、终端、登录时间、登录来源 IP。 区分重点：
> 
> - `whoami`：当前执行命令的**有效用户名**（单用户身份）
> - `who`：系统上**全部登录会话**（多用户、多终端）
> - `id`：查看 UID/GID、用户组详细信息

## 语法

```
who [参数]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-H`|打印标题栏，方便看懂各列含义|
|必须掌握|`-a`|输出全部完整信息（包含启动时间、空闲时间、PID 等）|
|必须掌握|`-b`|只查看系统最近一次开机启动时间|
|了解即可|`-l`|系统登录进程（login 进程）|
|了解即可|`-t`|系统上次锁定时间|
|了解即可|`-u`|已登录用户列表（默认行为，who 本身就输出登录用户）|
|了解即可|`-q`|精简模式，只输出登录用户名 + 用户总数量|
|了解即可|`-T`|显示终端属性（是否可写）|

## 实战示例

```
# 查看当前所有登录会话
who

# 带标题栏查看登录信息
who -H

# 带标题，输出全部完整信息
who -H -a

# 查看系统最近开机时间
who -b

# 精简模式：用户名+在线人数
who -q

# 带标题，显示终端读写属性
who -T -H
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 支持精简版`who`，但部分参数（如 `-t`）在 BusyBox 中可能不支持，优先用`who`、`who -H`、`who -b`。
2. 区分：ssh 远程登录、串口终端、本地控制台，都会被 who 识别为独立会话；同一个账号可以多处登录，会显示多条记录。
3. `who`看的是**登录会话**，不是进程身份；sudo 切换用户不会新增 who 记录，只是改变进程有效身份。

### 用户相关命令对比

表格

|命令|作用|
|---|---|
|whoami|当前执行命令的有效用户名|
|who|列出系统所有登录会话（多终端 / 多用户）|
|id|UID/GID、用户组完整信息|

## 面试背诵要点

who 命令用于查看系统所有登录会话，输出用户名、终端、登录时间、来源。`-H`增加标题栏，`-a`输出完整信息，`-b`查看系统启动时间，`-q`精简输出用户名和总人数。 who 查看的是登录会话，和 whoami（当前执行身份）不一样；嵌入式 BusyBox 内置 who，但部分扩展参数会缺失。

## 易错坑

- who 展示**所有登录会话**，不是只看你当前执行命令的用户，和 whoami 不要混淆。
- sudo 切换用户不会新增 who 的登录记录，who 记录的是登录时建立的会话。
- BusyBox 的 who 是阉割版本，部分参数不生效，面试和调试优先记住`who`、`who -H`、`who -b`。
# w 命令笔记（Linux 终端｜查看登录用户 + 系统负载）

> 作用：显示**当前登录用户、终端、来源、空闲时间，同时附带系统负载信息**。 对比区分：
> 
> - `whoami`：当前执行命令的有效用户名
> - `who`：仅列出登录会话，不带负载、进程信息
> - `w` = who + 系统 uptime + 用户正在执行的进程，信息最丰富

## 语法

```
w [参数]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-h`|不打印头部信息（不输出系统负载那一行）|
|必须掌握|`-s`|简短输出格式，省略登录进程、CPU 时间|
|必须掌握|`-i`|显示登录 IP，而不是主机名（ssh 远程调试很常用）|
|了解即可|`-f`|显示登录来源信息（部分系统默认开启）|
|了解即可|`-o`|老式输出格式|
|了解即可|`-u`|计算 CPU 时间时忽略用户名（很少用）|

## 实战示例

```
# 默认，查看所有登录用户+系统负载
w

# 不打印头部信息
w -h

# 简短输出
w -s

# 显示IP地址，不解析主机名
w -i

# 显示登录来源
w -f
```

输出头部含义：

```
 15:30:00 up 2h10m,  2 users,  load average: 0.21, 0.18, 0.15
```

- 当前时间、系统开机时长、在线用户数、1/5/15 分钟平均负载

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox**精简版不一定自带 w 命令**，很多嵌入式 rootfs 只提供`who`，没有`w`；调试时如果提示`w: not found`改用`who`。
2. 第一行的 load average 是面试高频考点，代表系统 CPU 排队任务数量。
3. 同一个用户多终端登录，`w`会展示多条会话，还能看到该终端当前正在跑什么命令。
4. ssh 远程登录场景，`w -i`直接看到对方 IP，排查在线连接非常好用。

### 用户相关命令对比

表格

|命令|核心信息|嵌入式预装情况|
|---|---|---|
|whoami|当前有效用户名|BusyBox 自带|
|who|全部登录会话，无负载|BusyBox 自带|
|w|登录会话 + 负载 + 用户进程|BusyBox 一般不带|
|id|UID/GID、用户组信息|BusyBox 自带|

## 面试背诵要点

w 命令用来查看当前登录用户，同时输出系统运行时间、在线用户数量和 1/5/15 分钟负载。`-h`去掉头部负载信息，`-s`简短输出，`-i`直接显示登录 IP。 w 相比 who 信息更多，能看到用户空闲时间和正在执行的进程；嵌入式 BusyBox 很多版本没有 w 命令，这时用 who 替代。负载是面试重点，load average 反映系统任务排队情况。

## 易错坑

- `w`第一行是系统负载，不是用户信息，很多初学者忽略。
- BusyBox 不一定包含 w，嵌入式设备调试不要默认能用 w。
- `w`看到的是**登录会话**，sudo 切换身份不会新增一条 w 记录。

# last 命令笔记（Linux 终端｜查看历史登录记录）

> 作用：读取 `/var/log/wtmp` 日志，查看**历史登录、登出、系统重启记录**（不是实时在线用户，是历史记录） 区分：
> 
> - `who` / `w`：**当前在线会话**
> - `last`：**过去所有登录历史，包含关机、重启记录**

## 语法

```
last [选项]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-n <num>` / `-<num>`|指定输出最近多少条记录，`last -5`等价`last -n 5`|
|必须掌握|`-i`|直接显示登录 IP，不解析主机名，排查 ssh 来源常用|
|了解即可|`-R`|省略主机名 / IP 那一栏，精简输出|
|了解即可|`-a`|把登录来源 IP / 主机名放到最后一列|

## 实战示例

```
# 查看全部历史登录记录
last

# 只看最近5条登录记录（两种写法等价）
last -n 5
last -5

# 最近5条，省略主机名列，精简输出
last -n 5 -R

# 最近5条，IP放在末尾，直接显示IP
last -n 5 -a -i
```

输出关键字段：用户名、终端、来源 IP、登录时间、登出时间 / 状态

- `still logged in`：用户当前还在线
- `reboot`：系统重启记录

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox**很多版本不带 last**，依赖 wtmp 日志文件；小型 rootfs 默认不开启 wtmp 日志，执行 last 会提示无文件或命令不存在。
2. 日志文件`/var/log/wtmp`可以被删除，日志丢失则查不到历史登录。
3. 可单独查询某个用户登录历史：`last root`，只过滤 root 账号记录。

### 用户会话类命令汇总对比

表格

|命令|查看内容|嵌入式预装情况|
|---|---|---|
|whoami|当前进程有效用户名|BusyBox 自带|
|who|当前在线登录会话|BusyBox 自带|
|w|在线会话 + 系统负载 + 进程|BusyBox 一般不带|
|last|历史登录 / 重启记录|BusyBox 大多不带|
|id|UID/GID、用户组信息|BusyBox 自带|

## 面试背诵要点

last 命令读取 wtmp 日志，查看历史登录、登出、系统重启记录。`-n`限定输出条数，`-i`展示 IP，`-R`精简去掉主机名，`-a`将来源放到末尾。 last 是历史记录，和 who/w（实时在线）区分；嵌入式很多根文件系统没有 last，并且 wtmp 日志可清理。

## 易错坑

- last 看**历史登录**，不是当前在线用户，不要和 who/w 混淆。
- wtmp 日志文件丢失，last 就无法查询记录。
- 嵌入式小系统默认没有 last 命令，调试时不要默认存在。
# users 命令笔记（Linux 终端｜极简查看当前登录用户）

> 作用：极简输出**当前系统所有登录用户名**，同一账号多处登录会重复打印。只输出用户名，无额外信息（无终端、IP、负载）。 对比区分：
> 
> - `users`：只打印登录用户名，极简
> - `who`：用户名 + 终端 + 登录时间 + 来源
> - `w`：who 信息 + 系统负载 + 用户进程
> - `whoami`：当前执行命令的单个有效用户

## 语法

```
users
```

无任何参数

## 实战示例

```
# 查看当前登录的所有用户
users
```

示例输出：

```
root liangxu liangxu
```

含义：root 在线，liangxu 打开了 2 个登录会话。

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 一般自带`users`，但属于极简实现。
2. 输出只是用户名列表，**没有任何附加信息**，适合快速看有几个登录，排查详细连接请用`who`。
3. 同一用户多终端登录，users 会重复输出用户名，可以用`users | tr ' ' '\n' | sort | uniq`去重统计独立账号。

### 用户会话命令完整汇总

表格

|命令|输出内容|嵌入式预装情况|
|---|---|---|
|whoami|当前进程有效用户名|BusyBox 自带|
|users|仅登录用户名列表，极简|BusyBox 自带|
|who|登录会话：用户、终端、时间、来源 IP|BusyBox 自带|
|w|who + 系统负载 + 用户进程信息|BusyBox 大多不带|
|last|历史登录、重启记录（读 wtmp 日志）|BusyBox 大多不带|
|id|UID/GID、用户组详细信息|BusyBox 自带|

## 面试背诵要点

users 命令用于快速查看当前登录系统的用户名列表。同一个账号多次登录，用户名会重复出现。输出信息极少，只适合粗略判断在线用户；需要终端、IP 等详细信息改用 who。

## 易错坑

- users 显示**登录会话对应的用户名**，不是当前执行身份，和 whoami 区分。
- 重复的名字代表同一个用户开了多个终端 /ssh 连接，不是多个不同账号。

# useradd 命令笔记（Linux 终端｜新建用户）

> 作用：创建并设置用户信息（底层新建用户命令；Ubuntu 常用 adduser 封装，本质调用 useradd） 区分：
> 
> - `useradd`：底层命令，默认**不创建家目录、不设置密码**
> - `adduser`：Debian/Ubuntu 封装脚本，交互式，自动建家目录、设密码

## 语法

```
useradd [参数] 用户名
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-m`|自动创建用户家目录（最常用）|
|必须掌握|`-d <目录>`|指定登录家目录|
|必须掌握|`-g <群组>`|指定**初始主组**|
|必须掌握|`-G <群组>`|指定**附加组（多个附属组）**|
|必须掌握|`-s <shell>`|指定登录使用的 shell，`/bin/bash`可登录，`/sbin/nologin`禁止登录|
|了解即可|`-M`|**不要**创建家目录|
|了解即可|`-N`|不创建和用户名同名的私有群组|
|了解即可|`-u <UID>`|手动指定用户 ID|
|了解即可|`-c "注释"`|添加用户注释信息|

## 四个核心用户配置文件

1. `/etc/passwd`：用户基础信息（用户名、UID、GID、注释、家目录、shell）
2. `/etc/shadow`：用户密码密文、密码有效期（仅 root 可读）
3. `/etc/group`：用户组信息
4. `/etc/gshadow`：组密码信息

## 实战示例

```
# 直接新建用户（默认不建家目录，不能直接登录）
useradd user1

# 常用完整写法：创建用户 + 自动建家目录 + 指定bash
useradd -m -s /bin/bash user2

# 自动创建家目录
useradd -m username

# 指定自定义家目录
useradd -m -d /new/dir username

# 指定UID
useradd -u 1500 username

# 指定主组
useradd -g group username

# 指定主组 + 多个附加组
useradd -g group -G group1,group2 username

# 指定登录shell
useradd -s /bin/bash username

# 添加用户注释
useradd -c "Test User Account" username
```

> ⚠️ 创建用户后，必须执行 `passwd 用户名` 设置密码，否则无法登录

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 精简版 useradd 支持基础功能，但部分参数（`-G`附加组、shadow 密码）要看 rootfs 配置；很多小型嵌入式系统直接只用 root，不新建普通用户。
2. 禁止登录用户：`-s /sbin/nologin`，常用于后台服务账号。
3. `/etc/shadow` 文件缺失，密码功能失效。

### 用户管理命令前置汇总

表格

|命令|功能|
|---|---|
|whoami|当前进程有效用户名|
|users|极简列出登录用户名|
|who|当前登录会话详情|
|w|登录会话 + 系统负载|
|last|历史登录记录|
|useradd|新建用户|

## 面试背诵要点

useradd 是 Linux 底层创建用户命令。`-m`自动创建家目录，`-g`主组，`-G`附加组，`-s`指定 shell。创建用户后需要 passwd 设置密码。 4 个关键文件：passwd 用户信息，shadow 存放加密密码，group 组信息，gshadow 组密码。Ubuntu 的 adduser 是 useradd 的高层封装。

## 易错坑

- **不加 - m 默认不生成家目录**，很多新手踩坑，新建用户后 cd 无家目录。
- `-g`主组、`-G`附加组，大小写不能搞混。
- useradd**不会自动设置密码**，必须单独 passwd。
- `/sbin/nologin`的用户不能 ssh / 终端登录，适合程序账号。

# adduser 命令笔记（Linux 终端｜交互式新建用户）

> 作用：创建用户账户，**Debian/Ubuntu 特有封装脚本**，底层自动调用 useradd。交互式向导，自动创建家目录、同名用户组，引导设置密码、填写用户信息。 区分：
> 
> - `adduser`：高层封装，Ubuntu/Debian，交互式，自动建家目录、组
> - `useradd`：通用底层命令，CentOS/RHEL 默认，**不加 - m 不会自动创建家目录**

## 语法

```
adduser [参数] 用户名
```

## 参数（常用）

表格

|优先级|参数|作用|
|---|---|---|
|了解即可|`--home`|手动指定家目录|
|了解即可|`--shell`|指定登录 shell|
|了解即可|`--ingroup`|指定主组|

## 实战示例

```
# 创建新用户（交互式，最常用）
adduser newuser
```

执行后交互式提示：设置密码、全名、电话等信息，一路回车可留空。

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox**没有 adduser**，嵌入式根文件系统只支持底层`useradd`。
2. CentOS/RHEL 没有 adduser 命令，只能使用 useradd。
3. adduser 本质脚本，最终写入同样 4 个用户文件：`passwd shadow group gshadow`。

### 用户创建命令对比

表格

|命令|发行版|自动建家目录|交互设置密码|
|---|---|---|---|
|adduser|Ubuntu/Debian|✅ 默认自动创建|✅ 交互式|
|useradd|全发行版通用|❌ 默认不创建，必须加`-m`|❌ 需要手动 passwd 设置密码|

## 面试背诵要点

adduser 是 Ubuntu/Debian 的用户创建脚本，封装了 useradd。执行`adduser newuser`交互式新建用户，自动创建家目录和同名组。CentOS 没有 adduser；嵌入式 BusyBox 不支持 adduser，只用 useradd。

## 易错坑

- CentOS/RHEL 系统敲 adduser 直接报错，不要混淆发行版。
- adduser 不是独立程序，是 perl 脚本，底层依然调用 useradd。
- 嵌入式不要用 adduser，嵌入式只认 useradd。



# passwd 命令笔记（Linux 终端｜修改 / 管理用户密码）

> 作用：修改用户密码，同时支持账号锁定、解锁、密码状态管理，密码信息写入`/etc/shadow`。 区分：普通用户不加用户名，**只能改自己密码**；root 管理员可以修改任意用户密码。

## 语法

```
passwd [参数] 用户名
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-l`|锁定用户密码，禁止登录（root 可用）|
|必须掌握|`-u`|解锁用户密码，恢复登录|
|必须掌握|`-d`|删除已有密码，账号无密码可直接登录|
|必须掌握|`-e`|下次登录强制修改密码|
|必须掌握|`-S`|查询用户密码状态（查看是否锁定、密码有效期）|
|了解即可|`-k`|密码过期后仍可继续使用|

## 实战示例

```
# 修改当前登录用户自身密码
passwd

# 修改指定用户密码（root权限）
passwd liangxu

# 锁定用户liangxu，禁止登录
passwd -l liangxu

# 解锁用户liangxu
passwd -u liangxu

# 用户下次登录必须重置密码
passwd -e liangxu

# 删除用户liangxu的密码
passwd -d liangxu

# 查看用户liangxu密码状态
passwd -S liangxu
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 的 passwd 只支持基础改密码，`-l/-u/-e/-S`这类高级参数**很多精简根文件系统不支持**。
2. 密码存在`/etc/shadow`，如果该文件不存在，密码功能失效。
3. `passwd -d`清空密码，**生产环境慎用**，任何人无需密码直接登录该账号。

### 用户管理命令串联

表格

|命令|功能|
|---|---|
|useradd|底层新建用户|
|adduser|Ubuntu/Debian 交互式新建用户|
|passwd|设置、锁定、查询用户密码|

## 面试背诵要点

passwd 用于管理用户密码。普通用户执行 passwd 只能修改自己密码，root 可以修改所有用户。`-l`锁定账号，`-u`解锁，`-e`强制下次登录改密码，`-S`查看密码状态，`-d`删除密码。密码密文保存在`/etc/shadow`文件。

## 易错坑

- 锁定`passwd -l`不是删密码，是在 shadow 密码字段前加`!`阻止登录。
- 普通用户**不能**执行`passwd 其他用户名`，只有 root 有权限修改别人密码。
- 生产环境不要随便`passwd -d`清空密码，存在巨大安全风险。

# userdel 命令笔记（Linux 终端｜删除用户账户）

> 作用：删除用户账户信息，修改`/etc/passwd`、`/etc/shadow`、`/etc/group`；**默认不删除家目录**。

## 语法

```
userdel [参数] 用户名
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-r`|删除用户，**同时删除家目录与目录内所有文件、用户邮箱**|

## 实战示例

```
# 仅删除用户账号信息，保留家目录
userdel liangxu

# 删除用户账号 + 一并删除家目录（常用）
userdel -r liangxu
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 精简版支持 userdel，但部分极简根文件系统无此命令。
2. 如果用户**正在登录**，直接执行 userdel 会报错，需要先 kill 该用户进程。
3. 不带`-r`时家目录会残留，容易产生垃圾文件与权限遗留。

userdel 用来删除 Linux 用户账号，默认只删账号，**不会自动删除家目录**；`-r`参数会同时删除家目录和用户邮件。用户在线登录状态下无法直接删除。

# su 命令笔记（Linux 终端｜切换用户身份）

> 作用：切换用户身份。`su`只切换用户，**不加载完整环境**；`su -`（等价`su -l`）完全切换，加载目标用户环境变量、切到家目录。

## 语法

```
su [参数] 用户名
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-` / `-l`|完全身份变更，切换到家目录，加载目标用户完整环境变量|
|必须掌握|`-c`|执行完指定命令后，立刻切回原用户身份|
|了解即可|`-f`|适用于 csh/tsch，跳过读取 shell 启动文件|
|了解即可|`-m`|切换身份，**保留原有环境变量不改动**|
|了解即可|`-s`|指定要执行的 shell|

## 实战示例

```
# 切换root（简写，不完整加载环境）
su
su root

# 切换alvin，保留当前目录、不更换完整环境
su alvin

# 完全切换alvin，切到家目录 + 加载alvin环境（最推荐写法 su - alvin）
su - alvin

# 临时以alvin身份执行whoami，执行完自动退回原用户
su -c whoami alvin
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 自带 su，但很多嵌入式默认关闭 root 密码，`su`会失败。
2. `su -` 和普通`su`差别巨大：脚本、环境变量、PATH 经常踩坑，生产尽量用`su -`。
3. 需要目标用户密码；普通用户要切 root，必须知道 root 密码。

### 用户管理命令串联

表格

|命令|功能|
|---|---|
|useradd|底层新建用户|
|adduser|Ubuntu/Debian 交互式新建用户|
|passwd|设置、锁定、查询用户密码|
|userdel|删除用户账号（-r 删除家目录）|
|su|切换用户身份|

## 面试背诵要点

su 用来切换用户身份。`su 用户名`只切换 UID，**不更换环境、不切换到家目录**；`su - 用户名`等价`su -l`，完全登录式切换，加载目标用户环境并进入其家目录。`su -c 命令 用户名`临时用该用户执行一条命令，执行完毕自动返回原用户。切换需要目标账号密码。

## 易错坑

- `su root` 不等于 `su - root`，PATH、环境变量不一致，容易命令找不到。
- 嵌入式很多 root 无密码，su 直接失败，一般用 sudo 或者直接 root 登录。
- su 需要**目标用户密码**，和 sudo 逻辑不同（sudo 是验证当前用户密码）。

# sudo 命令笔记（Linux 终端｜以管理员身份执行指令）

> 作用：临时以 root 或其他指定用户身份执行命令，**验证当前用户密码**，不用知道 root 密码；权限由`/etc/sudoers`控制。

## 语法

```
sudo [参数] 命令
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-l`|列出当前用户拥有的 sudo 权限|
|必须掌握|`-u <用户>`|指定以某个用户身份执行命令；不写`-u`默认 root|

## 配置文件

- `/etc/sudoers`：sudo 权限主配置文件，语法严格，**推荐 visudo 编辑**
- 编辑方式：
    - `sudo visudo`（推荐，自带语法校验，写错不会直接损坏文件）
    - `sudo vim /etc/sudoers`（不推荐，无语法检查，改错会锁死 sudo）
- 配置规则模板：`授权用户/组 主机=[(切换到哪些用户或组)] 允许执行的命令`

## 实战示例

```
# 查看当前用户拥有哪些sudo权限
sudo -l

# 以alvin用户身份执行whoami
sudo -u alvin whoami

# 用root权限重新执行上一条命令（高频）
sudo !!
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 默认**不带 sudo**，需要手动编译安装；很多嵌入式直接用 root 账号，不用 sudo。
2. sudo 和 su 核心区别：sudo 验证**当前用户密码**；su 验证**目标用户密码**。
3. visudo 有语法检测，直接 vim 改 sudoers 一旦语法错误，会直接导致 sudo 全部失效。

### 用户管理命令串联

表格

|命令|功能|
|---|---|
|useradd|底层新建用户|
|adduser|Ubuntu/Debian 交互式新建用户|
|passwd|设置、锁定、查询用户密码|
|userdel|删除用户账号（-r 删除家目录）|
|su|切换用户身份（需要目标用户密码）|
|sudo|临时提权执行命令（需要当前用户密码，由 sudoers 授权）|

## 面试背诵要点

sudo 用于临时以 root 或其他用户执行命令，密码是当前登录用户密码，不需要 root 密码。权限定义在`/etc/sudoers`，编辑优先使用`sudo visudo`。`sudo -l`查看权限；`sudo -u`指定其他用户；`sudo !!`用 root 重新跑上一条命令。su 和 sudo 最大差别：su 是切换账号，sudo 是临时借用权限。

## 易错坑

- 直接 vim 修改 /etc/sudoers，语法错误导致 sudo 瘫痪。
- 混淆 su 与 sudo 密码：su 要 root 密码，sudo 只要自己的密码。
- 嵌入式系统默认没有 sudo 命令，不要在 BusyBox 里直接使用。

# usermod 命令笔记（Linux 终端｜修改用户账号信息）

> 作用：修改已有用户账号的各项属性（UID、家目录、shell、群组、账号锁定、用户名等）

## 语法

```
usermod [参数] 用户名
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|

|必须掌握|`-d <目录>`|修改登录家目录|
|必须掌握|`-g <群组>`|修改**主组**|
|必须掌握|`-G <群组>`|修改**附加群组**（覆盖式，不是追加）|
|必须掌握|`-l <新账号>`|修改用户名|
|必须掌握|`-L`|锁定用户密码，账号无法登录|
|必须掌握|`-s <shell>`|修改登录 shell|
|必须掌握|`-u <uid>`|修改用户 UID|
|必须掌握|`-U`|解除密码锁定|

```
# 修改alvin家目录为/home/hometest

usermod -l harry alvin

# 解锁alvin账号
usermod -U alvin
```

1. BusyBox 精简版本 usermod 支持参数较少，很多嵌入式不支持全部选项。
2. **-G 是覆盖附加组**：想追加附加组要用`usermod -aG`，面试高频坑点。
3. 修改 UID / 家目录后，用户原有文件权限不会自动更新，需要手动 chown。
4. 用户**正在登录状态**，部分 usermod 修改操作会失败。
