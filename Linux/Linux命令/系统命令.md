# iostat 命令笔记（Linux｜IO 与 CPU 性能监控）

> 作用：监控系统块设备 IO、磁盘读写负载，同时查看 CPU 使用率，定位 IO 瓶颈

## 语法

```
iostat [参数] [设备] [间隔秒数] [次数]
```

## 参数

- `-c`：只输出 CPU 统计信息，不显示磁盘
- `-d`：只输出磁盘设备利用率，不显示 CPU
- `-k`：输出单位：KB/s
- `-m`：输出单位：MB/s
- `-p`：显示块设备 + 所有分区统计
- `-t`：每次输出附带当前时间戳
- `-x`：**扩展详细统计（面试重点，await、% util 都在这里）**

## 实战示例

```
# 查看所有设备+CPU负载
iostat

# 每2秒采样，一共输出3次
iostat 2 3

# 只看sda1磁盘IO
iostat -d sda1

# 输出附带时间戳
iostat -t

# 以MB为单位展示
iostat -m

# 查看TPS、读写吞吐量（KB单位）
iostat -d -k 1 1

# 查看磁盘详细IO指标（await、r/w、%util）
iostat -x /dev/sda1

# 组合：磁盘扩展信息，KB单位，1秒刷新1次
iostat -d -x -k 1 1

# 仅监控CPU，每1秒输出，共3次
iostat -c 1 3
```

## 嵌入式 & 面试重点

1. 核心字段（`-x`扩展输出）
    - `tps`：每秒 I/O 请求数
    - `await`：IO 平均等待时间（包含排队 + 磁盘读写，**判断 IO 慢的核心指标**）
    - `%util`：设备利用率，接近 100% 代表磁盘饱和、IO 瓶颈
2. 适用场景：排查应用卡顿、数据库 / 文件读写慢、嵌入式 eMMC/SD 卡 IO 负载。
3. 区分 vmstat 和 iostat：vmstat 看全局概览，iostat 看**单块磁盘 / 分区**详细 IO 指标。

## 易错坑

- `%util` 接近 100% 不绝对等于磁盘卡死，SSD 并行 IO 场景该指标会有误导，要结合 await 一起判断。
- 默认不带 `-x` 时，不会输出 await、r/s、w/s 这些详细延时指标。

# sar 命令笔记（Linux｜系统运行状态统计）

> 作用：全能系统性能采集工具，**既可实时采样，也能查看历史性能日志**；CPU、内存、IO、块设备、换页都能统计，是线上排查性能问题常用工具

## 语法

```
sar [参数] [间隔秒数] [采集次数]
```

## 参数

- `-R`：显示内存状态
- `-b`：显示块设备 I/O 速率
- `-B`：显示换页（page swap）状态
- `-d`：显示每个块设备磁盘状态
- `-i`：指定状态刷新间隔时间
- `-u`：显示 CPU 利用率（最常用）

> 补充常用扩展参数（面试常考）
> 
> - `-q`：查看队列负载、进程队列长度
> - `-n`：网络统计（DEV 网卡流量等）

## 实战示例

```
# 查看CPU利用率（实时采样，默认采样一次）
sar -u

# 查看内存状态
sar -R

# 查看IO速率
sar -b

# 查看块设备磁盘状态
sar -d

# 每2秒采集一次，一共采集5次CPU数据
sar -u 2 5
```

## 嵌入式 & 面试重点

1. sar 最大特点：**自带历史日志**（默认会定时收集系统指标，可回溯过去一段时间系统负载，vmstat/iostat 只看实时）。
2. `-u` CPU 字段：`%user`用户态、`%system`内核态、`%idle`空闲；idle 持续很低代表 CPU 瓶颈。
3. 适用场景：定位偶发卡顿，可回看历史指标，判断是 CPU、内存还是 IO 导致。
4. 嵌入式说明：busybox 一般不带 sar，多用于服务器 Linux。

## 易错坑

- 部分最小化系统默认**没有安装 sar**，需要安装`sysstat`包。
- 历史日志文件默认保存在 `/var/log/sa/`，系统日志轮转会清理旧数据。

# vmstat 命令笔记（Linux｜虚拟内存与系统状态监控）

> 作用：查看**虚拟内存、进程、IO、CPU**系统状态，是性能排查基础工具

## 语法

```
vmstat [选项] [时间间隔] [次数]
```

## 参数

- `-a`：显示活跃内存、非活跃内存统计
- `-f`：系统开机以来 fork 创建进程的总数量
- `-m`：显示 slab 内存缓存信息（内核 slab 分配器）
- `-n`：只在首次输出表头，后续刷新不再打印字段名
- `-s`：一次性输出内存、系统活动的汇总统计信息
- `delay`：刷新间隔（单位秒）；不写则只输出 1 次快照
- `count`：刷新次数；只指定间隔不指定次数，则无限循环输出
- `-d`：磁盘整体读写统计
- `-p 分区`：查看指定磁盘分区读写统计，如 `/dev/sda1`
- `-S`：指定输出单位：k (1000)、K (1024)、m、M；默认 K（1024 字节）

## 实战示例

```
# 输出一次系统状态快照
vmstat

# 每1秒刷新一次，持续监控
vmstat 1

# 显示活跃/非活跃内存
vmstat -a

# 查看开机以来fork总数
vmstat -f

# 内存汇总统计
vmstat -s

# 磁盘整体读写统计
vmstat -d

# 查看sda1分区IO
vmstat -p /dev/sda1

# 查看slab缓存信息，需要root权限
sudo vmstat -m
```

## 嵌入式 & 面试重点

1. vmstat 默认输出字段：`procs(进程)、memory内存、swap交换分区、io块读写、system中断/上下文切换、cpu`。面试重点看 `si/so`（swap 换入换出，si/so 高代表内存不足）、`us,sy,id` CPU 占用。
2. `vmstat 1` 是性能排查常用，持续采样观察系统负载。
3. `-m` slab 信息，内核内存调试、内存泄漏定位场景会用到。
4. 嵌入式 Linux 一般自带 vmstat，可用来定位 OOM 前内存、swap、IO 瓶颈。

## 易错坑

- `si` swap-in，从交换区读入内存；`so` swap-out，内存写入交换区。**si/so 持续大于 0，说明物理内存紧张**。
- 单位 `-S k` 和 `-S K` 不要搞混，一个 1000，一个 1024。


# sar 命令笔记（Linux｜系统运行状态统计）

> 作用：全能性能监控工具，**支持实时采集 + 查看历史性能统计数据**，用于 CPU、内存、IO、块设备、换页等系统指标排查

## 语法

```
sar [参数] [间隔秒数] [采集次数]
```

## 参数

- `-R`：显示内存状态
- `-b`：显示 I/O 速率
- `-B`：显示换页状态
- `-d`：显示每个块设备磁盘状态
- `-i`：状态信息刷新间隔时间
- `-u`：显示 CPU 利用率（高频使用）

> 面试扩展常用参数
> 
> - `-q`：查看系统负载、进程队列长度
> - `-n DEV`：网卡网络流量统计

## 实战示例

```
# 查看CPU利用率（默认单次快照）
sar -u

# 查看内存状态
sar -R

# 查看IO速率
sar -b

# 查看块设备磁盘统计
sar -d

# 每2秒采样一次，一共采集5次CPU数据
sar -u 2 5
```

## 嵌入式 & 面试重点

1. sar 独有的优势：**可回溯历史性能日志**（vmstat/iostat 只能看实时），适合排查偶发、间歇性卡顿。
2. `-u` 输出关键字段：`%user`用户态 CPU、`%system`内核态 CPU、`%idle`空闲 CPU；idle 持续偏低代表 CPU 瓶颈。
3. 依赖包：需要安装`sysstat`；BusyBox 嵌入式系统一般不带 sar，多用于服务器 Linux。
4. 历史日志存放路径：`/var/log/sa/`，日志会自动轮询清理。

## 易错坑

- 最小化系统默认未预装 sar，直接执行会提示命令不存在。
- 历史日志只保留一段时间，太久远的数据无法查看。
# ipcs 命令笔记（Linux｜查看 System V IPC 资源）

> 作用：查看**进程间通信 IPC**设备信息（System V 三种 IPC：共享内存、消息队列、信号量）

## 语法

```
ipcs [参数]
```

## 参数

- `-a`：输出全部 IPC 信息（默认）
- `-m`：只查看**共享内存**段信息
- `-q`：只查看**消息队列**信息
- `-s`：只查看**信号量**信息

## 实战示例

```
# 查看所有IPC资源
ipcs
ipcs -a

# 输出IPC资源的操作时间
ipcs -t

# 输出IPC对应的创建/操作进程PID
ipcs -p

# 输出IPC资源创建者、所有者
ipcs -c

# 输出IPC资源整体统计状态
ipcs -u

# 查看IPC资源的系统上限限制
ipcs -l
```

## 嵌入式 & 面试重点

1. System V IPC 三类资源：**共享内存 shm、消息队列 msg、信号量 sem**，ipcs 专门看这三类。
2. 配套删除命令：`ipcrm`，用来删除僵尸 / 残留的 IPC 资源（面试高频）
    
    ```
    # 示例：按key删除共享内存
    ipcrm -m shmid
    ```
    
3. 场景：排查 IPC 资源泄漏，进程异常退出后，共享内存 / 消息队列不会自动释放，会残留在系统，需要 ipcs 查看、ipcrm 清理。
4. 注意：**ipcs 只针对 System V IPC**；不看管道、socket、信号（signal）、POSIX 消息队列。

## 易错坑

- 进程崩溃后，System V IPC 资源**不会自动销毁**，容易造成资源泄露，需要手动 ipcrm 清理。
- 区分：`ipcs -s` 是 System V 信号量，不是 Linux 的 signal 信号。

# ipcrm 命令笔记（Linux｜删除 System V IPC 资源）

> 作用：删除消息队列、信号量、共享内存（System V IPC）资源标识，清理残留 IPC 资源

## 语法

```
ipcrm [options]
ipcrm <shm|msg|sem> <id> [...]
```

## 参数

- `-m, --shmem-id <id>`：按 id 移除共享内存段
- `-M, --shmem-key <key>`：按 key 键值移除共享内存段
- `-q, --queue-id <id>`：按 id 移除消息队列
- `-Q, --queue-key <key>`：按 key 键值移除消息队列
- `-s, --semaphore-id <id>`：按 id 移除信号量
- `-S, --semaphore-key <key>`：按 key 键值移除信号量
- `-a, --all[=<shm|msg|sem>]`：全部移除指定类型 IPC 资源
- `-v, --verbose`：详细输出，打印操作过程

## 实战示例

```
# 通过id删除共享内存
ipcrm -m 262144

# 通过key删除共享内存
ipcrm -M 0x55

# 通过id删除消息队列
ipcrm -q 252432

# 通过key删除消息队列
ipcrm -Q 0x88

# 通过id删除信号量
ipcrm -s 242438

# 通过key删除信号量
ipcrm -S 0x65

# 删除全部共享内存、信号量、消息队列
ipcrm -a

# 删除全部IPC资源并打印详细过程
ipcrm -v -a
```

## 嵌入式 & 面试重点

1. 配套 `ipcs` 使用：先用`ipcs`查询 IPC 资源 id/key，再用`ipcrm`删除。
2. 核心背景：System V IPC 资源**进程崩溃不会自动释放**，容易资源泄漏，需要手动清理。
3. id 与 key 的区别：
    - key：程序创建 IPC 时传入的键值（应用层约定）
    - id：内核返回的 IPC 实例编号（系统运行时分配）
4. 开发调试场景：IPC 服务异常退出后，旧资源占用导致程序重启失败，用 ipcrm 清理。

## 易错坑

- `ipcrm` 删除的是**IPC 资源标识符**，当还有进程 attach 共享内存时，内核不会立刻释放内存，会等最后一个进程脱离后销毁。
- `-a` 慎用，生产环境不要随意执行，会清空所有 System V IPC。
# uname 命令笔记（Linux｜查看系统内核与硬件信息）

> 作用：显示操作系统、内核版本、硬件架构等系统基础信息

## 语法

```
uname [OPTION]...
```

## 参数

- `-a`：输出系统全部相关信息（最常用）
- `-m`：计算机硬件架构（x86_64 /arm/aarch64）
- `-n`：主机名称
- `-r`：内核发行版本号
- `-s`：内核名称（一般输出 Linux）
- `-v`：内核版本详细信息
- `-p`：主机处理器类型
- `-o`：操作系统名称
- `-i`：硬件平台

## 实战示例

```
# 一次性输出主机名、内核版本、硬件架构全部信息
uname -a

# 仅查看主机名
uname -n

# 仅查看内核发行版本
uname -r

# 仅查看内核名称
uname -s

# 仅查看硬件平台
uname -i

# 打印操作系统类型
uname -o
```

## 嵌入式 & 面试重点

1. 嵌入式开发高频命令，用来快速确认目标板内核版本、CPU 架构（ARM/aarch64），判断交叉编译的镜像是否匹配。
2. `uname -r`：编译内核模块、驱动时经常要核对内核版本，版本不一致模块加载失败。
3. `uname -m`：区分 32 位 arm 与 64 位 aarch64，确定工具链选择。

## 易错坑

- `-i` 在很多现代 x86 电脑上会显示`unknown`，属于正常现象，硬件平台信息不一定全部支持。
- 区分：`uname`看**内核信息**，`lsb_release -a`看发行版（Ubuntu/CentOS）版本。

# hostname 命令笔记（Linux｜查看 / 设置主机名）

> 作用：显示和设置系统主机名

## 语法

```
hostname [参数]
```

## 参数

- `-a`：显示主机别名
- `-d`：显示 DNS 域名
- `-f`：显示 FQDN 完整域名
- `-i`：显示主机 IP 地址
- `-s`：短主机名，在第一个`.`处截断
- `-y`：显示 NIS 域名
- `-I`：显示主机所有 IP 地址

## 注意事项

1. 环境变量 `HOSTNAME` 保存当前主机名：`echo $HOSTNAME`
2. `hostname 新名字`：**临时设置**，重启后失效
3. 永久修改主机名两种方式：
    - 方式 1：修改配置文件 `/etc/hostname` 和 `/etc/hosts`
    - 方式 2：`sudo hostnamectl set-hostname <newhostname>`，**同时必须修改 /etc/hosts**

## 实战示例

```
# 查看当前主机名
hostname

# 临时修改主机名（重启失效）
hostname newname

# 查看本机所有IP
hostname -I
```

## 嵌入式 & 面试重点

1. 主机名作用：网络标识，多台嵌入式设备组网时用来区分设备。
2. 永久改名后，**/etc/hosts 一定要同步更新**，否则 sudo、ssh 会出现解析慢或者报错。
3. `hostnamectl` 是 systemd 系统（Ubuntu、CentOS7+）专用；传统嵌入式 busybox 一般只有基础 hostname 命令，没有 hostnamectl。

## 易错坑

- 用 `hostname` 直接修改只是临时生效，重启恢复原样。
- `/etc/hosts` 不更新，执行 sudo 会提示：`sudo: unable to resolve host xxx`。


# dmesg 命令笔记（Linux｜查看内核环形缓冲区日志）

> 作用：查看开机、内核驱动打印信息（内核 ring buffer 缓冲区日志），调试驱动、硬件异常最常用命令

## 语法

```
dmesg [参数]
```

## 参数

- `-c`：打印日志之后，清空 ring buffer 环形缓冲区
- `-s <缓冲区大小>`：设置读取缓冲区大小，默认 8196，等于 ring buffer 尺寸
- `-n`：设置内核日志记录级别

## 实战示例

```
# 直接查看内核开机信息
dmesg

# 分页浏览
dmesg | less

# 过滤内存、DMA、USB、TTY硬件相关打印
dmesg | grep -i memory
dmesg | grep -i dma
dmesg | grep -i usb
dmesg | grep -i tty

# 显示日志级别、信息（级别：emerg、alert、crit、err、warn、notice、info、debug）
dmesg -x

# 只输出错误、警告级别的日志
dmesg --level=err,warn

# 显示带人类可读时间戳的日志
dmesg -T

# 显示原始日志数据
dmesg -r

# 打印日志并清空环形缓冲区（需要sudo）
sudo dmesg -c
```

## 嵌入式 & 面试重点

1. 本质：dmesg 读取**内核环形缓冲区 ring buffer**，内核 printk 打印的日志都在这里；**重启后缓冲区日志丢失**。
2. 驱动调试核心命令：硬件上电、设备枚举、驱动 probe 失败、OOM 内存溢出、总线报错，优先看 dmesg。
3. printk 日志等级：控制内核打印输出，`dmesg -n`用来调整控制台打印级别。
4. 嵌入式开发：板卡 USB、SD 卡、eMMC、串口、I2C 设备识别失败，第一时间用 dmesg 定位。

## 易错坑

- ring buffer 容量有限，日志会循环覆盖，长时间运行后早期开机日志可能被冲掉。
- `dmesg -c`清空的只是当前内存里的环形缓冲区，**不会影响 /var/log 下持久化的系统日志文件**。

# uptime 命令笔记（Linux｜查看系统开机时长与负载）

> 作用：查看系统启动时间、运行时长以及系统平均负载信息

## 语法

```
uptime [options]
```

## 参数

- `-p`：只显示机器正常运行的时长
- `-s`：输出系统**启动的具体时刻**，格式 yyyy-mm-dd hh:mm:ss

## 实战示例

```
# 默认输出：当前时间、开机多久、登录用户数、1/5/15分钟平均负载
uptime

# 简洁打印运行时长
uptime -p

# 查看系统是什么时间开机的
uptime -s
```

## 嵌入式 & 面试重点

1. uptime 输出的三个负载：**1 分钟、5 分钟、15 分钟平均负载**，代表等待 CPU 的任务队列平均数量。
    - 单核 CPU：负载≈1 代表 CPU 满负荷；多核看核心总数。
2. 开发调试场景：看设备是否意外重启（对比开机时间）、长时间运行观察系统压力。
3. 平均负载不等于 CPU 使用率，负载包含等待 CPU、IO 阻塞的进程。

## 易错坑

- 负载大于 CPU 核心数，代表任务排队，系统压力大。
- busybox 嵌入式小系统可能不支持 `-p` / `-s` 参数，只能用基础 `uptime`。

# free 命令笔记（Linux｜查看内存与 Swap 使用情况）

> 作用：显示系统物理内存、交换分区 Swap 的使用量

## 语法

```
free [参数]
```

## 参数

- `-b`：以 Byte 为单位
- `-k`：以 KB 为单位
- `-m`：以 MB 为单位
- `-g`：以 GB 为单位
- `-s`：持续周期性刷新显示内存
- `-t`：增加一行显示内存总计
- `-h`：人类易读单位（最常用）

## 输出字段说明

- `Mem`：物理内存
- `Swap`：交换空间
- `total`：总内存 / 交换空间大小
- `used`：已使用内存
- `free`：完全空闲内存
- `shared`：共享内存大小
- `buff/cache`：buffer 缓冲区 + page cache 页缓存占用内存
- `available`：**应用程序实际可申请的内存（重点看这个）**

## 实战示例

```
# 默认单位查看内存
free

# MB单位查看
free -m

# 易读单位（推荐）
free -h

# 每3秒刷新一次内存状态
free -hs 3
```

## 嵌入式 & 面试重点

1. Linux 会尽量把空闲内存用作 cache/buffer 加速 IO，**free 数值小不代表内存不足，看 available**。
2. available = free + 可回收的 cache/buffer，是应用能拿到的内存。
3. Swap 升高说明物理内存不够，系统开始使用交换分区，性能会明显下降；嵌入式设备一般禁用 swap。
4. 内存泄漏排查：持续观察 available 持续下降，可结合`free -hs`长时间监控。

## 易错坑

- 老版本 free 输出格式和新版不同，旧版区分 -/+ buffers/cache 行，新版合并为 buff/cache。
- 不要以 free 字段判断内存紧张，优先看 available。

# ulimit 命令笔记（Linux｜shell 进程资源限制）

> 作用：控制 shell 及其子进程的系统资源上限（文件句柄、栈、进程数、core 文件等）

## 语法

```
ulimit [参数]
```

## 参数

- `-a`：查看当前全部资源限制配置
- `-c <core文件上限>`：core 转储文件最大大小，单位块；设为 unlimited 开启 core dump，用于段错误调试
- `-d <数据节区大小>`：进程数据段最大值，单位 KB
- `-f <文件大小>`：shell 可创建文件的最大大小，单位块
- `-H`：设置**硬限制**（hard limit，管理员设定，普通用户不能调高）
- `-m <内存大小>`：进程可用物理内存上限，单位 KB
- `-n <文件数目>`：单个进程最大打开文件描述符数（句柄数，高频面试参数）
- `-p <缓冲区大小>`：管道缓冲区大小，单位 512 字节
- `-s <堆栈大小>`：进程栈空间上限，单位 KB
- `-S`：设置**软限制**（soft limit，默认，用户可自行调低，不能超过硬限制）
- `-t <CPU时间>`：进程 CPU 使用时间上限，单位秒
- `-u <程序数目>`：单个用户最大可创建进程数量
- `-v <虚拟内存大小>`：进程虚拟内存上限，单位 KB

## 实战示例

```
# 查看全部资源限制
ulimit -a

# 设置用户最大进程数上限为500
ulimit -u 500

# 修改单进程最大打开文件句柄数为4096（网络服务常用）
ulimit -n 4096

# 设置虚拟内存上限12800KB
ulimit -v 12800

# 设置进程CPU最多使用2秒
ulimit -t 2
```

## 嵌入式 & 面试重点

1. 软限制 S：生效的限制；硬限制 H：上限天花板，普通用户只能下调软限制，不能突破硬限制。
2. `-n` 文件句柄：服务器 / 网络程序高频考点，高并发场景默认 1024 不够，会报`too many open files`。
3. `-c` core 文件：程序段错误 SIGSEGV 时生成 core 文件，gdb 用来定位崩溃堆栈，嵌入式驱动 / 应用调试常用。
4. **临时生效**：默认只在当前 shell 会话生效；永久修改需要改 `/etc/security/limits.conf`。

## 易错坑

- ulimit 修改是 shell 会话级别的，新开终端会恢复默认，必须改配置文件永久生效。
- hard limit 不能大于内核允许上限；修改 limits.conf 后需要重新登录用户才会加载。
# init 命令笔记（Linux｜切换系统运行级别）

> 作用：切换传统 SysVinit 系统的运行级别（现代 systemd 系统只是兼容支持）

## 运行级别说明

- `init 0`：关机
- `init 1`：单用户模式（root 维护，无网络）
- `init 2`：多用户模式，无 NFS 网络文件系统
- `init 3`：多用户，纯命令行模式（服务器常用）
- `init 4`：保留，一般未使用
- `init 5`：图形化桌面界面模式
- `init 6`：重启系统

## 实战示例

```
init 0    # 关机
init 1    # 进入单用户维护模式
init 3    # 切换到字符终端
init 5    # 切图形桌面
init 6    # 重启
```

## 嵌入式 & 面试重点

1. **SysVinit 与 systemd 区分**：CentOS7、Ubuntu 新版等 systemd 系统，init 只是兼容命令；底层目标用`systemctl isolate`、`systemctl get-default`。
    - systemd 目标对应：multi-user.target（init3）、graphical.target（init5）
2. 单用户 init1：忘记 root 密码修复时常用，不需要网络。
3. 嵌入式 busybox 很多用简化版 init，不一定支持全部 7 个运行级别。

## 易错坑

- `init 0`、`init 6` 不要在生产服务器随意执行，直接关机 / 重启。
- systemd 系统推荐优先用`systemctl`，不推荐依赖 init 运行级别。

# service 命令笔记（Linux｜控制系统服务）

> 作用：控制系统后台服务（SysVinit 传统命令，systemd 系统为兼容保留）

## 语法

```
service [参数]
```

## 参数

- `--status-all`：列出全部服务运行状态
- `start`：启动服务
- `stop`：停止服务
- `restart`：重启服务（先 stop 再 start）
- `status`：查看服务当前运行状态
- `reload`：不重启进程，重新加载配置文件（平滑加载，不中断服务）

## 实战示例

```
# 查看所有服务状态
service --status-all

# 查看sshd服务状态
service sshd status

# 启动sshd
service sshd start

# 停止sshd
service sshd stop

# 重启sshd
service sshd restart
```

## 嵌入式 & 面试重点

1. `service` 是**SysVinit 时代**的命令；CentOS7+/ 新版 Ubuntu 采用 systemd，底层推荐用`systemctl`，`service`只是兼容封装。
2. `restart`：会终止进程再启动，连接会断开；`reload`只重载配置，服务进程不退出（前提：程序支持 reload 信号）。
3. 嵌入式 busybox 也支持简易 service 脚本，用于板卡后台服务启停。

## 易错坑

- reload 不是所有服务都支持，部分服务不支持信号重载，只能用 restart。
- systemd 环境下 `service xxx restart` 等价于 `systemctl restart xxx`。
