# host 命令笔记（DNS 域名查询）

> 作用：**域名 DNS 查询**，解析域名对应的 IP，查看 DNS 记录，排查域名解析问题。

## 语法

```
host [参数] [域名]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-a`|详细查询，尝试获取多种 DNS 记录；**不保证返回域名全部记录**，受 DNS 服务器策略、记录本身限制|
|必须掌握|`-t`|指定查询的 DNS 记录类型（A/AAAA/MX 等）|
|了解即可|`-v`|详细输出模式，展示更多查询信息，行为随版本有差异，不是完整程序执行调试日志|

## 实战示例

```
# 查询域名对应的IP地址（最常用）
host www.baidu.com

# 详细查询，尝试获取多种DNS记录
host -a www.baidu.com

# 查询IPv4 A记录
host -t A www.baidu.com

# 查询IPv6 AAAA记录
host -t AAAA www.baidu.com

# 查询邮件交换MX记录
host -t MX baidu.com

# 指定DNS服务器来解析域名
host www.baidu.com 8.8.8.8
```

## ⚠️ 嵌入式 Linux 重点注意

1. host 属于 bind-utils 工具集，**很多精简嵌入式开发板默认不带**。嵌入式常用替代命令：`nslookup`、`getent hosts`；
2. `ping 域名`仅**辅助判断 DNS**：ping 能解析出 IP 只代表 DNS 生效；ping 不通不代表解析失败，可能目标禁 ICMP、路由异常；DNS 解析 和 IP 连通性是两件独立问题；
3. 域名解析失败排查顺序：

```
# 1. 查看DNS配置文件
cat /etc/resolv.conf
# 2. 查看网卡IP
ip addr
# 3. 查看路由信息
ip route
# 4. 有nslookup就用它做解析测试
nslookup www.baidu.com
# 5. ping DNS服务器，测试网络连通
ping -c 3 8.8.8.8
```

> 注意：`/etc/resolv.conf`可能由网络服务动态生成，手动修改会被覆盖；解析结果还会受 BusyBox 配置、C 库、网络命名空间影响。

## 面试背诵要点

host 是 DNS 查询工具，用于查询域名对应的 IP 地址和其他 DNS 记录。常用 `host 域名` 查询地址，`-t` 指定记录类型，`-a` 获取更详细的多类型记录信息。域名解析失败时，应检查 DNS 配置、服务器可达性和解析结果。嵌入式系统若没有 host，可以使用 nslookup 或其他可用的解析工具；ping 只能辅助排查，不能单独证明 DNS 是否正常。

## 易错坑

- host 依赖`/etc/resolv.conf`DNS 配置，配置错误直接解析失败。
- `host -a`不能拿到域名**全部 DNS 记录**，DNS 服务端会做限制。
- ping 域名成功拿到 IP = DNS 解析成功；ping 返回请求超时 ≠ DNS 解析失败。

# tcpdump 命令笔记（XShell 直接使用｜网络抓包）

> 作用：**监听网络流量，抓取网卡数据包**，定位网络收发异常、协议交互问题，嵌入式网络调试必备抓包工具。

## 语法

```
tcpdump [参数] [过滤表达式]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-i 网卡名`|指定网卡抓包；`-i any`监听本机所有网卡（Linux），但链路层信息会有差异|
|必须掌握|`-D`|列出本机所有可抓包的网络接口|
|必须掌握|`-c N`|抓取 N 个数据包后自动停止，避免无限抓包刷屏|
|必须掌握|`-nn`|不解析 IP、端口对应的域名 / 服务名，输出更快，排障首选|
|必须掌握|`-w xxx.pcap`|抓包保存到 pcap 文件，可在电脑用 Wireshark 分析|
|必须掌握|`-r xxx.pcap`|读取本地已保存的 pcap 抓包文件|
|必须掌握|`host IP`|按 IP 过滤通信报文；不推荐直接写域名，域名 IP 会变动|
|必须掌握|`port 端口号`|按端口过滤数据包（TCP/UDP）|
|了解即可|`-q`|精简输出模式，减少报文详情|
|了解即可|`-A`|以 ASCII 文本展示报文载荷；**不能解密 SSH/TLS 加密流量**，仅看明文|
|了解即可|`-v / -vv`|增加协议解析的详细程度|
|了解即可|`-s N`|设置每个数据包捕获的最大字节数|

## 实战示例（XShell 直接复制运行）

```
# 默认抓包：自动选择默认网卡持续抓包，Ctrl+C终止
tcpdump

# 列出本机所有可用网卡
tcpdump -D

# 指定网卡ens33抓包
tcpdump -i ens33

# 抓取eth0上20个包，-nn关闭域名端口解析，抓完自动退出
tcpdump -i eth0 -nn -c 20

# 只抓取eth0网卡TCP 80端口流量
tcpdump -i eth0 -nn 'tcp port 80'

# 抓取指定IP和TCP80端口通信流量，多条件建议引号包裹表达式
tcpdump -i eth0 -nn 'host 192.168.1.100 and tcp port 80'

# 抓取DNS传统53端口流量
tcpdump -i eth0 -nn 'port 53'

# 多端口组合过滤：指定IP访问80或443端口
tcpdump -i eth0 -nn 'host 192.168.1.100 and (tcp port 80 or tcp port 443)'

# 保存抓包文件，限制1000个包，防止文件过大
tcpdump -i eth0 -nn -c 1000 -w capture.pcap

# 读取本地pcap文件查看
tcpdump -nn -r capture.pcap

# 监听所有网卡22端口数据包，文本形式展示载荷
tcpdump -i any port 22 -A
```

## ⚠️ 嵌入式 Linux 重点注意

1. tcpdump 依赖 libpcap 库，很多精简 rootfs 默认不带；可静态交叉编译，部署要匹配 CPU 架构、libc、内核。
2. **权限**：抓包一般需要 root 权限执行；普通用户大概率提示权限不足。
3. 抓包开销：高流量场景抓包会占用 CPU，业务运行环境不要长时间抓包。
4. 文件风险：抓包文件增长很快，务必搭配`-c`限制包数量，避免占满 Flash / 根文件系统。
5. 敏感信息：抓包会记录 IP、端口、未加密载荷，保存传输 pcap 文件注意数据安全。
6. 过滤注意：`tcpdump host 域名`会先解析域名 IP，域名 IP 可能动态变化，排障优先直接写 IP。

## 面试背诵要点

tcpdump 是 Linux 常用的网络抓包工具，可以捕获并过滤网络数据包。-i 指定接口，-D 列出接口，-c 限制捕获数量，-nn 禁止地址和端口名称解析，-w 保存抓包文件，-r 读取已有抓包文件。过滤表达式可以通过 host、port、tcp、udp 及逻辑运算符组合。嵌入式 Linux 中常用它排查网络收发异常、DNS 问题和协议交互故障，抓包一般需要相应权限，并应控制抓包量和文件大小。

## 易错坑

- 不带`-i`不会监听全部网卡，只会抓取系统默认网卡流量。
- `-A`只能展示明文载荷，SSH/TLS 加密流量无法解密。
- 多条件过滤不加引号，shell 会解析括号导致命令报错。
- 不设置`-c`持续抓包，短时间内产生巨大 pcap 文件，耗尽存储空间。

# Ping 命令笔记（XShell 直接使用｜连通性测试）

> 作用：**测试主机之间 IP 层网络连通性，查看往返延迟 RTT 与丢包情况**，底层依靠 ICMP 协议。

## 语法

```
ping [参数] 目标主机
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-c N`|发送 N 次报文后自动停止；Linux 默认持续发包，不加 - c 需要 Ctrl+C 终止|
|必须掌握|`-i`|设置报文发送间隔（单位秒）。普通用户通常不能小于 1 秒，root 权限可设置更短间隔；BusyBox ping 权限行为随版本有差异|
|必须掌握|`-s`|设置**ICMP 数据载荷**大小（不是整个 IP 包）。IPv4 无额外头部选项时，总 IP 包长度≈载荷 + 8 字节 ICMP 头 + 20 字节 IP 头|
|了解即可|`-t`|设置**本机发出报文**的 IPv4 TTL 值。⚠️ 输出里看到的`ttl=xx`，是收到对端回包携带的 TTL，二者不能混淆。跨平台注意：Windows 下`ping -t`代表持续 ping，Windows 修改 TTL 使用`-i`|
|了解即可|`-4`|强制使用 IPv4 协议|
|了解即可|`-6`|强制使用 IPv6 协议|
|了解即可|`-M do`|禁止 IP 分片，用来做 MTU 探测；BusyBox ping 大多不支持该参数|

> TTL 参考（收到回包的 TTL，**仅辅助猜测系统，不可作为可靠判定依据**） 常见初始 TTL 值：64、128、255

## 实战示例（XShell 直接复制运行）

```
# 测试和百度网站连通性，持续发包，Ctrl+C停止
ping www.baidu.com

# 只ping4次，执行完毕自动退出（最常用）
ping -c 4 www.baidu.com

# ping4次，每次发包间隔3秒
ping -c 4 -i 3 www.baidu.com

# 测试局域网设备连通性
ping -c 4 192.168.107.128

# ICMP载荷1024字节，设置发出报文TTL=255
ping -s 1024 -t 255 www.baidu.com

# IPv4 MTU探测，禁止分片，以太网标准1500MTU场景
ping -4 -c 4 -M do -s 1472 192.168.1.1

# 强制IPv4 ping
ping -4 -c 4 www.baidu.com

# 强制IPv6 ping（需要环境支持IPv6）
ping -6 -c 4 ipv6.google.com
```

## ⚠️ 嵌入式 Linux 重点注意

1. ping 基于 ICMP 协议，**ping 不通 ≠ 网络不可达**。目标防火墙拦截 ICMP 应答时，ping 超时，但 TCP 业务端口仍可正常通信。
2. `ping 域名`能解析出 IP，仅说明 DNS 正常；ping 成功只代表 ICMP 往返正常，**不能证明应用层服务可用**；ping 的 RTT 是 ICMP 往返延迟，不等于 TCP 业务响应延迟。
3. BusyBox ping 和完整 iputils ping 参数支持存在差异，部分高级参数（如`-M do`）在极简 rootfs 上会缺失。
4. 权限：ping 不一定必须 root，依赖内核 capabilities 配置。
5. 排障组合流程：

```
# 1.查看路由，确认内核选择的出口网卡和网关
ip route get 8.8.8.8
# 2.ping测试连通性
ping -c 4 8.8.8.8
# 3.查看ARP邻居表，二层解析状态
ip neigh
# 4.测试TCP端口连通性（nc）
nc -vz -w 3 192.168.1.100 22
```

> 排查顺序：DNS 解析 → 路由 → ARP 邻居 → ICMP 连通性 → TCP 端口测试，必要时配合 tcpdump 抓包定位。

## 面试背诵要点

ping 基于 ICMP Echo Request 和 Echo Reply，用于测试 IP 层的往返连通性，并观察 RTT 和丢包情况。常用参数有 `-c` 指定发送次数、`-i` 指定发送间隔、`-s` 指定 ICMP 数据载荷大小、`-t` 设置 IPv4 发出报文的 TTL（以常见 Linux iputils 实现为例）。需要注意，ping 不通不代表 TCP 业务一定不通，ping 成功也不代表应用服务正常。排查网络故障时，应结合 DNS 解析、路由表、邻居表、抓包和 TCP 端口测试综合判断。

## 易错坑

- 混淆两个 TTL：`ping -t`是**发出包**的 TTL；输出打印的 ttl 是**收到回包**的 TTL。Windows 平台`ping -t`含义完全不同，跨平台不要记混。
- `-s`只是 ICMP 载荷大小，不是 IP 总包长；单纯加大`-s`会触发 IP 分片，不能直接用来判断 MTU，MTU 探测要搭配`-M do`。
- ping 成功仅代表 ICMP 通，无法验证 TCP 端口、应用服务是否正常。
# route 命令笔记（路由管理）

> 作用：**查看、添加、删除系统路由表，配置网关**，排查跨网段通信问题。 说明：`route`属于 net-tools 工具集，新版 Linux / 嵌入式系统大多已弃用；**嵌入式优先使用 iproute2 的 ip route**，route 仅作为老系统兼容知识保留。

## 语法

```
route [-f] [-p] [Command [Destination]] [mask Netmask] [gw Gateway] [dev Interface]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-n`|不解析主机名，直接显示 IP，查询更快，排障首选|
|必须掌握|`-net`|目标为一个网段|
|必须掌握|`-host`|目标为单个主机（单条主机路由）|
|必须掌握|`netmask`|指定子网掩码，定义网段范围|
|必须掌握|`gw`|指定下一跳网关 IP|
|必须掌握|`dev`|指定报文出口网卡，如 eth0、ens33|

### Flags 路由标志（重点只记 U/H/G，其余了解即可）

- `U`：路由启用（up）
- `H`：主机路由，目标是单台主机
- `G`：需要经过网关转发
- `R/D/M`：动态路由相关标记，实际工程很少见到，了解即可
- `!`：拒绝类路由

## 实战示例（XShell 直接复制运行）

```
# 查看当前路由表
route

# 查看路由表，不解析域名，只显示IP（推荐）
route -n

# 添加网段路由，指定网关
route add -net 192.0.2.0 netmask 255.255.255.0 gw 192.168.1.1

# 添加网段路由，指定出口网卡
route add -net 192.0.2.0 netmask 255.255.255.0 dev ens33

# 添加默认路由：无更具体路由匹配时，走该网关
route add default gw 192.168.1.1

# 添加reject拒绝路由，访问该网段直接拒绝
route add -net 192.0.2.0 netmask 255.255.255.0 reject

# 删除网段路由
route del -net 192.0.2.0 netmask 255.255.255.0

# 删除reject类型路由
route del -net 192.0.2.0 netmask 255.255.255.0 reject
```

## iproute2 新旧命令对照表（嵌入式重点掌握 ip route）

表格

|操作|传统 route|推荐 ip route|
|---|---|---|
|查看路由表|route -n|ip route show|
|查看默认路由|route -n|ip route show default|
|添加默认路由|route add default gw 192.168.1.1|ip route add default via 192.168.1.1|
|添加网段路由|route add -net 192.0.2.0 netmask 255.255.255.0 gw 192.168.1.1|ip route add 192.0.2.0/24 via 192.168.1.1|
|删除网段路由|route del -net 192.0.2.0 netmask 255.255.255.0|ip route del 192.0.2.0/24|
|查询访问目标 IP 实际走哪条路由|不直观|ip route get 8.8.8.8|

## ⚠️ 嵌入式 Linux 重点注意

1. route 添加的路由**临时生效，重启丢失**；永久路由需要修改网络配置文件。
2. 添加 / 删除路由需要 root 权限。
3. 网关通常要求通过出口接口可达；特殊场景可通过 onlink 机制配置，不要绝对认为网关必须和本机网卡同网段。dev 参数不仅用于直连网段，也可以明确指定远端流量的出口网卡。
4. 默认路由仅在**没有匹配到优先级更高、更具体路由**时才使用；访问本地直连网段会优先匹配直连路由，不走默认网关。
5. 开发板跨网段不通排查顺序：

```
#1 查看网卡IP与状态
ip addr
#2 查看完整路由表
ip route
#3 查询访问目标IP实际选中的路由
ip route get 192.168.2.10
#4 测试网关是否可达
ping -c 3 192.168.1.1
```

> 路由配置正确但仍不通，还需要检查：对端返回路由、防火墙、ARP 邻居表、物理链路。 极简 rootfs 可能裁剪 ip/route，根据目标板实际支持工具选择命令。

## 面试背诵要点

route 用于查看和管理 Linux 路由表，可以添加、删除主机路由和网段路由。`route -n` 不解析地址名称，便于快速查看路由表；`-net` 表示网段路由，`-host` 表示主机路由，gw 指定下一跳网关，dev 指定出口接口。默认路由用于处理没有匹配到更具体路由的流量。现代 Linux 通常优先使用 ip route，传统 route 命令主要用于兼容旧系统。

## 易错坑

- 不加`-n`查看路由，会反向解析域名，命令卡顿。
- 默认路由不是所有流量都走网关，更精细的路由条目优先级高于默认路由。
- route 配置的路由临时生效，重启开发板失效。

# traceroute 命令笔记（XShell 直接使用｜路由路径追踪）

> 作用：**追踪数据包从本机到目标 IP / 域名经过的完整路由跳数，定位网络中断、延时异常的故障节点**。 补充：Linux 完整版 traceroute 默认 UDP 探测；还支持 ICMP、TCP 探测模式。很多嵌入式 BusyBox 内置精简版 traceroute，部分高级参数不支持。

## 语法

```
traceroute [参数] [域名或者IP]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-m <TTL>`|设置最大跳数（最大存活 TTL），默认 30；限制探测最多经过多少个路由节点|
|必须掌握|`-n`|直接输出 IP，**不反向解析主机名**，排障首选，速度更快|
|必须掌握|`-q`|每一跳发送探测包的数量，默认 3|
|了解即可|`-p <端口>`|**UDP 模式下，设置探测报文的初始目标 UDP 端口**，不是本机源端口；探测过程端口可能变化，和目标业务端口无关|
|了解即可|`-r`|绕过本机路由表查找，仅尝试向**本地直连网段**的目标发包；不能绕过网关访问互联网远端主机|
|了解即可|`-w <秒>`|单次探测包的响应等待超时时间；每一跳默认 3 次探测，总等待时间会更长|
|了解即可|`-I`|使用 ICMP Echo 包探测（完整版支持）|
|了解即可|`-T`|使用 TCP SYN 包探测（完整版支持）|

## 实战示例（XShell 直接复制运行）

```
# 追踪本机到百度的完整传输路径
traceroute www.baidu.com

# 设置最大跳数为7
traceroute -m 7 www.baidu.com

# 只显示IP，不解析域名（推荐，排查必用）
traceroute -n www.baidu.com

# 每一跳发送4个探测包
traceroute -q 4 www.baidu.com

# 设置单次探测响应超时时间3秒
traceroute -w 3 www.baidu.com

# UDP探测初始目标端口6888
traceroute -p 6888 www.baidu.com

# 快速探测，减少探测次数、缩短超时，适合大量星号场景
traceroute -n -q 1 -w 2 www.baidu.com

# ICMP模式探测
traceroute -I -n www.baidu.com

# TCP SYN模式探测，目标端口443
traceroute -T -p 443 -n www.baidu.com

# 限制最大跳数10
traceroute -m 10 -n www.baidu.com

# 查看内核实际选择的路由（配合traceroute排查）
ip route get 8.8.8.8
```

## ⚠️ 嵌入式 Linux 重点注意

1. 原理：逐步增大 TTL，依靠中间设备返回`ICMP Time Exceeded`获取路由节点信息。
2. `* * *`解读：该次探测在超时时间内**没有收到预期响应**。 可能原因：防火墙过滤探测报文、路由器不返回 ICMP 超时报文、ICMP 限速、探测包 / 回包丢包、回程链路延迟高。 ✅关键结论：单跳出现`*`，**不代表该节点无法转发业务流量**。如果后面跳数又正常响应，说明数据包依然可以穿过这一跳，只是节点不回应探测包。
3. 延迟解读：某一跳 RTT 突然升高，不一定代表业务流量在这里卡顿。路由器可能仅对发给自身的 ICMP 探测报文限速，正常转发业务包速度不受影响，需要结合 ping、业务测试、抓包综合验证。
4. BusyBox 精简版 traceroute 会砍掉`-I / -T`等高级探测模式，参数支持有限。
5. 探测路径和回程路径**不对称**，去包和回包可能走不同路由。

### 示例结果解读

```
 1  192.168.1.1    1.2 ms   1.1 ms   1.3 ms
 2  10.10.0.1      8.5 ms   8.7 ms   8.4 ms
 3  * * *
 4  203.0.113.1   15.1 ms  14.8 ms  15.3 ms
```

- 第 1 跳：本地网关；第 2 跳：二级路由；第 3 跳无探测响应；**第 4 跳正常返回**。
- 说明数据包能够到达第 4 跳，第 3 跳只是不响应探测报文，转发功能正常。

## 面试背诵要点

traceroute 用于探测数据包从本机到目标主机经过的路由路径。它通过逐步增加探测包的 TTL，利用中间设备返回的 ICMP Time Exceeded 报文识别沿途节点。常见参数包括 `-m` 设置最大跳数、`-n` 禁止反向 DNS 解析、`-q` 设置每跳探测次数、`-w` 设置响应等待时间。常见 Linux 版本默认使用 UDP 探测，也支持通过 `-I` 使用 ICMP、通过 `-T` 使用 TCP。出现 `*` 表示未收到预期响应，不能直接认定网络中断。实际排障应结合 ping、ip route、TCP 端口测试和抓包综合判断。

## 易错坑

- `-p` 修改的是探测包**目标端口**，不是本机源端口，和目标业务端口无关。
- `-r` 只能用于直连网段，**不能跨网关访问外网**。
- 看到`* * *`不要直接判定链路断，节点只是不回复探测报文，业务流量仍可转发。
- 单跳延迟突增，不能直接判定是业务瓶颈，控制平面 ICMP 报文可能被单独限速。


# ifconfig 命令笔记（XShell 直接使用｜网卡配置）

> 作用：查看、配置网卡网络设备信息，属于 net-tools 工具集。 ⚠️ 重要说明：现代 Linux、嵌入式系统推荐使用 iproute2 的 ip addr；ifconfig 已经废弃，仅老系统、BusyBox 环境兼容使用。

## 语法

```
ifconfig [-v] [-a] [-s] [interface]
ifconfig [-v] interface [aftype] options | address ...
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`up`|启用 / 启动指定网卡|
|必须掌握|`down`|关闭指定网卡|
|必须掌握|`add <地址>`|给网卡添加 IPv6 地址|
|必须掌握|`del <地址>`|删除网卡上的 IPv6 地址|
|了解即可|`netmask`|设置子网掩码|
|了解即可|`broadcast`|设置广播地址|
|了解即可|`hw ether`|修改网卡 MAC 地址（需要先 down 网卡）|
|了解即可|`arp / -arp`|开启 / 关闭网卡 ARP 协议|
|了解即可|`mtu`|设置网卡最大传输单元 MTU|
|了解即可|`-a`|显示所有网卡（包含未启用 down 状态网卡）|

## 实战示例（XShell 直接复制运行）

```
# 查看所有网卡信息
ifconfig

# 关闭网卡eth0

# 启用网卡eth0
ifconfig eth0 up

# 给eth0配置IPv4地址

# 配置IPv4地址 + 子网掩码

# 配置IPv4地址 + 子网掩码 + 广播地址
ifconfig eth0 192.168.1.56 netmask 255.255.255.0 broadcast 192.168.1.255

# 添加IPv6地址
ifconfig eth0 add 33ffe:3240:800:1005::2/64

# 删除IPv6地址
ifconfig eth0 del 33ffe:3240:800:1005::2/64

# 修改MAC地址（流程：先关网卡 → 修改MAC → 再启用网卡）
ifconfig eth0 down
ifconfig eth0 hw ether 00:AA:BB:CC:DD:EE
ifconfig eth0 up

# 开启ARP
ifconfig eth0 arp
# 关闭ARP
ifconfig eth0 -arp

# 设置MTU=1500字节
ifconfig eth0 mtu 1500
```

表格

## ⚠️ 嵌入式 Linux 重点注意

1. ifconfig 配置**临时生效**，重启系统后丢失；永久配置需要修改系统网卡配置文件。
2. net-tools 在新版系统默认不预装，很多现代嵌入式 rootfs 只带`ip`命令，没有 ifconfig；BusyBox 内置的 ifconfig 功能会精简，部分高级选项缺失。
3. 修改 MAC 地址必须先 down 网卡，修改完成再 up；部分网卡硬件会限制 MAC 修改。
4. MTU 设置：以太网常规 1500，MTU 修改不当会引发分片、网络不通问题。
5. ARP 关闭：关闭 ARP 后网卡无法做二层地址解析，同网段通信失效，一般不建议关闭。

## 面试背诵要点

ifconfig 是 net-tools 工具集的网卡管理命令，用于查看网卡状态、配置 IP、MAC、MTU、ARP 等参数。up/down 控制网卡启停；可配置 IPv4/IPv6 地址。该工具已经废弃，现代 Linux 与嵌入式开发优先使用 iproute2 的`ip addr`、`ip link`。ifconfig 的网卡配置是临时的，重启失效。

## 易错坑

- ifconfig 配置的 IP 地址临时生效，重启丢失，不是永久配置。
- 修改 MAC 地址必须先 down 网卡，直接修改会报错。
- 新版 Ubuntu、Debian 等系统默认不带 ifconfig，需要手动安装 net-tools，优先使用 ip 命令。
- 关闭 ARP 会导致二层解析失败，同网段主机无法通信。

> 笔记格式统一完成，和前面 ping /route/traceroute /netstat/ss 保持一致。


# netstat 命令笔记（XShell 直接使用｜查看套接字 / 网络连接）

> 作用：**查看 socket 连接、监听端口、路由、网卡统计、协议统计**，属于 net-tools 工具集。 ⚠️ 重要说明：netstat 属于传统 net-tools 工具集，在现代 Linux 中通常优先使用 ss；但在老系统和部分嵌入式环境中，仍可能需要使用 netstat。在嵌入式系统中，ss 也不一定存在。实际使用前先检查目标 rootfs 是否提供对应命令。

## 语法

```
netstat [参数]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-a`|显示所有 socket（包含监听、已建立连接）|
|必须掌握|`-n`|直接显示 IP + 端口，**不做域名解析**，排障提速，高频使用|
|必须掌握|`-t`|只看 TCP 协议连接|
|必须掌握|`-u`|只看 UDP 协议连接|
|必须掌握|`-l`|仅列出处于等待连接的套接字（TCP 为 LISTEN，UDP 为本地绑定端口）|
|必须掌握|`-p`|显示 socket 对应的 PID 和进程名。普通用户通常只能看到有权限查看的进程信息；root 通常可以查看更多信息，但仍可能受到容器、PID 命名空间和系统安全策略限制。BusyBox 的 netstat 可能不支持 `-p`。|
|了解即可|`-r`|查看路由表（等价 route -n）|
|了解即可|`-i`|查看网卡接口统计信息|
|了解即可|`-s`|TCP/UDP 协议收发数据包统计|
|了解即可|`-x`|只查看 UNIX 本地套接字|

```

netstat -a

# 查看所有TCP连接
netstat -at

# 查看所有UDP连接
netstat -au

# 查看所有TCP监听端口及关联进程（排障高频）
netstat -ltnp

# 查看UDP本地绑定端口及关联进程
netstat -lunp

# 所有TCP连接，数字格式
netstat -ant

# 查看所有协议统计
netstat -s

# TCP协议统计
netstat -st

# UDP协议统计
netstat -su

# 查看网卡状态统计
netstat -i

# 查看路由表
netstat -rn

# 过滤ssh相关连接（备选方案：优先按端口过滤更稳定）
netstat -ap | grep ssh
```

## ss 与 netstat 对照表（嵌入式优先掌握 ss）

表格

|操作|netstat|ss|
|---|---|---|
|查看 TCP 监听端口及进程|netstat -ltnp|ss -ltnp|
|查看 UDP 本地绑定端口及进程|netstat -lunp|ss -lunp|
|查看全部 socket|netstat -an|ss -an|
|查看全部 TCP 连接|netstat -ant|ss -ant|
|查看 TCP 统计|netstat -st|ss -s（汇总统计，不完全等价）|
|查看路由表|netstat -rn|ip route|
|查看网卡统计|netstat -i|ip -s link|

> 注意：netstat -anp 和 ss -anp 虽然形式相似，但在不同实现中的输出细节并不完全一致。若要排查 SSH，优先按 TCP 端口或连接状态过滤，而不是简单地 grep ssh—— 因为数字格式、进程权限和命令行显示都会影响匹配结果。

## ⚠️ 嵌入式 Linux 重点注意

1. UDP 是无连接协议，没有 TCP 那样的 LISTEN、ESTABLISHED 状态。查看 UDP 服务通常使用 `netstat -lunp` 或 `ss -lunp`，检查本地绑定地址和端口。
2. netstat 依赖 net-tools 包，新版系统、很多精简嵌入式 rootfs 默认不安装；BusyBox 的 netstat 功能会阉割，很多参数不支持。
3. netstat 性能弱，高并发服务器场景下，读取很慢；ss 读取内核 socket，性能远高于 netstat。
4. 端口排查思路：服务启动失败，优先用`netstat -ltnp`确认 TCP 端口监听；UDP 查看本地绑定端口。
5. 排障原则：端口出现在监听列表中，不等于业务服务一定正常。
    - `ss -ltnp`：确认 TCP 服务是否监听。
    - `ip addr`、`ip route`：确认接口地址与路由。
    - `nc`：测试客户端到目标 TCP 端口是否能建立连接。
    - `tcpdump`：确认请求和响应报文是否真正经过网卡。
    - `strace` 或 `dmesg`：进一步检查应用系统调用和内核日志。

## 面试背诵要点（修正版）

netstat 是传统 net-tools 工具集中的网络诊断命令，用于查看 socket 连接、监听端口、路由表、网络接口统计和协议统计。常用参数包括 `-a` 查看所有 socket、`-n` 使用数字格式、`-t` 查看 TCP、`-u` 查看 UDP、`-l` 查看监听或等待连接的 socket（具体含义依协议而异）、`-p` 查看关联进程。现代 Linux 通常优先使用 ss、ip route 和 ip -s link。TCP 有 LISTEN、ESTABLISHED 等状态，而 UDP 是无连接协议，没有 TCP 那样的状态机。

## 易错坑

- 不加`-n`，命令会反向 DNS 解析，输出卡顿、变慢。
- BusyBox 精简版 netstat 不支持`-p`，看不到进程名。
- UDP 是无连接协议，不存在 TCP 意义上的 ESTABLISHED/LISTEN，只能看本地绑定端口。
- netstat 性能差，大量连接的机器不要长时间用 netstat，改用 ss。
- `-p`参数受权限、容器、PID 命名空间限制，root 也不一定能拿到全部进程信息。


# ss 命令笔记（套接字查看，netstat 替代品）

> 作用：**查看系统活动 socket 套接字信息**，属于 iproute2 工具集，用来替代传统 netstat。ss 通过内核提供的 socket 诊断接口等机制获取信息，通常比传统 netstat 更适合大量 socket 的查询；具体性能取决于系统、查询范围和工具实现。

## 语法

```
ss [参数]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-n`|数字格式，**不解析域名 / 服务名**，排障必加，避免解析延迟|
|必须掌握|`-a`|显示全部套接字（监听 + 非监听）|
|必须掌握|`-l`|显示处于监听状态的 socket；对于 UDP 等无连接协议，通常显示正在监听或绑定等待接收数据的 socket，具体显示取决于协议和实现|
|必须掌握|`-t`|只看 TCP 套接字|
|必须掌握|`-u`|只看 UDP 套接字|
|必须掌握|`-p`|显示关联的进程信息。普通用户通常只能看到有权限查看的进程。root 一般能够查看更多进程信息，但容器、PID 命名空间和安全策略仍可能限制可见范围。精简嵌入式 Linux 要确认目标版本是否支持`-p`。|
|了解即可|`-4`|仅 IPv4 套接字|
|了解即可|`-6`|仅 IPv6 套接字|
|了解即可|`-i`|显示 TCP 内部信息（拥塞、重传等详细 TCP 信息）|
|了解即可|`-o`|显示计时器信息（TIME_WAIT 等定时器）|
|了解即可|`-e`|套接字详细信息|
|了解即可|`-m`|套接字内存占用|
|了解即可|`-s`|套接字整体统计概况|
|了解即可|`-x`|只看 Unix 本地域套接字|

## 实战示例（XShell 直接复制运行）

```
# 查看TCP监听端口（数字格式，排障高频）
ss -ltn

# 查看TCP监听端口+进程（排查端口占用、服务监听）
sudo ss -ltnp

# 查看UDP本地绑定端口+进程（DNS、设备发现等UDP服务）
sudo ss -lunp

# 查看所有TCP套接字（监听+非监听全部TCP）
ss -ant

# 查看所有UDP套接字
ss -au

# 套接字总体统计概况
ss -s

# 查看已建立的TCP连接
ss -tn state established

# 查看TIME-WAIT状态TCP，用于短连接场景分析
ss -tn state time-wait
```

表格

|功能|传统 netstat|推荐 ss|
|---|---|---|
|TCP 监听端口|netstat -ltn|ss -ltn|
|TCP 监听端口及进程|netstat -ltnp|ss -ltnp|
|UDP 本地绑定端口|netstat -lun|ss -lun|

## ⚠️ 嵌入式 Linux 重点注意

1. UDP 是无连接协议，没有 TCP 那样的 LISTEN、ESTABLISHED 状态。查看 UDP 服务端口通常使用 `ss -lunp`，重点检查本地绑定地址和端口。UDP 可以通过 connect () 设置默认通信对端，不会执行 TCP 握手，但会改变 socket 收发行为。
2. ss 默认显示一部分非监听 socket，TCP 通常以已建立连接为主，**不能概括为所有协议都只显示已建立连接**。查看监听端口必须加`-l`；查看 TCP 所有 socket（监听 + 已建立）用`ss -ant`。
3. ss 属于 iproute2 工具集，现代 Linux 自带；BusyBox、精简嵌入式 rootfs 可能不带 ss，需要提前确认目标系统可用命令。

## 面试背诵要点（修正版）

ss 是 Linux 中查看 socket 信息的工具，属于 iproute2 工具集，通常用于替代传统的 netstat。常用参数包括 `-n` 数字格式、`-a` 查看更多 socket、`-l` 查看监听 socket、`-t` 查看 TCP、`-u` 查看 UDP、`-p` 显示关联进程。常用命令是 `ss -ltnp` 查看 TCP 监听端口及进程，`ss -lunp` 查看 UDP 本地绑定端口，`ss -tn state established` 查看已建立的 TCP 连接。嵌入式 Linux 中要注意 BusyBox 和精简 rootfs 可能不提供 ss，实际排障应以目标系统支持的命令为准。

## 易错坑

- 忘记`-n`：触发域名 / 服务名解析，命令卡顿、输出延迟。
- `-l`不能只理解为 TCP 的 LISTEN，UDP 下代表端口绑定，UDP 不存在 TCP 式的连接状态。
- `-p`参数受权限、容器、PID 命名空间限制，即使 root 也不一定能拿到全部进程信息。
- 不要混淆：`ss -lt`会尝试解析名称，排障优先使用`ss -ltn`数字模式。

# Telnet 命令笔记（XShell 直接使用｜远程登录 / TCP 端口探测）

> 作用：原生作用为远程登录服务器；**嵌入式 / 网络调试最常用作 TCP 端口连通性测试工具**。 ⚠️ 重要安全说明：telnet 明文传输所有数据（账号、密码直接裸跑），生产环境严禁用来登录主机，仅用于内网调试端口。现代远程登录优先 ssh。 补充区分：telnet 客户端可以连接任意 TCP 端口，**不代表目标端口跑的是 telnet 服务**。

## 语法

```
telnet [参数] [主机] [端口]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|主机 IP / 域名|目标主机地址|
|必须掌握|端口号|可选，不填默认 23（telnet 服务端口）；调试其他 TCP 端口时手动指定|
|了解即可，需按目标版本确认|`-l`|指定登录用户名；BusyBox 精简 telnet 不一定支持|
|了解即可，需按目标版本确认|`-d`|开启调试模式，输出更多连接过程信息；BusyBox 精简 telnet 不一定支持|

## 实战示例（XShell 直接复制运行）

```
# 默认23端口登录远程主机（极少用于正式登录）
telnet 192.168.107.133

# 【调试高频】测试目标IP的6379端口TCP连通性（端口探测）
telnet 192.168.107.133 6379
```

- **连接成功**：TCP 三次握手成功，目标地址端口接受连接；但**不代表上层应用业务一定正常**。部分服务不会主动返回 banner，黑屏属于正常现象，部分协议需要客户端先发指定报文才会响应。
- **Connection refused**：连接被拒绝，常见：目标端口无服务监听，或防火墙主动返回拒绝报文。
- **Connection timed out**：等待期间未能完成 TCP 握手；可能原因：防火墙丢弃报文、路由异常、目标主机离线、网络丢包，**不能直接判定路由不通**。
- **域名解析失败**：优先排查 DNS，不属于 TCP 端口本身故障。

> 退出交互：按下`Ctrl+]`，再输入`quit`回车退出 telnet 交互。直接关闭窗口容易残留会话。

### 补充：更适合脚本自动化的端口探测（nc）

```
# nc端口探测（支持该参数版本），3秒超时
nc -vz -w 3 192.168.107.133 6379
```

> BusyBox 的 nc 精简版本参数存在差异。

### 本机端口排查配套命令

```
# 查看本机TCP监听端口，确认服务监听状态与绑定地址
ss -ltnp
```

> 注意：服务绑定`127.0.0.1`仅本机可访问，外部主机无法连接。

## ⚠️ 嵌入式 Linux 重点注意

1. Telnet 协议明文传输，账号密码可被抓包窃听；正式远程登录必须使用 SSH，仅内网临时调试场景使用 telnet。
2. telnet**仅可测试 TCP 端口，不能做可靠 UDP 端口探测**；UDP 调试可使用 nc UDP 模式、对应协议客户端或 tcpdump 抓包。
3. 嵌入式 rootfs/BusyBox 是否自带 telnet 客户端取决于编译配置，很多极简固件不带。
4. 端口探测成功 ≠ 业务可用：TCP 握手成功只代表四层连通，Redis 这类服务还需要校验协议交互、鉴权、应用状态。
5. 排障思路：端口测试失败，结合`ip addr`、`ip route`、`ss`、`tcpdump`综合定位故障位置。

## 面试背诵要点（修正版）

telnet 原本用于远程终端登录，但协议采用明文传输，正式远程管理应优先使用 SSH。在 Linux 网络排障中，telnet 客户端常用于测试 TCP 端口连通性，例如 `telnet IP 端口`。连接成功说明 TCP 连接已经建立，但不能证明应用层业务正常；Connection refused 常见于端口无监听或防火墙主动拒绝，连接超时则可能与防火墙、路由或目标无响应有关。telnet 不能用于可靠的 UDP 端口探测，精简嵌入式系统也可能不包含该客户端。

## 易错坑

- 概念混淆：telnet 客户端可以连接任意 TCP 端口，不代表目标端口跑 telnet 服务。
- 误判结果：超时≠路由不通，端口通≠应用业务正常；黑屏不一定故障，部分服务不主动输出 banner。
- 参数兼容性：`-l`、`-d`在 BusyBox 精简 telnet 上不一定支持，不要直接照搬。
- 无法测试 UDP：telnet 基于 TCP，UDP 端口连通性不能用 telnet 验证。
- 退出会话操作：直接关窗口会残留会话，标准退出：`Ctrl+]` → `quit`。

# ssh 命令笔记（Linux 终端｜加密远程登录）

> 作用：SSH（Secure Shell）加密远程连接工具，用来登录远程 Linux 主机、远程执行命令；配套支持 scp/sftp 文件传输，替代明文 telnet。 区分：`ssh` = OpenSSH 客户端命令；`sshd` = SSH 服务端程序。嵌入式资源受限设备常使用轻量 Dropbear 实现。

## 语法

```
ssh [参数] [主机]
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-l <登录名>`|指定远程服务器登录用户名，等价 `用户名@ip` 写法|
|必须掌握|`-p <端口>`|指定 SSH 服务器端口；默认端口 22。服务器使用非默认端口（如 2222）时需要携带该参数；22 端口可省略。⚠️ 注意：ssh 小写`-p`；scp 大写`-P`指定端口，大小写不可混淆|
|必须掌握|`-v`|输出连接、握手、认证全过程调试日志，排错神器；可定位 DNS、TCP、密钥、认证阶段故障|
|了解即可|`-i <私钥文件>`|指定客户端身份私钥文件。**指定私钥≠免密登录**；需要满足：公钥写入服务端`~/.ssh/authorized_keys`、私钥权限合规、服务开启公钥认证。私钥带口令仍需输入密钥密码|
|了解即可|`-o`|单项配置，如`-o ConnectTimeout=5`设置 5 秒连接超时|
|了解即可|`-X`|X11 图形转发，不是完整远程桌面；需要客户端、服务端图形环境支持，嵌入式调试很少用到|

## 实战示例（Linux/macOS/OpenSSH 客户端）

```
# 登录远程服务器，使用当前本地用户名
ssh 192.168.0.10

# 指定用户名登录（写法1：-l参数）
ssh -l liangxu 192.168.0.10
# 指定用户名登录（写法2：@，工程更常用）
ssh liangxu@192.168.0.10

# 非默认端口登录，端口改为2222
ssh -p 2222 liangxu@192.168.0.10

# 远程执行命令，执行完直接返回本地终端，不进入远程shell
ssh 192.168.0.10 date

# 排障调试，输出详细连接日志
ssh -v liangxu@192.168.0.10

# 设置5s连接超时
ssh -o ConnectTimeout=5 liangxu@192.168.0.10

# 指定私钥文件登录
ssh -i ~/.ssh/id_ed25519 liangxu@192.168.0.10
```

## sshd 配置操作（服务端）

服务端配置文件：`/etc/ssh/sshd_config`（**服务端**） 客户端系统配置：`/etc/ssh/ssh_config`（**客户端**，不要混淆） 修改 sshd 配置推荐操作流程：

```
# 第一步：校验配置语法，防止配置写错无法登录
sudo sshd -t
# 校验无报错后，重载或者重启sshd
sudo systemctl reload sshd
# 或者重启：sudo systemctl restart sshd
```

> ⚠️ 安全操作提醒：远程修改 ssh 配置时**不要关闭当前 ssh 会话**，新开终端测试新连接正常，再关闭旧会话，防止配置错误锁死登录。

## ⚠️ 嵌入式 Linux 重点注意

1. SSH 全程加密，替代不安全 telnet；嵌入式设备两种实现：OpenSSH（功能全、占用大），Dropbear（轻量，资源小固件常用）。BusyBox 本身不带完整 SSH，SSH 由 OpenSSH/Dropbear 独立包提供。
2. SSH 连接失败标准排查顺序：
    1. 网络层：`ip addr`、`ip route`、`ping -c3 IP`；ping 不通不代表 SSH 不可达，ICMP 报文可被防火墙丢弃。
    2. TCP 端口层：`nc -vz -w 3 192.168.0.10 22`，验证 22 端口连通；TCP 通，不代表 SSH 认证正常。BusyBox nc 参数存在差异。
    3. 设备本地服务检查：`ss -ltnp`、`ps`，确认 sshd/dropbear 监听端口。精简系统可能没有 ss 工具。
    4. 客户端调试：`ssh -v`，定位 DNS、密钥、主机密钥校验、账号认证等问题。
3. scp、sftp 属于 SSH 配套文件传输工具，不是 ssh 登录命令。

## 面试背诵要点

SSH（Secure Shell）是加密远程登录和远程命令执行协议，用来替代明文 Telnet，默认 TCP 端口 22。OpenSSH 客户端命令为 ssh，服务端程序 sshd。`ssh user@IP`或`ssh -l user IP`指定登录用户；`-p`指定服务端口；`-i`指定私钥文件；`-v`输出详细日志用于排错。命令末尾追加指令可以远程执行命令。公钥认证要求客户端公钥写入服务端`authorized_keys`。嵌入式设备可选用 OpenSSH 或者轻量级 Dropbear。SSH 连不上，依次排查网络、TCP 端口、服务监听、账号与密钥认证。

## 易错坑

- 大小写混淆：ssh 端口参数小写`-p`，scp 端口参数大写`-P`，写反报错。
- 配置文件混淆：`sshd_config`服务端；`ssh_config`客户端。
- 误区：`-i`指定私钥不等于免密登录，还需要公钥部署、权限、服务配置全部满足。
- 误区：`-X`是 X11 图形转发，不是远程桌面，嵌入式很少使用。
- 高危操作：远程修改 sshd 配置，直接关闭当前会话，一旦配置错误直接锁死设备。

# ftp 命令笔记（Linux 终端｜FTP 文件传输客户端）

> 作用：FTP（文件传输协议）；`ftp`是 FTP 客户端命令，vsftpd 是常用 FTP 服务端软件，用于服务器之间上传、下载文件。 ⚠️ 概念区分：普通 FTP**不加密账号、密码与文件数据**，不要在公网 / 不可信网络使用；SFTP 基于 SSH 协议，不需要额外部署 FTP 服务；FTPS 是 FTP+TLS 加密，不等于 SFTP；TFTP 多用于嵌入式启动 / 固件升级，无用户认证。

## 语法

```
ftp [参数] [主机名或IP]
```

## ⚠️ 嵌入式 Linux 重点注意

1. FTP 有**控制连接 + 独立数据连接**，控制端口默认 TCP 21。
    
    - 主动模式：服务端主动回连客户端建立数据通道；NAT 环境容易失败。
    - 被动模式：客户端额外连接服务端的数据端口，NAT 更友好；服务端需要配置被动端口范围 + 防火墙放行。
    
    > 现象：能登录、ls 卡住，大概率是数据连接问题；不一定只是防火墙，还需要检查服务端被动端口配置、目录权限、磁盘空间、客户端传输模式。
    
2. 普通 FTP 明文传输，不可信网络禁止使用；嵌入式文件传输优先推荐 SFTP/SCP（依托 SSH 加密）。TFTP 适合裸机固件烧录，没有身份认证，只在内网隔离环境使用。
3. BusyBox 精简固件 ftp 客户端不一定自带，取决于编译配置。
4. 文件传输一定要使用`binary`二进制模式，否则 bin 固件、压缩包会损坏。
5. mget/mput 批量文件是否覆盖文件：由 ftp 客户端交互设置 + 服务器权限共同决定；使用`prompt`关闭确认前，确认文件名匹配规则，避免误覆盖。

## 面试背诵要点

FTP 是文件传输协议，Linux 下的 ftp 命令是 FTP 客户端，常用于文件上传和下载。FTP 默认控制端口为 TCP 21，并通过独立的数据连接传输目录列表和文件，分为主动模式、被动模式，容易受 NAT 和防火墙影响。 在 FTP 交互终端中，cd 切换远程目录，lcd 切换本地目录；get/mget 用于下载，put/mput 用于上传；binary 用于二进制传输，prompt 用于控制批量操作的交互确认。 普通 FTP 不加密账号、密码和文件数据。安全场景优先使用 SFTP 或 FTPS；嵌入式 Linux 中还可能使用 TFTP 进行启动或升级文件传输，但应结合认证、网络隔离和固件校验等安全措施。vsftpd 是常见的 FTP 服务端软件，实际上传权限取决于服务端配置和文件系统权限。

## 易错坑

- 混淆 cd 和 lcd：cd 操作远程目录，lcd 操作本地目录，传文件找不到本地文件最常见原因。
- 忘记 binary：传输固件、可执行文件、压缩包，不使用 binary 会造成文件损坏。
- 登录成功，但 ls/get/put 卡住：优先排查主动 / 被动模式、数据端口，不只是防火墙。
- 概念混淆：SFTP≠FTPS≠TFTP；SFTP 不需要部署 vsftpd，依赖 ssh 服务。
- 权限误区：打开 write_enable=YES 不等于一定可以上传，还要看 Linux 文件系统权限。

> 作用：SFTP（SSH File Transfer Protocol）交互式文件传输程序；**复用 SSH 连接通道，默认端口 TCP22，不需要额外部署 FTP 服务**，全程加密，嵌入式开发首选文件传输方式。 概念区分：SFTP ≠ FTPS；OpenSSH 一般依靠`sftp-server`或`internal-sftp`提供 SFTP 服务端；Dropbear 本身只提供 SSH 登录，**不自带完整 SFTP 服务端**，需要额外配套`sftp-server`程序，取决于固件构建配置。SSH 能登录 ≠ SFTP 一定可用。

|了解即可|`mkdir`|远程新建目录；`rm`删除远程文件；`rmdir`删除远程空目录|

## 实战示例

```
# 使用SFTP连接服务器
sftp liangxu@192.168.107.133

# 指定非默认SSH端口连接（注意大写-P）
sftp -P 2222 liangxu@192.168.107.133

# SFTP连接排错，打印详细日志
sftp -v liangxu@192.168.107.133
```

进入交互终端后的操作：

```
lcd /tmp                # 设置本地工作目录
lls                     # 查看本地文件

ls                      # 查看远程目录文件

put debug.conf          # 上传本地配置文件到远程

```

```

# 上传本地固件到远程 /tmp

```

## ⚠️ 嵌入式 Linux 重点注意

1. SFTP 复用 SSH 连接通道，没有 FTP 那种独立数据通道，不存在主动 / 被动模式 NAT 问题。端口可修改，22 只是默认端口。
2. SSH 登录正常，但 SFTP 连接失败，可能原因：
    
    - 服务端缺少`sftp-server`程序
    - sshd_config 中 Subsystem 子系统配置错误
    - 用户被`ForceCommand`、`ChrootDirectory`等策略限制
    - 文件 / 目录权限不足、文件系统只读
    
    > 排查顺序：先用`ssh -v`验证 ssh 登录；再用`sftp -v`看 SFTP 详细日志，查看服务端日志定位问题。
    
3. Dropbear 仅提供 SSH 登录能力；如需 SFTP，系统里必须额外部署`sftp-server`，很多极简 rootfs 直接砍掉该组件，ssh 可登录但 sftp 不可用。
4. `get -r / put -r`递归传输失败，除目录权限外，还要检查远程磁盘空间、文件系统是否只读；不同 sftp 客户端版本参数支持存在差异。

### FTP 与 SFTP 对比表

表格

|对比项|FTP|SFTP|
|---|---|---|
|基础协议|FTP|SSH 协议|
|默认端口|TCP 21|TCP 22（可修改）|
|传输加密|普通 FTP 明文|全程加密|
|连接模型|控制连接 + 独立数据连接|复用 SSH 单条连接|
|服务端组件|vsftpd 等 FTP 服务|OpenSSH sftp-server / internal-sftp|
|主动 / 被动模式|存在|无 FTP 主动被动模式概念|
|嵌入式场景|仅内网兼容场景|安全日志、固件调试传输首选|

## 面试背诵要点

SFTP 是基于 SSH 协议的安全文件传输工具，默认 TCP 22 端口，不需要额外部署 FTP 服务端，不存在 FTP 主动、被动模式的数据连接问题。 SFTP 客户端启动参数`-P`指定端口，`-i`指定身份私钥，`-o`传递 SSH 配置；`-v`用于连接调试。交互模式下`get`下载、`put`上传；`get -r`和`put -r`递归传输目录；`cd`切换远程目录，`lcd`切换本地目录，`lls`查看本地文件，`!cmd`执行本地 shell 命令。

SSH 登录成功**不代表 SFTP 一定可用**。服务端必须配置好 SFTP 子系统或配套`sftp-server`程序。嵌入式 Linux 要重点关注 OpenSSH、Dropbear 固件裁剪情况，rootfs 很可能缺少 SFTP 服务端组件。

## 易错坑

- 端口大小写：sftp/scp `-P`大写；ssh `-p`小写，写直接连接失败。
- 参数区分：`get -r`是 sftp 交互**内部命令选项**，不是 sftp 启动命令参数，不要混淆。
- Dropbear 误区：Dropbear 有 SSH 不等于自带 SFTP，必须额外有 sftp-server。
- 递归传输失败只看权限不够，还要检查磁盘空间、文件系统只读。
- 混淆 SFTP、FTPS：FTPS 是 FTP+TLS，底层仍是 FTP；SFTP 跑在 SSH 之上。

# lftp 命令笔记（Linux 终端｜多功能文件传输客户端）

> 作用：lftp 是功能强大的交互式文件传输客户端，**支持 FTP、FTPS、SFTP、HTTP、HTTPS 等多种协议**，嵌入式开发常用于批量文件与目录同步；特色是`mirror`目录同步、断点续传。 重要区分：lftp 只是客户端工具，**不是传输协议**；`lftp user@ip`写法协议可能受默认配置影响，推荐显式写 URL 避免选错协议。 lftp 属于独立软件包，**BusyBox 没有内置 lftp**，嵌入式 rootfs 需要单独交叉编译安装，存在依赖库；使用 SFTP 协议时，依然要求服务端具备可用 SFTP 服务组件，仅 SSH 登录成功不代表可以使用 SFTP。

## 语法

```
lftp [选项] [参数]
```

## 参数与交互命令

|必须掌握|`mirror dir`|同步远程目录到本地；根据配置策略判断传输文件，**默认不做完整哈希校验，默认不会删除目标端多余文件**|

|了解即可|`debug`|开启客户端调试输出，版本不同语法存在差异|

|了解即可|`ls`|列出远程目录文件；`lls`列出本地文件|

## 实战示例

```
# 显式指定FTP协议连接
lftp ftp://liangxu@192.168.107.133
# 显式指定SFTP协议连接（推荐写法，避免协议识别错误）
lftp sftp://liangxu@192.168.107.133
```

进入交互终端：

```
# 场景1：SFTP下载远程日志目录到本地/tmp/logs
lcd /tmp
mirror /var/log ./logs

# 场景2：上传本地工程目录到远程/tmp/test_project
lcd /home/user/test_project
mirror -R ./ /tmp/test_project

# 场景3：先预览，再执行同步（推荐安全操作流程）
mirror --dry-run /var/log ./logs

get file.txt              # 下载单个文件

mput newfile*.txt         # 批量上传

```

## ⚠️ 嵌入式 Linux 重点注意

1. `mirror`目录同步：
    - 判断文件是否传输依靠配置策略、文件元信息，**不会默认做完整文件哈希比对**；
    - 默认不会删除目标目录多余文件；`--delete`参数会删除目标端源不存在的文件，风险极高，**强烈建议搭配 --dry-run 预览**；
    - `mirror -R`仅反转同步方向，不代表无条件覆盖远程文件，文件覆盖逻辑由参数、协议共同决定。
2. 断点续传`-c`： FTP 依靠 REST 机制、SFTP 依靠文件偏移读取实现续传；受服务器、客户端版本限制。**远程源文件如果发生修改，直接续传会造成文件损坏，建议重新下载并校验 md5**。上传续传`put -c`的可用性需要结合 lftp 版本与协议确认。
3. 协议选择：推荐写`ftp://` / `sftp://`完整 URL；简写`lftp user@ip`会由客户端自动猜测协议，容易出现协议匹配错误。
4. 选型对比（嵌入式场景）

|工具|适用场景|
|---|---|
|ftp|老旧 FTP 服务器兼容、临时文件传输|
|sftp|交互式单文件 / 少量文件安全传输|
|scp|快速复制单个文件、简单目录拷贝|
|lftp|大量日志、工程目录镜像同步、自动化批量传输、断点续传|


> 极简 rootfs 优先使用系统自带工具，lftp 会引入额外依赖，不必强行部署。

## 面试背诵要点

lftp 是支持 FTP、FTPS、SFTP 等多协议的文件传输客户端，本身不是传输协议。`get/mget`下载文件，`put/mput`上传文件；`mirror`将远程目录同步到本地，`mirror -R`把本地目录同步上传远程。支持断点续传、批量传输，适合嵌入式日志采集、批量资源分发。

mirror 的同步策略受参数、协议能力影响，默认不进行完整哈希校验，默认不会删除目标端多余文件；`--delete`会删除目标多余文件，使用前必须确认同步方向，优先使用`--dry-run`预览。嵌入式系统需要单独部署 lftp，使用 SFTP 协议时服务端需要配套 SFTP 服务组件。

## 易错坑

- 简写`lftp user@ip`协议自动猜测，容易连错协议，推荐显式写`sftp://`或`ftp://`。
- `mirror --delete`高危，不预览直接执行极易误删远程文件。
- `-c`断点续传不是万能，源文件变更后直接续传会导致文件不一致，需要校验文件完整性。
- 误区：mirror 默认对比文件哈希；实际默认依靠文件元信息判断，不会逐字节比对内容。
- 嵌入式误区：BusyBox 不内置 lftp，需要单独部署，存在依赖库；lftp 的 SFTP 连接依然要求服务端具备 sftp-server。

# wget 命令笔记（Linux 终端｜HTTP/HTTPS/FTP 文件下载工具）

> 作用：wget 是非交互式网络文件下载工具，支持 HTTP、HTTPS、FTP；嵌入式开发常用来拉取固件、工具包、日志。支持断点续传、后台下载、限速；**BusyBox 一般内置 wget，但属于精简版本，可用参数取决于编译配置**。

## 语法

```
wget [option]... [URL]...
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-c`|断点续传，利用 HTTP Range 机制；服务器不支持 Range、远程文件变更时续传可能失效；固件下载完成务必校验完整性；**`-O`和`-c`不适合直接组合做普通文件断点续传**|
|必须掌握|`-O filename`|大写 O，下载内容写入指定文件；文件存在默认覆盖；`-O -`输出内容到标准输出 stdout|
|必须掌握|`-P dir`|指定文件保存前缀目录，目录必须预先存在；仅指定存放路径，不是重命名；可搭配`-O`同时指定路径 + 文件名|
|必须掌握|`-T seconds`|设置网络读取超时时间|
|必须掌握|`-t number`|设置失败重试次数|
|了解即可|`-b`|后台下载；GNU wget 默认日志`wget-log`，文件名受当前目录 / 版本影响；推荐搭配`-o`手动指定日志文件|
|了解即可|`-o logfile`|小写 o，将诊断日志写入指定日志文件，和大写`-O`区分开|
|了解即可|`--limit-rate=300k`|限速下载，单位 k/K (KB), m/M (MB)|
|了解即可|`-i file`|读取文本文件内 URL 列表，批量下载多个链接|
|了解即可|`-q`|安静模式，减少终端输出|
|了解即可|`--spider`|仅检测资源是否存在，不下载文件；行为受协议、版本限制|
|了解即可|`--no-check-certificate`|跳过 HTTPS 证书校验；**风险高，下载固件场景不推荐优先使用**|

## 实战示例

```
# 下载单个文件，使用原始文件名保存
wget https://cn.wordpress.org/latest-zh_CN.zip

# 下载并保存为指定文件名
wget -O firmware.bin https://example.com/firmware.bin

# 将下载内容直接输出到标准输出
wget -O - https://example.com/version.txt

# 指定保存目录（目录需提前创建 mkdir -p /tmp/downloads）
mkdir -p /tmp/downloads
wget -P /tmp/downloads https://example.com/firmware.bin
# 同时指定目录+文件名（-O带完整路径）
wget -O /tmp/downloads/firmware.bin https://example.com/firmware.bin

# 断点续传（不搭配-O）
wget -c https://example.com/firmware.bin

# 设置超时10秒，最多重试3次
wget -T 10 -t 3 https://example.com/firmware.bin

# 后台下载 + 手动指定日志文件
wget -b -o /tmp/wget-download.log https://example.com/firmware.bin
tail -f /tmp/wget-download.log

# 读取文件内多个URL批量下载
vim urllist.txt
wget -i urllist.txt

# 限速下载，限制最高300KB/s
wget --limit-rate=300k https://cn.wordpress.org/latest-zh_CN.zip
```

## ⚠️ 嵌入式 Linux 重点注意

1. GNU wget 功能完整；BusyBox 精简 wget 裁剪严重，`--limit-rate`、HTTPS、`-b`后台下载等功能要看编译开关，先用`wget --help`确认支持参数。
2. HTTPS 下载失败排查维度：
    
    - BusyBox wget 编译未开启 TLS 支持
    - 缺少 CA 根证书、证书链不全
    - 系统时间错误，证书有效期校验失败
    - TLS 版本、加密套件不兼容
    - DNS、路由、防火墙、服务端问题
    
    > 优先修复证书 / 时间，不推荐直接使用`--no-check-certificate`绕过校验，固件下载有安全风险。
    
3. 断点续传`-c`：依赖服务器 Range 支持；如果远程文件在中断后发生修改，直接续传会造成文件损坏，下载后**必须校验 sha256sum**。
4. `-O`大写、`-o`小写极易混淆：`-O`控制下载数据保存文件；`-o`控制日志输出文件。
5. `-P`仅为保存目录前缀，不会自动创建目录，需要`mkdir -p`提前建立。

### 嵌入式 wget 排障流程

1. 查看支持能力：`wget --help`，确认 HTTPS、超时、重试等参数是否可用
2. 网络连通：`ip route`、`ping -c3 example.com`，同时检查 DNS 解析、端口连通
3. HTTPS 环境：校验系统时间、CA 证书、TLS 支持
4. 文件校验：`ls -lh firmware.bin`，`sha256sum firmware.bin`对比官方校验值；固件升级优先验证数字签名

## 面试背诵要点

Wget 是 Linux 下非交互式网络下载工具，支持 HTTP、HTTPS、FTP 协议。GNU Wget 功能完整；BusyBox 内置精简版，协议与参数受固件编译配置限制。 常用参数：`-c`断点续传，`-O`指定输出文件，`-P`指定保存目录，`-T`超时，`-t`重试次数；`-b`后台下载，`-o`自定义日志，`-i`批量读取 URL。 嵌入式 HTTPS 下载失败，排查 TLS 支持、CA 证书、系统时间、网络连通；固件下载后一定要校验文件完整性。对比 wget，curl 更适合 HTTP 接口调试，二者能力都取决于编译版本。

## 易错坑

- `-O`大写（下载内容输出），`-o`小写（日志输出），千万不要写混
- `-c`断点续传不要直接搭配`-O`做普通文件续传
- `-P`目录不会自动创建，必须提前 mkdir
- BusyBox wget 裁剪版本可能无 HTTPS、限速、后台下载功能
- `--no-check-certificate`仅应急使用，固件下载场景禁止作为常规方案
- 断点续传成功不代表文件正确，一定要做 sha256 校验

# scp 命令笔记（Linux 终端｜基于 SSH 安全拷贝）

> 作用：scp（secure copy）远程拷贝文件 / 目录，传输全程加密；嵌入式开发常用于上传固件、下载设备日志。 版本要点：OpenSSH 9.0 及以上，scp 命令**底层默认改用 SFTP 协议传输**，命令写法不变；可加`-O`强制使用老式 SCP/RCP 协议，用于兼容老旧设备。 区分：scp 是拷贝命令；sftp 是交互式文件传输客户端。

## 语法

```
scp [选项] source ... target
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-r`|递归复制整个目录；拷贝目录必须加此参数，单文件无需|
|必须掌握|`-P port`|大写 P，指定远程 SSH 端口；ssh 命令是小写`-p`，面试高频易错点|
|必须掌握|`-p`|小写 p，保留源文件修改时间、访问时间、权限模式；**不能完整保留属主、属组、ACL 扩展属性**；最终生效与否受远端权限、文件系统限制|
|必须掌握|`-v`|输出完整 SSH 连接、握手、传输调试日志，排查失败首选|
|了解即可|`-i identity_file`|指定私钥文件，密钥登录场景|
|了解即可|`-C`|开启传输压缩，降低带宽占用|
|了解即可|`-q`|静默模式，不打印进度信息|
|了解即可|`-O`|强制使用旧 SCP/RCP 协议，仅兼容老旧设备，日常不推荐|
|了解即可|`-l limit`|限制传输带宽，单位 Kbit/s|
|了解即可|`-3`|远程到远程拷贝，流量经本地主机中转|

## 实战示例

```
# 1. 从远程复制文件到本地
scp liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~

# 2. 从远程复制目录到本地（加-r）
scp -r liangxu@192.168.107.128:/home/liangxu/commands/scp/dir/ ~

# 3. 上传本地文件到远程机器
scp /newfile.txt liangxu@192.168.107.128:/home/liangxu/commands/scp/

# 4. 上传本地目录到远程机器（-rp组合：递归+保留文件属性）
scp -rp ~/newdir liangxu@192.168.107.128:/home/liangxu/commands/scp/

# 5. 指定非默认端口传输（大写-P）
scp -P 2222 liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~

# 6. 保留文件时间与权限（小写-p）
scp -p liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~

# 7. 开启调试日志，排查传输故障
scp -v firmware.bin liangxu@192.168.107.128:/tmp/

# 8. 使用私钥上传固件
scp -i ~/.ssh/id_ed25519 firmware.bin liangxu@192.168.107.128:/tmp/
```

## ⚠️ 嵌入式 Linux 重点注意

1. SSH 连通只是基础前提，**ssh 能连上 ≠ scp 一定成功**。失败原因常见：远程路径不存在、用户读写权限不足、磁盘满、文件系统只读、Dropbear 精简 ssh 缺少配套传输组件、路径含特殊字符。
2. 原生 scp**没有标准断点续传参数**，传输中断一般需要从头重传；大固件、不稳定网络建议改用 lftp/mirror，传输结束务必校验 sha256。
3. OpenSSH9.0 + 底层默认走 SFTP 协议；老旧嵌入式设备只支持传统 SCP 协议，此时加`-O`兼容。
4. `-p`仅保留基础时间和权限，**不能保留属主、ACL 等高级元数据**；远端权限会影响最终文件属性。

### 嵌入式文件传输选型对比

表格

|工具|适用场景|特点|
|---|---|---|
|scp|简单单文件 / 小目录一次性拷贝|命令简洁，老设备普遍支持；原生无断点续传|
|sftp|交互式操作、文件浏览、分步上传下载|支持续传，可切换目录查看文件|
|lftp mirror|大量文件、工程目录反复同步|增量同步、断点续传，适合批量日志 / 源码同步|

## 面试背诵要点

SCP 是基于 SSH 的远程文件复制命令，用于本地与远程主机安全传输文件或目录。`-r`递归拷贝目录；`-P`大写指定远程端口；`-p`小写保留文件时间和权限；`-v`打印调试信息，`-i`指定私钥。 OpenSSH9.0 及以上版本 scp 底层默认使用 SFTP 协议，scp 命令本身仍可正常使用；`-O`参数用于回退到老 SCP 协议兼容老旧设备。 原生 scp 没有标准断点续传，适合一次性简单拷贝；交互式文件操作用 sftp，大量目录增量同步选用 lftp。嵌入式设备需要关注 SSH 服务实现、远端目录权限、磁盘空间，传输固件后校验文件完整性。

## 易错坑

- `-P`大写 = 端口；`-p`小写 = 保留文件属性，极易写反
- 拷贝目录**必须加`-r`**，单文件不要携带 - r
- ssh 登录成功 scp 依旧失败：排查远端权限、磁盘、文件系统只读、ssh 服务端组件
- `-p`不能完整保留属主、ACL 等扩展属性
- scp 原生不支持断点续传，大文件网络不稳优先 lftp
- OpenSSH 新版本 scp 底层是 SFTP，不是 scp 命令被淘汰

# curl 命令笔记（Linux 终端｜网络请求 / 文件传输工具）

> 作用：curl 多功能网络传输工具，支持 HTTP/HTTPS/FTP 等协议；嵌入式开发多用于接口调试、HTTP 请求测试、文件上传下载。 区分：wget 侧重**文件下载保存**；curl 侧重**灵活的 HTTP 接口交互**，默认直接输出响应到终端，支持自定义请求头、Cookie、POST 数据、各类 HTTP 方法。 嵌入式提示：BusyBox 一般不带 curl，只有精简 wget；curl 需要单独安装 / 交叉编译，TLS、协议支持取决于编译配置。可用`which curl`、`curl --version`检查是否安装及支持能力。

## 语法

```
curl [参数] URL
```

## 参数

表格

|优先级|参数|作用|
|---|---|---|
|必须掌握|`-o filename`|小写 o，将响应内容保存到指定本地文件名（自定义命名）|
|必须掌握|`-O`|大写 O，自动使用远程资源原始文件名保存文件|
|必须掌握|`-C -`|断点续传；`-C -`自动读取本地文件大小获取偏移，配合`-O`使用；需要本地已有部分下载文件，依赖服务器 Range 支持，远程文件变更不可直接拼接，下载后校验哈希|
|必须掌握|`-I`|发送 HEAD 请求，仅打印 HTTP 响应头；**HEAD 成功≠GET 下载一定成功**，部分服务端对 HEAD/GET 处理逻辑不同|
|必须掌握|`-u user:pwd`|身份认证，传递用户名：密码，HTTP 基础认证、FTP 认证都可用|
|必须掌握|`-T file`|上传本地文件；FTP 为 FTP 上传；HTTP 默认发起 PUT 请求，需要服务端允许 PUT，否则返回 405|
|必须掌握|`-H "Header: value"`|自定义 HTTP 请求头，Token、Authorization 场景高频|
|必须掌握|`-d "key=value"`|发送 POST 表单数据|
|必须掌握|`-L`|跟随 HTTP 重定向|
|必须掌握|`-sS`|静默模式，隐藏进度条，但保留错误信息；脚本首选；单独`-s`会隐藏错误，不推荐脚本使用|
|必须掌握|`--connect-timeout 5`|连接阶段超时时间，单位秒，只限制 TCP 连接阶段|
|必须掌握|`-v`|详细调试输出，查看 DNS、TCP、TLS 握手、HTTP 交互，排错神器|
|了解即可|`-b "k=v"`|设置 Cookie；也可读取 cookie 文件|
|了解即可|`-c cookie.txt`|把服务端返回 Cookie 保存到文件|
|了解即可|`-X METHOD`|手动指定 HTTP 请求方法（PUT/DELETE 等）|
|了解即可|`-w`|自定义输出内容，可打印 http_code、耗时等信息|

## 实战示例

```
# 获取网页源码，直接打印终端
curl www.baidu.com

# 保存网页，自定义文件名
curl -o baidu.html www.baidu.com

# 下载文件，使用远程原始文件名保存
curl -O https://cn.wordpress.org/latest-zh_CN.zip

# 下载文件并重命名
curl -o wp.zip https://cn.wordpress.org/latest-zh_CN.zip

# 断点续传下载
curl -C - -O https://cn.wordpress.org/latest-zh_CN.zip

# HEAD请求，只打印响应头
curl -I https://cn.wordpress.org/latest-zh_CN.zip

# GET请求，只输出HTTP状态码（推荐替代-I探测真实GET可用性）
curl -sS -o /dev/null -w '%{http_code}\n' https://example.com/firmware.bin

# FTP，带账号密码下载文件
curl -u liangxu:123456 ftp://www.baidu.com/file.txt

# FTP上传本地文件
curl -T newfile.txt -u 用户名:密码 ftp://www.baidu.com/dir/

# HTTP PUT上传文件，服务器需要支持PUT
curl -T firmware.bin https://example.com/upload/firmware.bin

# POST提交表单数据
curl -d "name=test&value=123" https://example.com/api

# 自定义请求头Token认证
curl -H "Authorization: Bearer TOKEN" https://example.com/api

# 设置Cookie
curl -b "session=abc123" https://example.com/

# 跟随重定向下载固件，失败返回非0退出码
curl -fL -o firmware.bin https://example.com/firmware.bin

# 设置连接超时5秒
curl --connect-timeout 5 https://example.com/api

# 开启详细调试，排查TLS/网络问题
curl -v https://example.com/api
```

## ⚠️ 嵌入式 Linux 重点注意

1. BusyBox 默认不包含 curl，需要单独部署；wget 在 BusyBox 里更常见。部署 curl 后用`curl --version`查看支持协议、TLS 后端。
2. HTTPS 请求失败排查方向：编译是否开启 TLS、CA 根证书、系统时间、TLS 加密套件、DNS / 路由防火墙。
3. `-I` HEAD 请求只能做粗略探测，HEAD 成功不代表 GET 能正常下载文件。如果要真实校验资源，用`curl -sS -o /dev/null -w '%{http_code}'`。
4. `-C -`断点续传前提：本地存在已下载文件 + 服务器支持 Range；远程文件更新后直接续传会造成文件损坏，固件下载**必须校验 sha256sum**。
5. `-T`在 HTTP 下默认 PUT，不是所有 web 服务器都支持 PUT，会返回 405 Method Not Allowed。
6. 脚本推荐`-sS`，不推荐单纯`-s`，防止错误被静默隐藏。

### curl vs wget 选型对比

表格

|对比项|curl|wget|
|---|---|---|
|典型用途|HTTP API 调试、自定义请求、上传文件|文件下载、批量下载|
|输出行为|默认输出到 stdout|默认保存成文件|
|自定义请求头|原生强大`-H`|受版本限制|
|HTTP 方法 / POST 数据|完整支持|能力弱|
|断点续传|`-C -`|`-c`|
|后台下载|需 shell 后台|GNU wget 原生`-b`|
|嵌入式预装情况|一般需要单独交叉编译安装|BusyBox 内置精简版本|

## 面试背诵要点

curl 是支持 HTTP、HTTPS、FTP 的多协议网络传输工具，常用于接口调试、文件上传下载。`-o`自定义保存文件名，`-O`使用远程原名保存；`-C -`尝试断点续传；`-I`发送 HEAD 请求；`-u`基础认证；`-T`上传文件；`-H`自定义请求头，`-d`POST 数据；`-L`跟随重定向；`-sS`适合脚本，`-v`用于排错。 curl 默认输出响应到标准输出，适合接口调试；wget 更适合直接下载文件。嵌入式 Linux 要确认 curl 是否安装、TLS 是否启用；HTTPS 失败检查网络、系统时间、CA 证书；固件下载后校验文件完整性。

## 易错坑

- `-b`Cookie 参数前面的横线不能丢，不要写成 b "k=v"
- `-I`HEAD 探测有局限性，HEAD 成功 ≠ GET 下载一定正常
- `-C -`中间的`-`不能省略；续传成功不等于文件完整，一定要校验哈希
- HTTP `-T`是 PUT 上传，web 服务器默认一般不开放 PUT
- BusyBox 没有 curl，不要默认嵌入式设备自带 curl
- `-s`会屏蔽错误信息，脚本推荐`-sS`
