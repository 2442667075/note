# wc 命令笔记（Linux｜文本统计）

> 作用：统计文本的行数、单词数、字节 / 字符数。

## 语法

```
wc [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-w`|统计单词数，空白 / 换行分隔的字符串算 1 个单词|
|`-c`|统计字节数 bytes|
|`-l`|统计行数 lines|
|`-m`|统计字符数（中文多字节场景和`-c`不一样）|
|`-L`|获取文件**最长一行**的长度|

## 实战示例

```
# 默认输出：行数、单词数、字节数
wc file.txt

# 只统计单词数
wc -w file.txt

# 只统计字符数
wc -m file.txt

# 只统计字节数
wc -c file.txt

# 只统计行数
wc -l file.txt

# 获取最长行长度
wc -L file.txt

# 管道用法：cat输出交给wc统计行数
cat file.txt | wc -l
```

## 嵌入式 & 面试重点

1. `wc -l`是面试高频，常配合`grep`统计匹配结果行数。
2. `-c`字节、`-m`字符区别：UTF-8 中文 1 个汉字占 3 字节，`-c`会算 3，`-m`只算 1 个字符。
3. BusyBox 支持 wc，嵌入式环境可用。

## 易错坑

1. wc 默认输出顺序：**行、单词、字节**，顺序不要记反。
2. 如果文件最后一行没有换行符，`wc -l`不会统计这一行。

# split 命令笔记（Linux｜文件分割）

> 作用：把大文件按**行数 / 字节大小**切分成多个小文件

## 语法

```
split [OPTION]... [FILE [PREFIX]]
```

## 参数

表格

|参数|说明|
|---|---|
|`-<行数>` / `-l 行数`|按行数分割，每 N 行生成一个小文件|
|`-b <字节>`|按字节大小分割；支持单位 k、M、G|
|`-d`|使用**数字**作为后缀（默认是字母 aa,ab,ac…）|
|`-a`|指定后缀长度，默认 2 位|
|PREFIX|分割后文件名称前缀|

## 实战示例

```
# 每2行切割成一个小文件
split -2 file1.txt

# 按大小分割，每10KB一个文件
split -b 10k file2.txt

# 每10KB分割，数字后缀，后缀占3位
split -b 10k -d -a 3 file2.txt

# 每10KB分割，数字后缀3位，指定前缀split_file
split -b 10k -d -a 3 file2.txt split_file
```

## 嵌入式 & 面试重点

1. 常用于日志拆分、超大固件分包传输；合并用`cat split_file* > origin_file`。
2. 默认后缀是字母 aa、ab，`-d`改成 00、01 数字编号，脚本处理更方便。
3. BusyBox 支持 split，嵌入式环境可用来拆分大文件。

## 易错坑

1. `-b`按字节切割文本文件，**可能切断单行文字**；按行分割用`-l`。
2. `-a`设置后缀位数，文件数量超过位数上限会报错。

# cut 命令笔记（Linux｜截取文本片段）

> 作用：提取文件每行里**指定字节、字符、字段**，常用于按列解析文本。

## 语法

```
cut OPTION... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-b`|按**字节**截取|
|`-c`|按**字符**截取（中文多字符场景优先用 - c）|
|`-d`|自定义字段分隔符，默认是 TAB 制表符|
|`-f`|配合`-d`，提取指定字段（列）|
|`-n`|不分割多字节字符，防止中文乱码|
|`--complement`|取反：输出**除选中部分以外**的内容|
|`--out-delimiter`|设置输出时的字段分隔符|

## 实战示例

```
# 提取第2列（默认TAB分隔）
cut -f2 file1.txt

# 提取除第2列之外全部字段
cut -f2 --complement file1.txt

# 使用;作为分隔符，提取第2列
cut -f2 -d";" file2.txt

# 提取第2,3,4,6字节
cut -b 2-4,6 file3.txt

# 提取第1～3字符
cut -c1-3 file3.txt

# 提取前2个字符
cut -c-2 file3.txt

# 提取第4个及之后全部字符
cut -c4- file3.txt
```

## 嵌入式 & 面试重点

1. `cut -d: -f1 /etc/passwd` 经典考题，提取系统用户名。
2. 空格分隔文本**不推荐 cut**，优先用 awk；cut 只支持**单个分隔字符**，不能匹配多空格。
3. BusyBox 支持 cut，嵌入式脚本解析日志很常用。

## 易错坑

1. `-b`字节，`-c`字符：UTF8 中文 1 汉字占 3 字节，用`-b`截取会把汉字拆坏，中文解析用`-c`。
2. `-d`只能跟**单个字符**，不能写多个字符分隔符。

# paste 命令笔记（Linux｜按行横向拼接文件）

> 作用：**横向合并多个文件**（按行并排拼接，不是上下追加；上下追加用 cat）

## 语法

```
paste [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-d`|设置字段分隔符；默认分隔符是 Tab 制表符|
|`-s`|串行合并：把**单个文件内所有行合并成一行**|
|`-`|从标准输入读取数据，一个`-`代表一路标准输入|

## 实战示例

```
# file1、file2按行横向并排输出
paste file1.txt file2.txt

# 调换文件顺序，拼接结果随之改变
paste file2.txt file1.txt

# 同时横向拼接3个文件
paste file1.txt file2.txt file3.txt

# 指定分隔符为冒号，横向拼接两个文件
paste -d":" file1.txt file2.txt

# -s：每个文件内部多行合并为一行，用:分隔
paste -d":" -s file1.txt file2.txt

# ls输出交给paste，每行放4个文件名
ls | paste -d" " - - - -
```

## 嵌入式 & 面试重点

1. ✅paste：**左右并排（横向）**；cat：**上下追加（纵向）**，面试高频区分考点。
2. `-`代表 stdin，可以多次使用实现多列排版。
3. BusyBox 内置 paste，脚本做日志表格、多列排版时很方便。

## 易错坑

1. 分隔符`-d`只支持单个字符，多字符分隔不支持。
2. 两个文件行数不一致时，短文件读完后对应列会为空，不会报错。
# sort 命令笔记（Linux｜文本行排序）

> 作用：对文件的每行文本进行排序，默认**字典序**。

## 语法

```
sort [参数] 文件
```

## 参数

表格

|参数|说明|
|---|---|
|`-n`|按**数值大小**排序（不是字典序，面试高频）|
|`-t <分隔字符>`|指定字段分隔符|
|`-k`|指定用哪一列（栏位）作为排序关键字|
|`-r`|反向排序（降序）|

## 实战示例

```
# 默认字典序（字母顺序）
sort file1.txt

# 反向降序排序
sort -r file1.txt

# 纯数字从小到大排序
sort -n file2.txt

# 以冒号:做分隔符，取第3列，按数字升序排序
sort -t: -k 3 -n file3.txt
```

## 嵌入式 & 面试重点

1. **字典序 vs 数值序**：不加`-n`时，`10`会排在`2`前面；`-n`才是真正数字大小比较，面试必考点。
2. 常配合`uniq`去重：`sort file.txt | uniq`。
3. BusyBox 支持 sort，日志、脚本处理很常用。

## 易错坑

1. `-k`是从 1 开始计数，不是从 0。
2. sort**默认不修改原文件**，结果输出到 stdout；如需保存要重定向`sort file > newfile`。

# uniq 命令笔记（Linux｜去连续重复行）

> 作用：**只移除连续重复的行**；非连续重复不会自动去重，面试高频坑点。

## 语法

```
uniq [OPTION]... [INPUT [OUTPUT]]
```

## 参数

表格

|参数|说明|
|---|---|
|`-c`|在每行前面打印该行出现次数|
|`-d`|只输出**存在重复**的行，每种重复行只显示 1 次|
|`-u`|只输出**仅出现一次**、无重复的行|

## 实战示例

```
# 删除连续重复行，保留单行
uniq file.txt

# 统计每行出现次数
uniq -c file.txt

# 只显示有重复的记录
uniq -d file.txt

# 只显示只出现一次、无重复的行
uniq -u file.txt
```

## 嵌入式 & 面试重点

1. ⚠️核心考点：**uniq 只能去除相邻连续重复**，如果重复行不挨在一起，必须先用`sort`排序，再管道交给 uniq：

```
sort file.txt | uniq
sort file.txt | uniq -c
```

2. 常用于日志统计，统计相同日志打印次数。
3. BusyBox 支持 uniq，嵌入式脚本可用。

## 易错坑

1. 直接 uniq**不能全局去重**，必须先 sort。
2. 末尾换行缺失会影响 uniq 识别行边界。

# diff /patch 命令笔记（Linux｜文件对比与补丁）

> 作用：diff 对比两个文本文件差异；patch 使用 diff 生成的补丁文件更新源文件。

## 语法

```
diff [OPTION]... FILES
```

## 参数

表格

|参数|说明|
|---|---|
|`-y`|并列左右两栏显示异同|
|`-c`|上下文格式，输出完整内容并标记差异|
|`-u`|unified 合并格式（最常用，patch 标准格式）|
|`-W`|设置输出宽度，搭配`-y`使用|

## diff 标记含义

- `a` add：新增
- `c` change：修改
- `d` delete：删除
- `|` 前后文件内容不同
- `<` 后面文件比前面文件少 1 行
- `>` 后面文件比前面文件多 1 行
- `+` 后者比前者多一行（`-u`格式）
- `-` 后者比前者少一行（`-u`格式）
- `!` 该行内容存在差别（`-c/-y`格式）

## 实战示例

```
# 对比两个文件
diff file1.txt file2.txt

# 左右并排对比，宽度50
diff -y -W 50 file1.txt file2.txt

# 上下文格式输出
diff -c file1.txt file2.txt

# unified标准格式（推荐，补丁首选）
diff -u file1.txt file2.txt

# 将差异保存为补丁文件
diff file1.txt file2.txt > file.patch

# 使用补丁更新file1.txt
patch file1.txt file.patch
```

## 嵌入式 & 面试重点

1. **`diff -u`**：代码版本、驱动 / 内核补丁最常用格式，面试高频。
2. patch 常用于源码打补丁，嵌入式内核、驱动开发必备。
3. 只对比文本，二进制文件 diff 效果差，二进制对比用`cmp`。
4. BusyBox 可支持简易 diff/patch。

## 易错坑

1. diff 默认**不修改原文件**，仅输出差异；patch 才修改文件。
2. 换行符不同（Windows CRLF / Linux LF）会被判定为文件差异。

# join 命令笔记（Linux｜按关键字连接两个文件，类似 SQL 表连接）

> 作用：将两个文件，按**相同关键字段**做关联合并；前提：文件必须预先按关键字排序。

## 语法

```
join [OPTION]... FILE1 FILE2
```

## 参数

表格

|参数|说明|
|---|---|
|`-a1 / -a2`|`-a1`：输出文件 1 全部记录；`-a2`：输出文件 2 全部记录（包含不匹配行）|
|`-o`|指定输出字段格式|
|`-t`|设置字段分隔符|
|`-v1 / -v2`|`-v1`只输出文件 1**无匹配**的行；`-v2`只输出文件 2 无匹配的行|
|`-j`|指定用第几列作为匹配关键字段（两文件同列）|

## 实战示例

```
# 默认使用第1列做连接字段，内连接，只输出两边匹配上的行
join file1.txt file2.txt

# 左连接：保留文件1所有记录，匹配不到的右边填空
join -a1 file1.txt file2.txt

# 右连接：保留文件2所有记录
join -a2 file1.txt file2.txt

# 全连接：两个文件全部记录都输出
join -a1 -a2 file1.txt file2.txt

# 指定输出字段：文件1的1、2、3列，文件2的2、3列
join -o 1.2 1.3 2.3 file1.txt file2.txt

# 指定分隔符为空格
join -t ' ' file1.txt file2.txt

# 只输出文件1中找不到匹配的行
join -v1 file1.txt file2.txt

# 使用第2列作为匹配关键字段
join -j2 file1.txt file2.txt
```

## 嵌入式 & 面试重点

1. ⚠️硬性前提：**两个文件必须按 join 关键字预先 sort 排序，否则匹配会出错**。
2. 本质类似 SQL：内连接（默认）、左连接`-a1`、右连接`-a2`、全连接`-a1 -a2`。
3. 多用于文本表格处理，嵌入式脚本处理表格类日志。

## 易错坑

1. 文件未排序，join 不会自动排序，直接执行会丢失大量匹配行。
2. `-t`只能单个字符分隔符，多字符分隔不支持。
3. 关键字两端空格不一样会判定为不匹配。


# tr 命令笔记（Linux｜字符转换 / 删除 / 压缩）

> 作用：转换、删除、压缩字符，**只处理标准输入，不直接接收文件名参数**

## 语法

```
tr [OPTION]... SET1 [SET2]
```

## 参数

表格

|参数|说明|
|---|---|
|`-c`|反选字符集合：对**不在 SET1**里的字符做处理|
|`-d`|删除字符集合中所有匹配字符|
|`-s`|把**连续重复字符**压缩成单个字符|

> 字符类：`[:lower:]`小写、`[:upper:]`大写、`[:digit:]`数字

## 实战示例

```
# 小写转大写
tr "[a-z]" "[A-Z]" < file.txt
cat file.txt | tr a-z A-Z
echo "hello world" | tr [:lower:] [:upper:]

# 大小写互换
echo "Hello World" | tr '[A-Za-z]' '[a-zA-Z]'

# 删除小写字母
echo "abcABdefCD" | tr -d "[a-z]"

# 删除数字
echo "abc123def888hello" | tr -d 0-9

# 删除空格与tab
echo " Hello World " | tr -d ' \t'

# -c 只保留数字和换行，其余全部删掉
echo -e "abc123*& def888" | tr -d -c '0-9\n'

# -s 压缩连续换行（合并空白行）
echo -e "1\n\n2\n\n\n3" | tr -s '\n'

# -s 压缩连续重复字符 o、x
echo "Hellooo  Linuxxxxxx" | tr -s "xo"

# 多个连续空格合并成单个空格，再替换为破折号
echo "2022  05  16" | tr -s ' ' '-'

# Tab制表符转为空格
echo -e "hello\tworld" | tr '\t' ' '
```

## 嵌入式 & 面试重点

1. ✅tr**不能直接跟文件**，必须通过`<`重定向或者管道`|`传入内容，面试高频坑。
2. tr 操作是**单字符映射**，适合简单字符替换；复杂字符串替换用`sed`。
3. BusyBox 内置 tr，嵌入式脚本清洗日志非常常用。

## 易错坑

1. tr 只处理**单个字符**，无法替换长字符串。
2. `-s`只是压缩连续重复，不是删除所有重复；只压缩挨在一起的。
3. 反选`-c`经常搭配`-d`一起使用，保留指定集合。


# sed 命令笔记（Linux｜流式文本编辑器，批量编辑文本）

> 作用：流式批量编辑文本，默认只输出到 stdout；`-i` 才直接修改原文件

## 语法

```
sed [选项] [动作] 文件名
```

## 选项

表格

|参数|说明|
|---|---|
|`-n`|只输出匹配脚本处理后的行，不打印默认全部内容|
|`-e`|执行多个脚本规则，多个处理条件|
|`-i`|**直接修改源文件，操作前建议备份**|

## 动作指令

表格

|指令|含义|
|---|---|
|`a`|append，在**指定行之后**新增一行|
|`c`|replace，**整行取代**|
|`d`|delete，删除行|
|`i`|insert，在**指定行之前**插入一行|
|`p`|print，打印输出，一般搭配 `-n`|
|`s`|substitute，字符串替换，格式 `s/旧/新/g`；`g`= 全局替换|

## 实战示例

```
# 输出第2行
sed -n '2p' file.txt

# 输出3~5行
sed -n '3,5p' file.txt

# 搜索包含an关键字的行并打印
sed -n '/an/p' file.txt

# 删除2~4行（仅输出，不改原文件）
sed '2,4d' file.txt

# 删除包含an关键字的行
sed '/an/d' file.txt

# 在第2行后面追加一行：nice
sed '2a nice' file.txt

# 在第2行前面插入一行
sed '2i 123456789' file.txt

# 将第2行整行替换为 asdfgh
sed '2c asdfgh' file.txt

# 2到5行整行替换
sed '2,5c data changed' file.txt

# 全局替换：liangxu → alvin（整文件所有匹配）
sed 's/liangxu/alvin/g' file.txt

# 只替换第3行的匹配内容
sed '3s/liangxu/alvin/g' file.txt

# 多个替换条件，-e 叠加规则
sed -e 's/liangxu//g;s/alvin//g' file.txt

# -i 直接修改原文件，替换第3行
sed -i '3s/liangxu/alvin/g' file.txt
```

## 嵌入式 & 面试重点

1. `-i` 高危：**直接修改磁盘文件**，生产 / 调试建议先不带`-i`预览结果；可以用`-i.bak`自动备份原文件 `sed -i.bak 's/xx/yy/g' file.txt`。
2. 工作原理：按行流式读取，**不一次性加载全部文件**，适合处理超大日志。
3. 正则支持基础正则，高级扩展正则加 `-r`。
4. 嵌入式脚本里常用于日志过滤、配置文件批量修改。

## 易错坑

1. 不加 `-n` 时，`p` 动作会**重复打印行**（默认输出 + p 打印）。
2. `a` 是**行后追加**；`i` 是**行前插入**，两个很容易记混。
3. `s///g` 末尾不带`g`只会替换**每行第一个匹配**，不是全局。

# awk 命令笔记（Linux｜文本数据处理编程语言）

> 作用：面向字段的文本处理语言，擅长按列解析日志、表格文本，处理结构化文本。

## 语法

```
awk '条件1 {动作1} 条件2 {动作2} ...' file.txt
```

## 参数

表格

|参数|说明|
|---|---|
|`-F`|指定**输入字段分隔符**|
|`-v`|自定义变量|
|`-f`|从外部脚本文件读取 awk 命令|
|`-m`|对 val 值设置内存限制|

## 常用内置变量

表格

|变量|含义|
|---|---|
|`ARGC`|命令行参数个数|
|`ARGV`|命令行参数数组|
|`ENVIRON`|读取系统环境变量|
|`FILENAME`|当前正在处理的文件名|
|`FNR`|当前文件内的行号（多个文件时重置）|
|`FS`|输入字段分隔符，等价 `-F`|
|`NF`|当前行**字段（列）总数**|
|`NR`|全局累计已读行号（多文件持续累加）|
|`OFS`|输出字段分隔符|
|`ORS`|输出记录分隔符（默认换行）|
|`RS`|输入记录分隔符|

## 实战示例

```
# df -h输出，打印第1列、第3列
df -h | awk '{print $1 "\t" $3}'

# 以冒号:分隔，打印/etc/passwd的第1、3列
awk -F: '{print $1 "\t" $3}' /etc/passwd

# 筛选第3列UID >=500 的行
awk -F: '$3>=500' /etc/passwd

# 匹配包含liangxu的整行
awk -F: '/liangxu/' /etc/passwd

# 匹配liangxu，输出第7列（shell字段）
awk -F: '/liangxu/{print $7}' /etc/passwd

# BEGIN前置初始化，END收尾输出
head /etc/passwd | awk -F: 'BEGIN{print "name\tuid"}{print $1 "\t" $3}END{print "from file /etc/passwd"}'
```

## 嵌入式 & 面试重点

1. `$0` 代表**整行**；`$1 $2 $3` 代表第 1、2、3 列，列号从 1 开始。
2. `BEGIN{}`：**读取文件前执行**；`END{}`：全部文件读取完成后执行。
3. 适合解析 `/etc/passwd`、日志、`df`/`netstat` 这类带固定分隔符的输出；`sed`擅长行替换，`awk`擅长按列处理。
4. BusyBox 提供简易 awk，嵌入式脚本统计日志、提取字段非常常用。

## 易错坑

1. `NR` vs `FNR`：多文件处理时，`FNR`每个文件行号重置，`NR`持续累加。
2. `-F` 分隔符可以是字符串 / 正则，例如 `-F "[,; ]"` 多分隔符。
3. 条件判断运算符：`> >= < <= == !=`，字符串匹配用 `/正则/`。

# grep 命令笔记（Linux｜文本搜索工具）

> 作用：在文本中搜索匹配指定模式（字符串 / 正则）的行

## 语法

```
grep [参数] 匹配模式 文件
```

## 参数

表格

|参数|说明|
|---|---|
|`-i`|忽略大小写|
|`-c`|只输出匹配行**计数**，不输出内容|
|`-l`|只列出**匹配的文件名**，不打印匹配行|
|`-n`|输出匹配行并**显示行号**|
|`-h`|多文件查询时，**不显示文件名**|
|`-s`|屏蔽文件不存在、无匹配等错误信息|
|`-v`|反向匹配：显示**不包含**关键词的所有行|
|`-w`|匹配**整词**（单词边界，不匹配子串）|
|`-x`|匹配**整行**，整行完全一致才算匹配|
|`-r`|递归搜索目录及其子目录下文件|
|`-q`|静默模式，无任何输出；靠返回码判断（0 匹配成功，1 无匹配），常用于 shell 脚本判断|
|`-b`|打印匹配行距离文件开头的字节偏移量|
|`-o`|只打印**匹配到的字符串本身**，搭配 `-b` 输出词偏移量|
|`-F`|按固定字符串匹配，不解析正则（fgrep）|
|`-E`|启用扩展正则表达式（egrep）|

## 实战示例

```
# 单个文件搜索关键词
grep liangxu /etc/passwd

# 多文件搜索
grep liangxu /etc/passwd /etc/shadow

# 多文件搜索，不显示文件名
grep -h liangxu /etc/passwd /etc/shadow

# 递归搜索目录内所有文件
grep -r hello *

# 统计匹配行数
grep -c root /etc/passwd /etc/shadow

# 忽略大小写搜索
grep -i LIANGXU /etc/passwd

# 匹配行+显示行号
grep -n liangxu /etc/passwd

# 反向查找，输出不含关键词的行
grep -v liangxu /etc/passwd

# 只输出匹配的文件名
grep -l hello *

# 整行精确匹配
grep -x hello file1.txt

# 静默检测，脚本中判断是否存在该字符串
grep -q hello file1.txt
```

## 嵌入式 & 面试重点

1. 返回码：`$?` 0 = 找到匹配；1 = 没找到；2 = 文件错误，`-q` 在 shell 脚本里高频使用。
2. 组合使用：`grep -rn "xxx" ./` 开发中最常用，递归 + 行号搜索源码 / 日志。
3. 区分：`-w` 整词匹配，防止子串误匹配；`-F` 固定字符串，特殊符号不用转义。
4. 管道组合：`ps aux | grep xxx` 进程检索，日常调试非常常见。

## 易错坑

1. 不加 `-E` 时，`+ | ()` 这类扩展正则需要转义 `\+ \|`。
2. `-v` 是**取反行**，不是删除关键词，整行不包含才输出。
3. `-r` 递归搜索，会遍历目录；注意不要在根目录随便执行，速度很慢。

# egrep 命令笔记（Linux｜扩展正则搜索，等价 `grep -E`）

> 作用：查找指定字符串，**直接支持扩展正则表达式**，不用对 `+ | () {}` 转义

## 语法

```
egrep [参数] [匹配模式] [文件]
```

> 参数：**全部和 grep 通用**（`-i -n -v -r -c -l`等），egrep = `grep -E`

## 实战示例

```
# 匹配包含1个及以上连续a
egrep 'a+' file.txt

# 匹配 linux 或者 666 （| 或逻辑）
egrep 'linux|666' file.txt

# 分组匹配 linux
egrep '(linux)' file.txt

# 匹配一个或多个连续的 linux
egrep '(linux)+' file.txt

# 匹配以 # 开头的行（^行首）
egrep '^#' file.txt

# 匹配以 linux 结尾的行（$行尾）
egrep 'linux$' file.txt

# 匹配连续出现3次ab，ababab
egrep '(ab){3}' file.txt

# 匹配 abc 或者 abd，字符集 [cd]
egrep 'ab[cd]' file.txt
```

## 嵌入式 & 面试重点

1. **基础 grep（不带 - E）属于基础正则**，`+ | ( ) { }` 需要加反斜杠转义 `\+ \| \( \)`；egrep/grep -E 不需要转义，写正则更简洁。
2. 正则元字符速记：
    - `^`：行开头
    - `$`：行结尾
    - `+`：前面字符 / 分组至少出现 1 次
    - `|`：或者
    - `()`：分组
    - `{n}`：前面分组精确重复 n 次
    - `[]`：字符集合，匹配括号里任意单个字符
3. 开发常用写法：`grep -E "pattern" file`，工程里很多人不再单独写 egrep。

## 易错坑

1. `^` 在 `[]` 内是**取反**，在外是**行首**，不要混淆。
2. 正则匹配是**按行匹配**，默认不会跨多行。
3. 分组`()`只捕获匹配内容，如需反向引用要额外注意。

# cat 命令笔记（Linux｜查看文件内容）

> 作用：在终端输出文件内容，也可用于文件合并、重定向创建文件

## 语法

```
cat [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-n`|显示行号，**空行也会编号**|
|`-b`|显示行号，**空行不编号**|
|`-s`|压缩、去除连续重复的空行，多个空行合并成一行|
|`-E`|每行末尾显示 `$`，直观看到换行符|
|`-T`|将 TAB 制表符显示为 `^I`，区分空格与 Tab|

## 实战示例

```
# 查看单个文件
cat file.txt

# 同时查看多个文件
cat file1.txt file2.txt

# 查看文件并显示全部行号（空行也编号）
cat -n file.txt

# 压缩连续空行输出
cat -s file.txt

# 重定向 > 覆盖写入（不存在则新建，原有内容直接覆盖）
cat file.txt > file1.txt

# 重定向 >> 追加写入（文件不存在新建，内容追加到末尾）
cat file.txt >> file1.txt

# 合并多个文件输出到新文件
cat file1.txt file2.txt > combinedfile.txt

# 直接新建文件，输入文本，结束按 Ctrl+D 保存
cat > file.txt
```

## 嵌入式 & 面试重点

1. `>` 覆盖；`>>` 追加，是 Shell 重定向高频考点。
2. cat 适合**小文件**，大文件不要直接 cat 刷屏，推荐 less/more 分页查看。
3. 管道常用组合：`cat xxx | grep xxx`，不过很多时候可以直接 `grep xxx file`，减少 cat 多余开销。
4. BusyBox 内置 cat，嵌入式系统必备命令。

## 易错坑

1. `cat > file.txt` 会**覆盖**原有文件，操作前确认。
2. `-s` 只是**输出时压缩空行，不会修改原文件**；想要永久修改原文件要配合重定向。
3. 不要 cat 二进制文件，会乱码并干扰终端。

# more 命令笔记（Linux｜分页查看文本）

> 作用：分页显示文本文件内容，**只能向下浏览，不能向上回退**

## 语法

```
more [options] file...
```

## 基本交互操作

- 回车：向下滚动**一行**
- 空格：向下滚动**一整页**

## 参数

表格

|参数|说明|
|---|---|
|`-num`|指定每屏展示多少行|
|`+num`|从第 num 行开始显示文件|
|`-p`|先清屏，再展示剩余文本|
|`-c`|和 - p 类似，不滚屏；先输出内容再清除旧屏幕|
|`-s`|多个连续空行压缩为一行显示|

## 实战示例

```
# 分页查看 .bashrc
more ~/.bashrc

# 清屏，每屏展示10行
more -c -10 ~/.bashrc

# 压缩连续空行分页查看
more -s ~/.bashrc

# 从第10行开始分页显示
more +10 ~/.bashrc
```

## 嵌入式 & 面试重点

1. more 是**单向分页工具**，只能往下翻，不支持向上翻页；`less` 是升级版，支持上下滚动、搜索，日常开发优先用 less。
2. 管道场景常用：`cat file.txt | more`，分页查看命令输出。
3. BusyBox 支持 more，嵌入式调试查看日志可用。

## 易错坑

1. `+num` 是**从第 num 行开始**；`-num` 是**每屏行数**，不要记混。
2. 大文件加载时 more 会预读部分内容，文件特别巨大时，打开会有短暂延迟。

# less 命令笔记（Linux｜高级分页查看文本）

> 作用：分页显示文本内容，**支持上下滚动、搜索，比 more 功能更强**

## 语法

```
less [参数] 文件
```

## 快捷键操作

- 空格键：下翻一页
- 回车键：下滚一行
- `j`：下滚一行
- `k`：上滚一行
- `b`：回翻一页（向上翻页）
- `f`：下翻一页
- `q`：退出 less
- `/word`：向下搜索`word`关键词；`n`跳到下一个匹配，`N`上一个匹配

多文件浏览子命令（less 内输入）

- `:n` 浏览**下一个**文件
- `:p` 浏览**前一个**文件

## 实战示例

```
# 查看单个文件
less ~/.bashrc

# 同时打开多个文件
less ~/.bashrc ~/.bash_history

# 将命令输出分页查看（管道）
history | less
```

## 嵌入式 & 面试重点

1. less = more 的增强版：**支持向上回翻**，自带搜索，不会一次性加载整个大文件，打开超大日志文件效率更高。
2. 工程高频用法：`cat log.txt | less`、`dmesg | less` 查看内核打印。
3. 搜索 `/关键词` 是日常定位日志最常用操作。

## 易错坑

1. 打开多个文件时，初始只加载第一个，必须输入`:n`切换，不会自动加载全部。
2. 退出一定要按`q`，忘记退出会卡在 less 界面。

# tail 命令笔记（Linux｜查看文件尾部）

> 作用：查看文件尾部内容，默认输出最后 10 行，`-f` 可实时追踪新增日志

## 语法

```
tail [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-c N`|输出文件尾部 N 个字节|
|`-n N`|输出文件尾部 N 行；`+N` 代表**从第 N 行开始一直输出到文件末尾**|
|`-f`|实时监听文件，文件新增内容会持续输出，常用于日志|

## 实战示例

```
# 默认查看最后10行
tail file.txt

# 查看最后20行
tail -n 20 file.txt

# 从第20行开始，输出到文件末尾
tail +20 file.txt

# 查看最后10个字节
tail -c 10 file.txt

# 实时跟踪日志（最常用），动态输出新增内容，Ctrl+C退出
tail -f file.txt
```

## 嵌入式 & 面试重点

1. `tail -f` 是日志调试神器，嵌入式开发经常看应用日志、内核日志：`tail -f app.log`
2. `tail +20 file.txt` 容易混淆：**+20 不是最后 20 行，而是从第 20 行开始读到结尾**，和`tail -n 20`区分开。
3. 组合使用：`tail -n 100 -f log.txt`，先展示末尾 100 行，再持续监听新增。
4. BusyBox 内置 tail，嵌入式平台日志排查必备。

## 易错坑

1. `tail -f` 会阻塞终端，必须按`Ctrl+C`退出。
2. `-c`按字节截取，中文会乱码；适合二进制文件。
3. 文件被删除 / 重命名时，部分 tail 继续读旧句柄；`tail -F`可监控文件名字重建。

# head 命令笔记（Linux｜查看文件头部）

> 作用：显示文件开头的内容，**默认输出前 10 行**

## 语法

```
head [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-n <数字>`|设置显示行数；`-n -N` 表示**排除最后 N 行，输出剩下全部**|
|`-c <数字>`|指定输出头部的字符数；`-c -N` 表示**去掉末尾 N 个字符**，输出剩余全部|

## 实战示例

```
# 默认输出前10行
head ~/.bashrc

# 输出前5行
head -n 5 ~/.bashrc

# 输出全部内容，但剔除最后6行
head -n -6 ~/.bashrc

# 输出前20个字符
head -c 20 ~/.bashrc

# 输出全部内容，剔除末尾30个字符
head -c -30 ~/.bashrc
```

## 嵌入式 & 面试重点

1. 默认 10 行，`head -n N file` 是高频用法，常和管道组合，如 `dmesg | head -n 20`。
2. 负数用法：`-n -6`，不是显示负行数，是**去掉末尾 6 行**，面试容易挖坑。
3. `-c` 按字节 / 字符截取，处理二进制、文本片段提取时会用到。
4. BusyBox 支持 head，嵌入式查看日志头部很方便。

## 易错坑

1. `-n -6` 不要理解为显示负 6 行，含义是：**不输出文件最后 6 行**。
2. `-c` 统计单位是字符，中文一个汉字占多个字节，截取中文文本容易乱码。

# tac 命令笔记（Linux｜反向输出文件）

> 作用：反向显示文件内容，**从最后一行输出到第一行**（cat 倒过来，cat 反向就是 tac）

## 语法

```
tac [参数] [文件]
```

## 常用参数

- `-b`：把分隔符放在行首（默认分隔符换行符在行尾）
- `-r`：使用正则表达式作为行分隔符
- `-s STRING`：自定义行分隔字符串，不使用默认换行符

## 实战示例

```
# 反向打印file.txt，最后一行最先输出
tac file.txt

# 管道组合，反向查看日志
cat log.txt | tac
```

## 嵌入式 & 面试重点

1. 名字记忆：`cat` 正序，`tac` 反过来拼写，输出也反转，面试经常对比考察。
2. 典型场景：日志文件时间正序追加，用 tac 直接把最新日志放最上面，替代 `tail` 后往上翻。
3. BusyBox 支持 tac，嵌入式调试日志很有用。

## 易错坑

1. tac 是**按行反转**，不是把每行里面的字符颠倒。每行内部文字顺序不变，只调换行的先后。
2. 如果文件末尾没有换行符，tac 解析会异常。

# nl 命令笔记（Linux｜添加行号）

> 作用：读取文件内容，输出时**添加行号**，和`cat -n`类似，但对空行、行号格式控制更强

## 语法

```
nl [OPTION]... [FILE]...
```

## 参数

1. `-b`：控制哪些行编号
    - `-b a`：所有行（含空行）都加行号，等价 `cat -n`
    - `-b t`：**空行不显示行号（默认行为）**
2. `-n`：行号对齐格式
    - `-n ln`：行号靠左显示
    - `-n rn`：行号靠右，不补 0
    - `-n rz`：行号靠右，**前面补 0 对齐**
3. `-w`：设置行号栏占用的字符宽度

## 实战示例

```
# 默认输出，空行不带行号
nl file.txt

# 所有行（空行也编号）
nl -b a file.txt

# 全部行编号，行号靠右补0
nl -b a -n rz file.txt

# 全部行编号，靠右补0，行号宽度3位
nl -b a -n rz -w 3 file.txt

# 空行不编号（默认效果，显式指定）
nl -b t file.txt
```

## 嵌入式 & 面试重点

1. `nl` vs `cat -n`：`cat -n`一定会给空行加行号；nl 默认空行不加，可通过 `-b` 灵活切换。
2. `-n rz` 补零对齐，打印脚本 / 代码清单时很美观，面试常考三者（ln/rn/rz）区别。
3. BusyBox 支持 nl，可用于嵌入式下查看带行号的配置文件。

## 易错坑

- 不加 `-b a` 时，空白行**不会分配行号**，这点是和 `cat -n` 最大差异。
