# chown 命令笔记（Linux 终端｜修改文件 / 目录属主、属组）

> 作用：修改文件或目录的所属用户（属主）、所属用户组（属组）

## 语法

```
chown [参数] 所属主:所属组 文件/目录
```

## 参数

表格

|参数|作用|
|---|---|
|`-R`|递归修改目录下**所有文件、子目录**的属主属组（非常常用）|
|`-c`|只在文件信息发生变更时，打印变更信息|

## 实战示例

```
# 修改file.txt属主和属组都为alvin
sudo chown alvin:alvin file.txt

# 只修改属主为alvin，属组不变
sudo chown alvin file.txt

# 只修改属组为alvin，属主不变（冒号不能省）
sudo chown :alvin file.txt

# 修改属主属组，并且打印变更信息
sudo chown -c liangxu:liangxu file.txt

# 递归修改dir目录+内部全部文件子目录的属主属组
sudo chown -R alvin:alvin dir
```

## ⚠️嵌入式 Linux 重点注意

1. BusyBox 支持 chown 基础功能，`-R`递归一般也支持；
2. **修改属主 / 属组通常需要 root 权限**，普通用户无法把文件转让给别人；
3. `-R`递归慎用！不要随便对`/`根目录执行`chown -R`，系统直接损坏。

## 面试背诵要点

chown 修改文件的属主与属组，格式 `用户:组`。只改属组写`:组名`。`-R`递归对子文件子目录批量修改。一般需要 sudo/root 权限。**chown 改所有者，chmod 改权限 rwx**，这两个命令面试必考区分。

## 易错坑

1. `chown -R` 递归操作风险极高，线上环境一定要先确认路径；
2. 冒号写法：`alvin:` 代表属主 alvin，属组改成 alvin；`:alvin`只改属组；
3. 区分 chown（属主属组） vs chmod（rwx 权限），面试高频混淆点。

# chgrp 命令笔记（Linux 终端｜修改文件 / 目录属组）

> 作用：**只修改文件或目录的所属用户组**，不修改属主；等价于 `chown :组名 文件`

## 语法

```
chgrp [参数] 目标组 文件/目录
```

## 参数

表格

|参数|作用|
|---|---|
|`-R`|递归处理目录，目录 + 内部所有文件、子目录批量修改属组|
|`-v`|显示命令执行详细过程|
|`--reference=参考文件`|把目标文件的属组设置成和参考文件完全一样|

## 实战示例

```
# 修改file.txt所属组为alvin
sudo chgrp alvin file.txt

# 修改属组，同时打印执行过程
sudo chgrp -v alvin file.txt

# 参考reffile.txt的属组，设置file.txt的属组
sudo chgrp --reference=reffile.txt file.txt

# 递归修改dir目录及其内部全部文件子目录的属组为alvin
sudo chgrp -R alvin dir
```

## ⚠️嵌入式 Linux 重点注意

1. BusyBox 一般支持 chgrp 基础功能，`-R`、`-v`大部分固件可用；
2. 修改属组通常需要 root/sudo 权限；
3. chgrp = chown 只改组的简写；生产环境更多直接用 chown，chgrp 单独用的场景偏少。

## 面试背诵要点

chgrp 专门修改文件的所属组，不改动属主。`-R`递归批量修改目录下所有内容，`--reference`可以复用另一个文件的属组。chown 可以同时改属主 + 属组，chgrp 仅改属组。

## 易错坑

1. `-R`递归操作谨慎使用，不要对根目录`/`执行；
2. 目标组必须预先存在，否则报错；
3. 区分：chown（属主 + 属组）、chgrp（仅属组）、chmod（rwx 权限）。

# chmod 命令笔记（Linux｜修改文件 / 目录 rwx 权限）

> 作用：修改文件或目录权限；**只有属主或者 root 能执行**。分**符号模式**、**数字 (八进制) 模式**两种写法。

## 语法

```
chmod [选项] 模式 文件/目录
# 三种写法
chmod [ugoa][+-=][rwx] file        # 符号模式
chmod 八进制数字 file               # 数字模式
chmod --reference=参考文件 目标文件 # 参考别的文件权限
```

## 一、符号模式 ugoa +-= rwx

### 对象

表格

|对象|含义|
|---|---|
|u|user 文件所有者|
|g|group 文件所属组|
|o|others 其他用户|
|a|all 全部用户（u+g+o）|

### 操作符

表格

|操作|说明|
|---|---|
|`+`|增加权限|
|`-`|删除权限|
|`=`|**直接设置权限，覆盖原有权限**|

### 权限位

表格

|权限|数字|说明|
|---|---|---|
|r|4|读|
|w|2|写|
|x|1|执行（目录必须有 x 才能进入访问）|

## 二、数字模式（八进制，面试重点）

权限分三段：**属主 | 属组 | 其他用户**，每段 r=4,w=2,x=1 相加。 例：`755`

- 7 = 4+2+1 → u=rwx
- 5 = 4+0+1 → g=rx
- 5 = 4+0+1 → o=rx

> 777：u=rwx,g=rwx,o=rwx（所有人读写执行，生产慎用）

## 参数

表格

|参数|作用|
|---|---|
|`-R`|递归修改目录下**所有文件、子目录**权限|

## 实战示例

```
# 所有人增加读权限
chmod a+r file.txt

# 递归当前目录所有文件，全部增加读权限
chmod -R a+r *

# 给文件所有者增加执行权限（脚本常用）
chmod u+x file.txt

# 属主、组可写；其他人去掉写权限
chmod ug+w,o-w file.txt

# 全部用户 rwx
chmod a+r,a+w,a+x file.txt
chmod 777 file.txt

# 755：属主rwx，组和其他rx
chmod 755 file.txt

# u=rw，g和o无任何权限
chmod u=rw,go= file.txt
```

## ⚠️嵌入式 Linux 重点

1. BusyBox 支持 chmod，数字模式和基础符号模式都支持；
2. **目录 x 权限意义和文件不一样**：目录没有 x，就算有 r 也无法 cd 进入；
3. `-R`递归慎用！不要直接 chmod -R 777 /，系统直接崩溃。

## 面试背诵要点

chmod 修改 rwx 权限，两种写法：符号`ugoa +-=` 和八进制数字。 r=4,w=2,x=1；三段依次是 u g o。 目录 x 代表能否进入；文件 x 代表能否执行。 755 最常见：所有者读写执行，组和其他只读执行；777 开放全部权限，不安全。 chown 改属主属组，chmod 改 rwx 权限，不要混淆。

## 易错坑

1. `=`是覆盖，不是追加；`u=rw`会直接删掉 u 原有的 x 权限；
2. 目录权限：**r 是列出目录内容，x 是 cd 进入目录，w 是增删文件**；
3. 脚本必须加 x 权限才能直接`./xxx.sh`运行；
4. 777 权限风险很高，线上尽量避免。


# find 命令笔记（Linux｜文件搜索）

> 作用：在指定路径递归搜索文件，可按**名称、权限、属主、时间、大小、文件类型**过滤，支持对搜索结果执行命令。

## 语法

```
find [搜索路径] [参数] [匹配条件]
```

## 常用参数

表格

|参数|含义|
|---|---|
|`-name`|文件名匹配，**区分大小写**；`-iname`忽略大小写|
|`-perm`|匹配权限；mode 完全匹配，`-mode`代表包含该权限即可|
|`-user`|匹配文件属主；`-nouser`匹配无属主文件|
|`-group`|匹配文件属组；`-nogroup`匹配无属组文件|
|`-mtime ±n`|文件内容修改时间；`-n`n 天内，`+n`n 天以前|
|`-atime ±n`|文件访问时间|
|`-ctime ±n`|文件权限 / 元数据修改时间|
|`-newer f1 !f2`|匹配比 f1 新、比 f2 旧的文件|
|`-type`|文件类型：`b`块设备，`d`目录，`c`字符设备，`p`管道，`l`软链接，`f`普通文件|
|`-size`|文件大小；`+50KB`大于 50KB，`-50KB`小于 50KB|
|`-prune`|忽略某个目录（搜索时跳过）|
|`-exec 命令 {} \;`|对查到的文件执行后续命令；`{}`代表 find 匹配到的文件|

## 实战示例

```
# 全盘搜索以.conf结尾文件
find / -name *.conf

# /etc目录搜索大于1k的文件
find /etc -size +1k

# /home下查找属主为liangxu的文件
find /home -user liangxu

# 当前目录查找所有普通文件
find . -type f

# 当前目录找权限664的文件，并ls列出
find . -perm 664 -exec ls -l {} \;

# 列出当前目录全部文件、目录、子文件
find .

# 当前目录搜索txt后缀，忽略大小写
find . -iname "*.txt"

# 当前目录搜索后缀不是txt的文件（!取反）
find . ! -name "*.txt"

# 当前目录7天内修改过的文件，找到直接删除
find . -mtime -7 -exec rm {} \;
```

## ⚠️嵌入式 Linux 重点

1. BusyBox 精简版 find 支持基础搜索、`-name`、`-type`、`-exec`；部分复杂参数（prune、newer）可能不支持；
2. find 是**实时遍历磁盘**，不像 locate 读数据库，搜索大目录速度慢；
3. `-exec rm {} \;`高危！**先不加 exec，确认 find 查到的文件是否正确，再执行删除**。

## 面试背诵要点

find 递归遍历目录查找文件，可以按名字、类型、大小、时间、权限、属主过滤。 `-mtime`内容修改时间；`-type f`普通文件，`-type d`目录。 `-exec {} \;`对匹配结果执行命令，`{}`占位代表找到的文件。 `!`代表取反。find 是磁盘实时检索，locate 是数据库检索。

## 易错坑

1. `-mtime -7`：**7 天以内**；`-mtime +7`：7 天之前；容易记反；
2. `-name "*.txt"` 通配符建议**加引号**，防止 shell 提前解析；
3. `-exec`结尾必须是 `{} \;`，分号不能丢；
4. 不要直接执行`find / -exec rm`，极易误删系统文件。

# which 命令笔记（Linux｜查找命令程序路径）

> 作用：在 **PATH 环境变量** 里搜索可执行命令，输出命令文件所在位置；只找能直接敲的外部命令。

## 语法

```
which [-a] filename ...
```

- `-a`：列出 PATH 中**全部匹配到的命令**，而不是只返回第一个。

## 实战示例

```
# 查看bash程序路径
which bash

# 查看ls命令路径
which ls

# 查看fdisk命令路径
which fdisk
```

## ⚠️嵌入式 & 面试重点

1. which **只会扫描 PATH 目录**，不在 PATH 里的文件找不到；
2. **内部命令（cd、exit）找不到**，因为不是独立可执行文件；
3. 和 find 区分：which 找命令；find 全盘遍历任意文件；
4. BusyBox 一般自带 which，基础功能可用。

## 面试背诵要点

which 根据 PATH 环境变量查找外部可执行命令的位置；`-a`显示所有匹配项。shell 内置命令（cd/pwd）用 which 查不到。 对比：

- which：查**命令程序**，走 PATH，速度快；
- find：全盘遍历，任意文件，速度慢。

## 易错坑

1. 找不到 cd：cd 是 shell 内置命令，不是磁盘上独立程序；
2. PATH 不同用户不一样，同一条命令，root 和普通用户 which 结果可能不同。

# whereis 命令笔记（Linux｜查找命令二进制、手册、源码）

> 作用：查找命令对应的**二进制程序、man 手册页、源代码文件**路径；不依赖 PATH，预定义系统目录库检索。

## 语法

```
whereis [options] name...
```

## 参数

表格

|参数|含义|
|---|---|
|`-b`|只查找**二进制程序**|
|`-B`|在指定目录下查找二进制程序|
|`-m`|只查找 **man 手册文件**|
|`-M`|在指定目录下查找 man 手册|
|`-s`|只查找源代码文件|
|`-S`|在指定目录下查找源码文件|

## 实战示例

```
# 查找ls的二进制 + man手册
whereis ls

# 只查ls二进制程序路径
whereis -b ls

# 只查ls的man手册位置
whereis -m ls
```

## 面试 & 嵌入式重点

1. whereis 一次性返回三类文件：**二进制程序、man 手册、源码**；而 which**只找二进制可执行文件**。
2. 它只会在系统预设目录（/bin、/sbin、/usr/bin、/usr/share/man 等）搜索，**不能自定义全盘搜索普通文件**。
3. BusyBox 精简系统里，很多时候不带 whereis。

## 对比总结（面试高频）

表格

|命令|搜索范围|查找内容|
|---|---|---|
|which|PATH 环境变量|仅可执行二进制|
|whereis|系统预设目录|二进制 + man 手册 + 源码|
|find|自定义任意路径|所有类型文件，实时磁盘遍历|

## 易错坑

1. whereis**不能用来搜索普通文档 / 用户文件**，只能检索命令相关文件；
2. 很多命令没有源码包，`-s`经常返回空。

# locate 命令笔记（Linux｜快速文件检索）

> 作用：快速查找文件 / 目录，**读取系统预建文件数据库**，不是实时遍历磁盘，所以速度远快于 find。

## 语法

```
locate [参数] [文件]
```

## 参数

表格

|参数|含义|
|---|---|
|`-i`|搜索时**忽略大小写**|

## 实战示例

```
# 查找系统内所有file.txt
locate file.txt

# 搜索路径包含/etc/sh的文件
locate /etc/sh

# 查找所有名字含whereis的文件
locate whereis

# 忽略大小写，查找指定目录下f开头文件
locate -i locate/f
```

## 面试 & 嵌入式重点

1. 底层依赖数据库（`updatedb`生成），**新创建的文件不会立刻搜到**，需要执行`updatedb`更新库。
2. 搜索速度极快，但存在延迟；find 是实时扫描磁盘，结果最新，速度慢。
3. BusyBox 一般**不带 locate**，嵌入式开发板基本不用。

## 查找系列 4 命令汇总（面试必背）

表格

|命令|检索源|查找对象|特点|
|---|---|---|---|
|which|PATH 环境变量|外部命令二进制|只找可执行程序|
|whereis|系统预设目录|二进制 + man 手册 + 源码|命令相关三类文件|
|locate|updatedb 数据库|任意文件 / 目录|速度快，有延迟|
|find|实时遍历磁盘|任意文件 / 目录|实时，可多条件过滤，支持 exec|

## 易错坑

1. 刚新建文件，locate 找不到，数据库未更新；
2. 数据库会跳过部分目录（如 /tmp），里面的文件检索不到；
3. 数据库由定时任务自动更新，也可手动`updatedb`（需要 root）。

# stat 命令笔记（Linux｜查看文件 / 文件系统元信息）

> 作用：查看文件或者文件系统的详细元数据（大小、权限、inode、时间戳等）

## 语法

```
stat [OPTION]... FILE...
```

## 参数

表格

|参数|含义|
|---|---|
|`-L`|跟随符号链接，读取链接指向真实文件信息|
|`-f`|不看文件本身，查看该文件所在**文件系统**信息|
|`-t`|简洁模式输出（一行，方便脚本解析）|

## 三大时间戳（面试高频考点）

- **atime（access time，访问时间）**：读取文件内容（cat、less、vim 打开读）就更新；只看内容。
- **mtime（modify time，修改时间）**：**文件内容被修改**时更新（vim 写入，追加内容）。
- **ctime（change time，状态改变时间）**：**文件元数据变化**时更新，如 chmod、chown，也会在内容修改时同步更新。

> 一句话区分： atime：读内容；mtime：改内容；ctime：改属性（或改内容也会触发）

## 实战示例

```
# 查看file.txt文件详细信息
stat file.txt

# 查看file.txt所在文件系统信息
stat -f file.txt

# 简洁单行输出
stat -t file.txt
```

## 嵌入式 & 面试重点

1. stat 可以拿到 inode 号，硬链接的 inode 相同；软链接 inode 不同。
2. 很多文件系统（ext4 可挂载参数`noatime`）会**关闭 atime 自动更新**，减少磁盘 IO，提升性能，所以 atime 不一定每次读文件都变。
3. BusyBox 支持 stat，嵌入式板子可用。

## 易错坑

1. ctime 不是 “创建时间”！Linux 默认没有原生创建时间（部分新文件系统 ext4/btrfs 支持 birth）；
2. 只 chmod 改权限，mtime 不变，但 ctime 会变；
3. 软链接直接 stat 默认看链接本身，加 `-L` 才会读取目标文件。
# rename 命令笔记（Linux｜批量重命名文件）

> 作用：利用正则字符串替换，批量修改文件名。⚠️注意：Linux 有两个版本 rename（Perl 版最常用，支持`s///`正则语法）

## 语法（Perl 版本）

```
rename 's/old-name/new-name/' files
```

- `s/旧串/新串/`：正则替换语法，把文件名里**旧字符串替换成新字符串**
- files：待处理的文件列表，可搭配通配符

## 通配符

- `?`：匹配**单个任意字符**
- `*`：匹配**任意多个字符**

## 参数

表格

|参数|含义|
|---|---|
|`-n`|模拟运行，**只打印效果，不实际改名**，强烈建议先测试！|
|`-v`|verbose，输出每一步改名详情|
|`-f`|强制覆盖，目标文件名存在时直接覆盖|

## 实战示例

```
# 把myfile.txt后缀改成myfile.doc
rename 's/.txt/.doc/' myfile.txt

# -n模拟：file1.txt→file01.txt、file2.txt→file02.txt，只预览不执行
rename -n 's/file/file0/' file*.txt

# -v真正执行改名，并打印操作信息
rename -v 's/file/file0/' file*.txt
```

## 面试 & 嵌入式重点

1. **版本坑**：Debian/Ubuntu 默认是 Perl 版 rename（支持`s///`正则）；CentOS/RHEL 自带简易 rename，语法不一样，不支持这种正则写法。
2. **安全习惯**：批量改名**优先加 - n 预览**，确认输出没问题再去掉 - n 执行，防止改错。
3. BusyBox 里 rename 功能极简，只支持简单替换，不支持 Perl 正则。

## 易错坑

1. 正则是**匹配文件名内字符串**，不是整体匹配；`s/A/B/`只会替换**第一个 A**；全局替换写成`s/A/B/g`。
2. 不要直接写`rename old new file`，这是另一个版本语法，容易混淆。
3. 文件名含空格时，要小心通配符匹配问题。

# asename 命令笔记（Linux｜从路径提取文件名）

> 作用：从完整路径字符串中提取**文件名 / 目录名**，常用于 Shell 脚本。配套命令：dirname（提取目录路径）

## 语法

```
basename NAME [SUFFIX]
basename OPTION... NAME...
```

## 参数

表格

|参数|含义|
|---|---|
|`-a`|一次处理**多个路径**，输出多行结果|
|`-s`|删除指定后缀|

## 实战示例

```
# 提取文件名，输出 passwd
basename /etc/passwd

# 提取目录名，自动剔除末尾/，输出 local
basename /usr/local/

# -a 一次性处理多个路径
basename -a /etc/passwd /usr/local/

# 简写方式：提取并删掉后缀.conf，输出 sysctl
basename /etc/sysctl.conf .conf

# -s 参数删除后缀，效果同上
basename -s .conf /etc/sysctl.conf
```

## 脚本 & 嵌入式重点

1. **只做字符串切割，不会访问磁盘**，路径文件不存在也可以解析。
2. 搭配`dirname`是 Shell 脚本处理文件路径的黄金组合：

```
# dirname 获取目录部分
dirname /etc/passwd   # 输出 /etc
```

3. BusyBox 支持 basename，嵌入式板子脚本里经常使用。

## 易错坑

1. 后缀匹配**必须严格完全匹配末尾字符串**；
2. basename 单纯字符串处理，不校验文件是否真实存在；
3. 路径末尾带`/`会自动忽略，`basename /usr/local/`结果等价于`basename /usr/local`。
# dirname 命令笔记（Linux｜提取路径目录部分）

> 作用：去掉路径里最后的文件名 / 目录名，**只保留目录路径**，和`basename`成对使用，Shell 脚本高频工具

## 语法

```
dirname [OPTION] NAME...
```

## 实战示例

```
# 提取文件所在目录，输出 /usr/bin
dirname /usr/bin/cat

# 提取目录的上级路径，输出 /home/liangxu
dirname /home/liangxu/commands/
```

## 脚本 & 嵌入式重点

1. **仅字符串处理，不访问磁盘**，文件 / 目录不存在也能解析路径字符串。
2. dirname + basename 经典组合，脚本里拆分全路径：

```
fullpath="/etc/sysctl.conf"
file_dir=$(dirname "$fullpath")    # /etc
file_name=$(basename "$fullpath")  # sysctl.conf
```

3. BusyBox 内置 dirname，嵌入式 Linux 脚本广泛使用。

## 易错坑

1. 路径末尾带`/`会自动忽略尾部斜杠再解析；
2. 输入纯文件名（不带路径，如`dirname test.txt`），直接输出`.`（当前目录）；
3. 输入根路径`dirname /`，输出`/`。

# chattr /lsattr 命令笔记（Linux｜文件扩展属性）

> 作用：`chattr` 修改文件**扩展属性**（ext 系列文件系统特有，区别于 chmod 权限）；`lsattr` 查看扩展属性。

## 语法

```
chattr [-RVf] +-=[aAcCdDeijsStTu] files...
```

## 参数

表格

|参数|含义|
|---|---|
|`-R`|递归处理目录下全部文件|
|`-v`|设置文件版本号|
|`-V`|显示命令执行详细过程|
|`+`|**开启**某项属性|
|`-`|**关闭**某项属性|
|`=`|指定仅保留该项属性，覆盖原有|

### 高频属性标志（面试重点）

- `i`：immutable 不可变。文件**不能修改、删除、重命名、新增写入**，root 也无法直接改；常用于保护关键配置文件。
- `a`：append only 仅追加。只能往文件末尾追加内容，不能覆盖、删除原有内容，适合日志文件。

## 实战示例

```
# 给文件加i属性，锁定不可修改
chattr +i file.txt

# 取消i属性，解锁
chattr -i file.txt

# 给文件开启a属性，仅允许追加（日志）
chattr +a file.txt

# 递归给目录内所有文件加i保护
chattr -R +i dir

# lsattr 查看扩展属性
lsattr file.txt
```

## 嵌入式 & 面试重点

1. 这是**ext2/ext3/ext4**文件系统扩展属性；xfs 部分支持，fat32 不支持。
2. `chattr +i` 很强：就算 root 也不能 rm、vim 修改，必须`chattr -i`解除。
3. `+a`适合日志，只能`>>`追加，不能`>`覆盖清空。
4. BusyBox 支持 chattr/lsattr，嵌入式开发板 ext 文件系统会用到。

## 易错坑

1. `chattr` 和 `chmod` 是两套东西：chmod 控制读写执行权限；chattr 是底层文件属性。**chmod 777 也绕不开 chattr +i 锁定**。
2. 必须 root 才能设置 i/a 属性。
3. 如果文件系统挂载时带`noattr`，chattr 会失效。

# file 命令笔记（Linux｜识别文件类型）

> 作用：探测文件真实类型，**不靠后缀名，读取文件头部魔数 (magic number)** 判断，是排查未知文件的利器。

## 语法

```
file [参数] 文件
```

## 参数

表格

|参数|说明|
|---|---|
|`-b`|只输出文件类型，**不显示文件名**|
|`-c`|详细打印命令执行解析过程（调试 magic 规则）|
|`-f`|读取一个文本文件，里面每行是待检测文件名，批量检测|
|`-L`|跟随符号链接，直接显示**链接指向目标文件**的类型|
|`-m`|指定自定义魔法数字文件|
|`-z`|尝试解析**压缩包内部**文件类型|
|`-i`|输出 MIME 类别信息|

## 实战示例

```
# 查看普通文件类型
file file.txt

# 查看目录类型
file dir

# 查看块设备
file /dev/sda

# -b：只输出类型，不带文件名
file -b file.txt

# -i：输出MIME类型
file -i file.txt

# 默认查看符号链接本身
file /dev/cdrom

# -L 跟踪软链，查看目标真实文件类型
file -L /dev/cdrom
```

## 面试 & 嵌入式重点

1. 判断原理：读取文件头部**魔数**，**不受文件名后缀影响**。比如把`elf可执行文件`改名成`xxx.txt`，`file`依旧识别为 ELF。
2. 嵌入式开发经常用来判断：镜像文件、elf 程序、设备文件、固件 bin。
3. BusyBox 精简版 file 功能有限，很多时候只支持基础识别，不支持 `-z / -i`。

## 易错坑

1. 不加 `-L` 时，对软链默认输出 `symbolic link to xxx`，而不是目标文件类型。
2. 空文件会识别为空，没有魔数就无法精准识别。


# md5sum 命令笔记（Linux｜MD5 哈希校验）

> 作用：生成、校验文件 MD5 摘要，用来检查文件**传输 / 烧录后是否损坏、篡改**，嵌入式固件、镜像分发非常常用。

## 语法

```
md5sum [OPTION]... [FILE]...
```

## 参数

表格

|参数|说明|
|---|---|
|`-b`|二进制模式读取文件|
|`-t`|文本模式读取文件|
|`-c`|读取 md5 记录文件，批量校验文件|
|`--status`|校验时**不打印输出**，只通过命令返回码判断结果（脚本专用）|

## 实战示例

```
# 生成文件md5值
md5sum file.txt

# 二进制 / 文本模式计算md5
md5sum -b file.txt
md5sum -t file.txt

# 将md5结果保存到校验文件
md5sum file.txt > file.md5

# 根据md5文件做校验
md5sum -c file.md5

# 静默校验，无输出，用echo $?查看返回码（0成功，非0失败）
md5sum -c --status file.md5
echo $?
```

## 面试 & 嵌入式重点

1. MD5 原理：对文件全部内容做哈希运算，**只要文件有 1 字节改动，MD5 值完全不同**；但 MD5 存在碰撞漏洞，**只适合完整性校验，不能用于安全加密签名**。
2. 脚本场景：`--status` 在自动化烧录、升级脚本里大量使用，适合判断固件是否烧录正确。
3. BusyBox 自带 md5sum，开发板上可直接使用。
4. 同类命令：sha256sum（更安全，现在工程推荐 sha256）。

## 易错坑

1. Windows 换行`\r\n`和 Linux`\n`不同，同一份文本在不同系统计算 md5 会不一样。
2. md5 文件里**文件名路径必须匹配**，否则校验失败。
3. 软链：md5sum 默认读取软链指向的真实文件内容，不是软链本身。

# tree 命令笔记（Linux｜树形展示目录结构）

> 作用：树形递归列出目录内容，快速看项目目录架构；**默认很多最小系统 / 开发板没有预装，需要单独安装**。

|`-t`|按文件修改时间**正序**排序|

|`-f`|每行前面输出完整相对路径|

2. 源码、工程目录查看神器，写文档、README 目录结构经常用 tree 输出。

2. `-L` 一定要写数字，`tree -L2`不行，中间要有空格 `tree -L 2`。

1. `ls -R`目录很深时输出巨多，慎用。
2. `ls`默认不会显示隐藏文件，必须`-a / -A`。
3. `ls`只是读取文件名，不读文件内容；权限不足时会提示 cannot access。

# cd & pwd 命令笔记（Linux｜目录切换与查看当前路径）

# 切换到 dir 子目录

# 输出当前工作目录完整路径
pwd

2. `cd -` 会打印切换后的路径，快速在两个目录来回切换，开发很常用。

2. 权限不足时会提示`Permission denied`，无法进入目标目录。

# cp 命令笔记（Linux｜复制文件 / 目录）

> 作用：复制文件或目录。

## 语法

```
cp [OPTION]... [-T] SOURCE DEST
cp [OPTION]... SOURCE... DIRECTORY
cp [OPTION]... -t DIRECTORY SOURCE...
```

## 参数

表格

|参数|说明|
|---|---|
|`-f`|目标存在，**直接覆盖，无提示**|
|`-i`|目标存在，交互式询问，确认后才覆盖|
|`-a`|归档复制；递归复制，保留权限、时间、软链接等全部属性（目录复制首选）|
|`-r`|递归复制目录及里面文件（不推荐保留属性）|
|`-b`|覆盖前自动备份原有目标文件|
|`-v`|verbose，打印每一步复制详情|

## 实战示例

```
# 复制文件
cp file1.txt file2.txt

# 复制目录（普通递归）
cp -r dir1 dir2

# 复制文件，存在则询问是否覆盖
cp -i file1.txt file2.txt

# 强制覆盖，不提示
cp -f file1.txt file2.txt

# 覆盖前备份旧文件
cp -b file1.txt file2.txt

# 归档复制目录，保留所有属性（工程最常用）
cp -a dir1 dir2
```

## 嵌入式 & 面试重点

1. **复制目录必须加 `-r / -a`**，不加会报错，不能直接 cp 目录。
2. `-a = -d + -R + -p`，打包、固件、配置迁移首选，保留文件权限和时间戳。
3. BusyBox 自带 cp，开发板可用。

## 易错坑

1. `cp` 默认直接覆盖（很多发行版会给 cp 设置`alias cp='cp -i'`，行为会变）。
2. 多个源文件复制时，最后参数必须是目录。
3. 软链接：`cp -r` 默认复制链接本身；`cp -a` 保留软链接。

# mv 命令笔记（Linux｜移动 / 重命名文件目录）

> 作用：①移动文件 / 目录；②重命名文件 / 目录。**同一分区 mv 只是修改文件元数据，不拷贝数据，速度极快；跨分区才会复制 + 删除源文件**。

## 语法

```
mv [OPTION]... [-T] SOURCE DEST
mv [OPTION]... SOURCE... DIRECTORY
mv [OPTION]... -t DIRECTORY SOURCE...
```

## 参数

表格

|参数|说明|
|---|---|
|`-i`|目标同名，交互式询问是否覆盖|
|`-f`|存在同名直接覆盖，**无提示**|
|`-b`|覆盖前，自动备份原有目标文件|
|`-u`|仅当源文件更新，或目标不存在时，才执行移动|

## 实战示例

```
# 将file.txt移动到dir目录内
mv file.txt /dir

# 文件重命名
mv file.txt newfile.txt

# dir2存在 → dir1移入dir2；dir2不存在 → dir1重命名为dir2
mv dir1 dir2

# 重命名，存在则询问覆盖
mv -i file1.txt file2.txt

# 重命名，强制覆盖不提示
mv -f file1.txt file2.txt

# 覆盖前自动备份旧文件
mv -b file1.txt file2.txt

# 仅源文件更新时才移动
mv -u file1.txt file2.txt

# 当前目录全部文件移动到上一级
mv * ../

# dir3内所有文件移动到dir2
mv dir3/* dir2
```

## 嵌入式 & 面试重点

1. `mv` 对目录操作**不需要加 - r**，这点和 cp 不同。
2. 同磁盘分区移动，本质修改 inode 目录项，不读写文件内容，所以大文件瞬间完成。跨分区时底层是拷贝 + 删除源文件。
3. BusyBox 内置 mv，开发板直接可用。

## 易错坑

1. 很多发行版默认别名 `alias mv='mv -i'`，直接 mv 遇到同名文件会询问；脚本里一般用`mv -f`。
2. `mv * ../` 不会移动隐藏文件（`.`开头文件）。



# rm & rmdir 命令笔记（Linux｜删除文件 / 目录）

> rm：删除文件或非空目录；rmdir：**仅删除空目录**

## rm

### 语法

```
rm [OPTION]... [FILE]...
```

### 参数

表格

|参数|说明|
|---|---|
|`-f`|强制删除，忽略不存在文件，**无任何提示**|
|`-i`|删除前逐个询问确认|
|`-r / -R`|递归删除目录及里面所有内容|
|`-v`|详细输出每一步删除操作|

### 实战示例

```
# 删除单个文件
rm file.txt

# 删除目录（必须加-r）

# 强制删除，不提示（脚本最常用）

# 删除当前目录下全部文件

# 删除多个文件，逐个询问

```

## rmdir

### 语法

```
rmdir [OPTION]... DIRECTORY...
```

### 参数

表格

|参数|说明|
|---|---|
|`-p`|递归删除整条目录链，父目录为空就一起删；目录非空则报错|
|`-v`|打印详细执行过程|

### 实战示例

```
# 删除空目录
rmdir dir

# 递归删除多级空目录
rmdir -p dir1/dir2/dir3

# 带详情输出删除空目录
rmdir -v dir
```

## 嵌入式 & 面试重点

1. **rmdir 只能删空文件夹**，目录里面有文件就报错；删除非空目录用`rm -r`。
2. `rm -rf`高危命令，**`rm -rf /`会删除根目录所有数据，绝对禁止**。
3. BusyBox 自带 rm、rmdir，开发板可用。

## 易错坑

1. `rm`删除后一般**无法恢复**，不是移入回收站，直接释放 inode。
2. `rm -rf *`不会删除`.`开头隐藏文件。
3. 别名风险：部分环境`alias rm='rm -i'`，脚本中要用`\rm -rf`绕过别名。


# mkdir 命令笔记（Linux｜创建目录）

> 作用：新建目录；不加参数时，上级目录不存在则报错，目录已存在也会提示报错。

## 语法

```
mkdir [OPTION]... DIRECTORY...
```

## 参数

表格

|参数|说明|
|---|---|
|`-p`|递归创建多级目录；路径上级不存在会自动创建，目录已存在**不会报错**|
|`-m`|创建目录同时直接指定权限|
|`-v`|打印创建详情，可视化创建过程|

## 实战示例

```
# 创建单个目录dir1
mkdir dir1

# 一次性创建多个同级目录 dir2 dir3 dir4
mkdir dir2 dir3 dir4

# 大括号展开，创建 dir5 dir6 dir7
mkdir dir{5..7}

# 递归创建多级目录（最常用 -p）
mkdir -p dir7/dir8/dir9

# 创建目录并设置权限700
mkdir -m 700 dir1/dir10

# 带详情输出，批量创建 dir11 dir12 dir13
mkdir -v dir{11..13}
```

## 嵌入式 & 面试重点

1. `-p`是工程脚本高频参数，写自动化编译、部署脚本必备；**不会因为目录已存在中断脚本**。
2. 大括号`{5..7}`属于 shell 扩展，不是 mkdir 本身功能。
3. BusyBox 自带 mkdir，开发板直接可用。

## 易错坑

1. 不带`-p`时，如果上级目录不存在，直接报错，不能一次性建多层。
2. 同名文件和目录不能共存：当前已有`dir1`文件，就无法创建 dir1 目录。


# touch 命令笔记（Linux｜创建空文件 / 修改文件时间戳）

> 作用：①文件不存在 → 创建空文件；②文件已存在 → 更新文件时间戳（访问时间、修改时间）。 注意：修改时间属性，需要文件属主或写权限。

## 语法

```
touch [OPTION]... FILE...
```

## 参数

表格

|参数|说明|
|---|---|
|`-a`|仅修改访问时间 access time|
|`-m`|仅修改修改时间 modify time|
|`-r`|参考另一个文件的时间戳，把源文件时间复制过来|
|`-c` / `--no-create`|**不创建新文件**；文件不存在直接忽略，只改已有文件时间|
|`-d`|使用字符串设置时间，如`tomorrow`、`2026-01-01`|
|`-t`|设置时间，格式 `[[CC]YY]MMDDhhmm[.ss]`|

## 实战示例

```
# 创建单个空文件（文件不存在时）
touch file.txt

# 一次性创建多个空文件
touch file1.txt file2.txt file3.txt
touch file{1..3}.txt

# 文件已存在：更新访问+修改时间为当前系统时间
touch file.txt

# 只修改访问时间
touch -a file.txt

# 只修改修改时间
touch -m file.txt

# 文件不存在时，不新建文件
touch -c nofile.txt
touch --no-create nofile.txt

# 把 ref_file 的时间戳复制给 file
touch file -r ref_file.txt

# 修改文件时间为明天
touch -d "tomorrow" file.txt

# 指定时间 2020年10月11日03:00.55
touch -t 202010110300.55 file.txt
```

## 嵌入式 & 面试重点

1. touch**不能创建目录**，只能操作文件。
2. Make 编译原理：make 通过对比文件 mtime 判断是否需要重新编译源码，`touch`常用于强制触发重新编译。
3. BusyBox 自带 touch，嵌入式开发板可用。

## 易错坑

1. 直接 touch 已存在文件，默认同时更新 atime 与 mtime。
2. `-t`参数时间格式不能乱写，年份、月日时分顺序不能颠倒
