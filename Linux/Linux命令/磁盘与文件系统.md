# du 命令笔记

`du`（disk usage）用于统计文件 / 目录占用磁盘空间大小。

## 作用

查看文件或目录的磁盘使用空间

## 语法

```
du [OPTION]... [FILE]...
du [OPTION]... --files0-from=F
```

## 常用参数

表格

|参数|功能|示例|
|---|---|---|
|`-a`|显示目录中所有文件大小（包含目录内文件，不只统计子目录）|`du -ah dir`|
|`-h`|以人类易读方式显示大小（K/M/G 单位）|`du -h dir`|
|`-s`|只显示总计，不展开内部子文件 / 子目录|`du -s dir`|
|`--max-depth=N`|限制目录递归深度；`--max-depth=0`等价于 - s，只输出总大小|`du -h --max-depth=1 dir`|
|`-d N`|GNU du 中等价于`--max-depth=N`，限制递归深度|`du -h -d 1 dir`|
|`-x`|只统计当前文件系统，不跨越到其他文件系统|`du -xh /var`|
|`-c`|最后额外输出所有指定对象的合计|`du -ch file1 file2`|
|`--exclude=PATTERN`|排除匹配指定模式的文件或目录|`du -h --exclude='*.log' dir`|
|`-L`|跟随符号链接，统计其指向的文件或目录|`du -hL link`|
|`-0`|使用 NUL 字符分隔每条输出记录|`du -0 -h dir`|
|`--apparent-size`|统计文件逻辑大小，而非磁盘块占用大小|`du --apparent-size -h sparse_file`|

> 💡提示：以上参数以 GNU du 为准；不同 Unix 系统中的 du 选项可能有所不同。实际使用时可以 `du --help` 查看本机支持的参数。

## 实战案例

```
# 列出当前目录下所有文件和目录的容量大小
du

# 以易读方式显示 dir 文件夹及其子文件夹大小
du -h dir

# 以易读方式显示 dir 文件夹内所有文件大小（包含文件+目录）
du -ah dir

# 显示文件 file.txt 所占用的磁盘空间
du file.txt

# 仅显示目录的总大小（两种写法等价）
du -s dir
du --max-depth=0 dir

# 显示指定目录总大小，并且以易读方式显示（最常用）
du -sh dir

# 查看当前目录下各个一级目录的大小，并按大小排序
du -h --max-depth=1 . | sort -h

# 查看当前目录下占用空间较大的目录和文件
du -ah . | sort -h | tail -n 20

# 查看 /var 空间占用，但不跨越其他文件系统
du -xh --max-depth=1 /var

# 统计多个文件或目录，并显示合计
du -ch file1 file2 dir

# 统计目录大小时排除日志文件
du -h --exclude='*.log' dir

# 查看稀疏文件的逻辑大小
du --apparent-size -h sparse_file
```

> 💡补充知识点

1. `sort -h` 可以识别 K、M、G 等大小单位，比普通 sort 更适合处理 du -h 的输出。
2. `du -ah . | sort -h | tail -n 20` 定位大文件，但目录大小包含子项，直接累加会重复计算。
3. `du -sh *` **不会自动包含隐藏文件**，`*` 不会匹配 `.` 开头的目录，磁盘排查需要留意。
4. 默认 du 统计**文件实际占用磁盘块大小**；`--apparent-size` 统计文件逻辑大小。稀疏文件下两者差距明显；普通文件也会受文件系统块分配粒度影响。
5. 硬链接：GNU du 默认同一份硬链接文件只统计一次，多个硬链接路径不会重复算空间。

## 面试常考：du 和 df 的区别

表格

|对比|du|df|
|---|---|---|
|主要用途|查看文件和目录占用|查看文件系统整体使用情况|
|统计对象|文件和目录树|文件系统|
|常用命令|`du -sh /var/log`|`df -h`|
|典型场景|找出哪个目录占空间|查看哪个分区快满了|

> 💡重点面试考点： 当 `df -h` 显示磁盘快满，但 du 找不到对应大文件时，优先排查**已删除但进程仍打开的文件**，以及挂载点、跨文件系统统计问题。


# df 命令笔记

`df`（disk free）用于查看文件系统整体磁盘占用、剩余空间，查看分区层面的磁盘信息。

## 作用

显示磁盘分区空间使用情况

## 语法

```
df [OPTION]... [FILE]...
```

## 常用参数

表格

|参数|功能|示例|
|---|---|---|
|`-a`|显示所有文件系统，包含块大小为 0 的虚拟文件系统|`df -a`|
|`-h`|人类易读格式展示，**1024 进制 (KiB/MiB/GiB)**|`df -h`|
|`-H`|人类易读格式展示，**1000 进制 (kB/MB/GB)**|`df -H`|
|`-i`|查看 inode 使用信息（inode 耗尽即使还有空间也无法新建文件）|`df -i`|
|`-k`|以 1024 字节为单位显示容量|`df -k`|
|`-l`|仅显示本地文件系统，不展示远程挂载|`df -l`|
|`-P`|POSIX 标准输出格式，适合脚本解析，每个文件系统占一行|`df -P`|
|`-t <类型>`|只展示指定类型的文件系统|`df -t ext4`|
|`-T`|输出中增加文件系统类型列|`df -T`|
|`-x <类型>`|排除指定类型的文件系统，不展示|`df -x tmpfs`|
|`--total`|在最后一行输出所有文件系统的汇总统计|`df -h --total`|
|`--output=字段`|自定义输出需要展示的列（GNU df 特有）|`df --output=source,size,used,avail,pcent,target`|

> 💡提示：参数以 GNU df 为准，不同 Unix 版本选项存在差异，可`df --help`查看本机支持选项。 -h 与 -H 核心区别：
> 
> - `-h`：1024 进制（操作系统标准）
> - `-H`：1000 进制（硬件厂商标准）

## 实战案例

```
# 显示磁盘分区空间使用情况
df

# 以易读方式展示磁盘空间（最常用，1024进制）
df -h

# 查看当前目录所在文件系统的空间（不是当前目录大小！）
df -h .

# 查看根目录所在文件系统的空间
df -h /

# 以1000进制显示容量
df -H

# 查看指定文件/目录所在分区的磁盘信息
df /home

# 只显示squashfs类型文件系统
df -t squashfs

# 查看inode使用情况，排查inode耗尽问题
df -i

# 列出全部文件系统（含虚拟文件系统）
df -a

# 输出并展示文件系统类型
df -T

# 只看ext4分区
df -t ext4

# 排除tmpfs内存文件系统
df -x tmpfs

# 只查看本地文件系统，易读格式
df -lh

# POSIX格式，方便脚本处理
df -P

# 自定义输出字段
df --output=source,size,used,avail,pcent,target

# 汇总所有分区统计
df -h --total

# 同时检查空间和 inode
df -h
df -i
```

## 补充知识点 & 面试考点

1. **df 统计原理** df**读取文件系统元数据**，直接获取整个文件系统的总量、已用量和可用量，**不会递归扫描每个文件**，所以执行速度很快。
2. **df 输出字段含义**

- Filesystem：文件系统 / 设备名
- Size：文件系统总容量
- Used：已使用空间
- Avail：**普通用户可使用的剩余空间**
- Use%：文件系统空间使用率
- Mounted on：挂载点

> 面试重点：Avail ≠ Size - Used ext4 等文件系统会预留一部分块给 root 特权用户，普通用户无法使用。所以 Avail 会小于`Size - Used`；同时单位换算、四舍五入也会造成数值偏差。

3. **df 与 du 数值不一致的常见原因（面试高频）**

- 文件被删除，但进程仍然持有该文件句柄，内核不会释放空间（`lsof +L1`可排查）
- 文件系统 root 预留块、文件系统元数据占用
- 稀疏文件、快照、容器挂载视图
- 挂载点覆盖：旧目录文件被新挂载遮挡，du 无法读取底层文件

> 排查已删除但仍被进程占用文件命令：
> 
> ```
> sudo lsof +L1
> ```
> 
> 查找链接计数小于 1、进程仍打开的文件，确认后重启对应进程释放磁盘空间。

4. **inode 耗尽问题** 磁盘还有剩余容量，但无法新建文件，优先执行`df -i`查看 inode 使用率。大量小文件会快速消耗 inode。

## df 和 du 对比

表格

|对比|df|du|
|---|---|---|
|主要用途|查看分区整体空闲空间|统计目录 / 文件实际占用空间|
|统计对象|读取文件系统元数据，不遍历文件|递归遍历目录树统计文件|
|速度|很快|目录文件多时较慢|
|典型场景|检查哪个分区快满|定位哪个目录占用大量空间|

## 优化磁盘爆满排查流程

第 1 步：检查分区整体空间

```
df -h
```

第 2 步：检查 inode 是否耗尽

```
df -i
```

- ✅空间耗尽：`du -xhd1 /目标路径`逐级定位大目录（`-x`不跨文件系统，`-h`易读，`-d1`仅一层目录）
- ✅inode 耗尽：查找存在海量小文件的目录

第 3 步：检查异常占用

```
sudo lsof +L1
```

额外检查挂载点、文件系统保留空间、快照等因素。


# sync 命令笔记

`sync` 用于强制把内核缓冲区（page cache）中待落盘的数据，写入磁盘，保证数据持久化。

## 作用

强制将缓冲区中修改过的内容立刻写入磁盘

## 语法

```
sync [OPTION] [FILE...]
```

## 常用参数

表格

|参数|功能|示例|
|---|---|---|
|`-d, --data`|只同步文件数据，不同步元数据（inode 等信息）|`sync -d test.txt`|
|`-f, --file-system`|同步指定文件所在的整个文件系统|`sync -f /mnt/data`|
|`--help`|打印帮助信息|`sync --help`|
|`--version`|输出版本信息|`sync --version`|

> 💡说明：不带任何参数直接执行 `sync`，会同步所有挂载文件系统的脏缓冲区。

## 实战案例

```
# 全局同步：将所有缓存数据刷入磁盘（最常用）
sync

# 只同步单个文件的数据（不含元数据）
sync -d test.txt

# 同步该文件所属的整个文件系统
sync -f /home/user/file.log

# 同步指定多个文件
sync file1.txt file2.log
```

## 补充知识点 & 面试考点

1. **Linux IO 缓冲原理** Linux 写文件时，数据先写入内存页缓存（page cache），内核后台择机刷盘，提升 IO 性能。断电前如果缓存没刷盘，数据丢失。`sync`主动触发刷脏页。
2. **sync /fsync/fdatasync 区别（面试高频）**

- `sync`：系统调用，把所有文件系统脏缓冲区排队写入磁盘，命令会等待操作完成返回。
- `fsync(fd)`：针对单个文件，**数据 + 元数据**全部刷盘。
- `fdatasync(fd)`：只刷文件内容数据，不强制刷新 inode 元数据，开销更小。

3. 使用场景

- 卸载挂载盘、U 盘前执行 sync，防止数据丢失
- 准备关机 / 断电前，手动刷缓存
- 脚本中，大量文件写入后调用 sync 保证落盘

4. 注意事项

- sync 只是**发起刷盘并等待完成**，执行耗时取决于脏数据量和磁盘速度。
- 普通用户可以执行 sync，但无法同步不属于自己的文件；root 可以同步全部。
- `umount`内部本身会自动执行类似 sync 操作，umount 成功说明缓存已落盘。

# mount 命令笔记

`mount`：将文件系统挂载到 Linux 目录树上，访问挂载点目录即可读写该设备 / 镜像里的文件。

## 作用

把文件系统挂载到目录

## 语法

```
mount [参数] [设备] [挂载点]
```

## 常用参数

表格

|参数|功能|示例|
|---|---|---|
|`-t <文件系统类型>`|指定文件系统类型，如 ext4、iso9660、tmpfs|`mount -t ext4 /dev/sdb1 /mnt/data`|
|`-o <挂载选项>`|指定挂载属性，多个选项逗号分隔|`mount -o ro,noexec /dev/sdb1 /mnt/usb`|
|`-a`|挂载 `/etc/fstab` 中符合条件的文件系统|`sudo mount -a`|
|`-B / --bind`|将目录绑定挂载到另一个目录，只是新增访问路径，不复制文件|`sudo mount --bind /data /mnt/data`|
|`-r`|只读挂载，等价于 `-o ro`|`sudo mount -r /dev/sdb1 /mnt/usb`|
|`-v`|输出详细挂载信息|`sudo mount -v /dev/sdb1 /mnt/usb`|
|`-L`|根据文件系统标签 LABEL 指定设备|`sudo mount -L DATA /mnt/data`|
|`-U`|根据文件系统 UUID 指定设备|`sudo mount -U xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/data`|

### -o 常用挂载选项

表格

|选项|说明|适用场景|
|---|---|---|
|`loop`|把普通文件虚拟成块设备（挂载 iso 镜像）|ISO 镜像挂载|
|`ro`|只读模式挂载（read-only）|保护数据、维护模式|
|`rw`|读写模式挂载（默认）|常规读写分区|
|`iocharset`|设置文件系统字符集，**仅 FAT 等少数文件系统可用**|老 Windows FAT 分区|
|`noatime`|不更新文件访问时间，减少磁盘 IO，提升性能|数据盘优化|
|`remount`|重新挂载，无需 umount，在线切换 ro/rw|系统维护|
|`defaults`|默认选项：rw,suid,dev,exec,auto,nouser,async|常规 ext4 分区|
|`nosuid`|禁止 setuid/setgid 权限生效，安全加固|临时盘、外接 U 盘|
|`nodev`|不识别该文件系统上的设备文件|安全加固|
|`noexec`|禁止直接执行该文件系统上的程序|临时目录，**注意：不能完全阻止解释器执行脚本**|
|`nofail`|设备挂载失败不阻断系统开机|非关键数据盘|
|`sync`|同步写，写操作直接落盘，保证一致性，性能较差|对数据安全极高场景|
|`async`|异步写，写入 page cache 后台刷盘，默认行为|绝大多数场景|

## 实战案例

```
# 查看当前所有挂载信息
mount

# 更直观查看挂载层级、来源、文件系统类型（推荐运维使用）
findmnt
# 查询指定目录所属挂载点
findmnt /mnt/data

# 查看磁盘分区、文件系统类型、UUID
lsblk -f

# 只查看tmpfs类型挂载
mount -t tmpfs

# 查看磁盘块设备，寻找U盘分区
sudo fdisk -l

# 将U盘分区/dev/sdb1挂载到/mnt/udisk（注意：/dev/sdb是整块磁盘，sdb1才是分区）
sudo mount /dev/sdb1 /mnt/udisk

# 只读方式挂载U盘
sudo mount -o ro /dev/sdb1 /mnt/udisk

# 挂载ISO镜像（推荐加ro只读；现代Linux可省略loop）
sudo mkdir -p /mnt/iso
sudo mount -o loop,ro /home/user/mydisk.iso /mnt/iso
ls /mnt/iso
sudo umount /mnt/iso

# 绑定挂载目录：将/data映射到/mnt/data，修改任意一处文件两边同步变化
sudo mkdir -p /mnt/data
sudo mount --bind /data /mnt/data
findmnt /mnt/data
sudo umount /mnt/data

# 在线重新挂载切换读写（常用于单用户模式根分区）
sudo mount -o remount,rw /
# 注意：文件系统损坏、内核强制只读时该命令会失败，不是万能修复命令

# 安全加固挂载示例：nosuid,nodev,noexec限制权限与执行
sudo mount -o nosuid,nodev,noexec /dev/sdb1 /mnt/data
```

## 配套命令 umount（卸载）

```
# 通过挂载点卸载（推荐写法）
sudo umount /mnt/udisk

# 通过设备名卸载
sudo umount /dev/sdb1
```

### 卸载报错 target is busy 排错

> 不要直接强制卸载，优先排查占用进程

```
# 查看挂载点占用进程（优先使用，速度更快）
sudo fuser -vm /mnt/udisk

# 递归扫描目录内打开文件，目录很大时速度慢
sudo lsof +D /mnt/udisk
```

排查思路：退出挂载点目录的终端、关闭打开的文件，结束占用进程后再执行 umount。

## /etc/fstab 开机自动挂载

### 6 个字段定义

表格

|序号|字段|含义|
|---|---|---|
|1|设备来源|设备名 / LABEL / UUID，**推荐 UUID**，避免设备名漂移|
|2|挂载点|已存在目录|
|3|文件系统类型|ext4 /tmpfs/iso9660 等|
|4|挂载选项|逗号分隔，defaults、nosuid、nodev、noexec、nofail 等|
|5|dump 备份标记|0 = 不 dump 备份，1 开启备份（一般填 0）|
|6|fsck 自检顺序|0 = 不自检；根分区填 1，其他数据盘填 2|

示例配置：

```
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /data ext4 defaults,nofail 0 2
```

> 修改前**备份 /etc/fstab**，写完配置测试：

```
sudo mount -a
findmnt /data
```

> 注意：`mount -a`成功不等于开机挂载一定正常，网络文件系统、特殊根文件系统仍存在风险。

## 关键概念修正

1. 挂载点**要求目录已存在，不强制为空目录**；挂载后原有目录内容会被遮挡，卸载恢复。实操建议使用空目录避免混淆。
2. U 盘设备区分：`/dev/sdb`是整块磁盘，`/dev/sdb1`是磁盘上第一个分区，挂载**分区**而不是整块磁盘。先用`lsblk -f`确认。
3. `mount -o remount,rw /` 仅适用于根分区被内核设为只读的场景；文件系统损坏时无法生效，不是通用修复命令。

## 运维命令速查表

表格

|需求|命令|
|---|---|
|查看设备、分区 UUID|lsblk -f|
|查看挂载树、挂载属性|findmnt|
|临时挂载文件系统|mount|
|挂载 ISO 镜像|mount -o loop,ro image.iso /mnt/iso|
|目录绑定挂载|mount --bind /data /mnt/data|
|查看开机挂载配置|cat /etc/fstab|
|测试 fstab 配置|mount -a|
|卸载文件系统|umount /mnt/data|
|排查挂载点进程占用|fuser -vm /mnt/data|

## 面试要点总结

1. 绑定挂载：只是目录的另一个访问入口，**不复制数据**，一处修改两边同步；只读绑定挂载需要 remount。
2. nosuid/nodev/noexec：外接存储、临时目录安全加固三件套，限制权限、设备文件、程序执行。
3. fstab 推荐 UUID：防止磁盘顺序变化，设备名`/dev/sdX`容易漂移。
4. sync/async：sync 同步写保证数据安全，性能差；async 异步写是默认，依靠 page cache 提升 IO。
5. 卸载 target busy 优先排查进程，不要直接强制卸载。

# umount 命令笔记

`umount`：卸载文件系统，断开设备 / 镜像与目录树的关联；正常卸载时内核会协调缓存刷回，完成文件系统清理工作。

## 作用

卸载文件系统

## 语法

```
umount [参数] <设备名 | 挂载点>
```

> 两种写法二选一：传入**设备路径**，或者传入**挂载点目录**，优先推荐挂载点写法。

## 常用参数

表格

|参数|功能|示例|
|---|---|---|
|`-v`|verbose，输出详细卸载信息|`sudo umount -v /mnt/usb`|
|`-l`|lazy 延迟卸载：立即从目录树解绑，文件句柄全部释放后后台完成真正卸载|`sudo umount -l /mnt/usb`|
|`-f`|强制卸载，多用于失联 NFS 网络文件系统；**本地磁盘慎用，极易丢数据**|`sudo umount -f /mnt/nfs`|
|`-r`|卸载失败时，尝试将文件系统重新挂载为**只读**，不是修复文件系统|`sudo umount -r /mnt/data`|
|`-a`|卸载所有符合条件的文件系统，读取系统挂载信息`/etc/mtab`|`sudo umount -a`|
|`-R`|递归卸载目录下全部子挂载点；执行前务必检查挂载层级，防止误卸载|`sudo umount -R /mnt/data`|
|`-i`|不调用外部卸载辅助程序，直接通过系统调用卸载|`sudo umount -i /mnt/data`|
|`-n`|不更新`/etc/mtab`挂载记录，行为随系统版本略有差异|`sudo umount -n /mnt/data`|

## 实战案例

```
# 通过设备名卸载（-v输出详情）
sudo umount -v /dev/sdb1

# 通过挂载点卸载（推荐优先使用挂载点写法）
sudo umount -v /media/liangxu/ALVIN/

# 递归卸载/mnt/data及其下面所有子挂载
findmnt -R /mnt/data       # 先查看挂载层级，确认范围
sudo umount -R /mnt/data

# Lazy延迟卸载（target is busy应急方案，不作为首选）
sudo umount -l /mnt/udisk

# NFS网络盘失联，强制卸载
sudo umount -f /mnt/nfs

# 卸载失败自动切只读
sudo umount -r /mnt/data
```

### 案例 1：安全卸载 U 盘标准流程

```
#1. 确认挂载关系
findmnt /mnt/udisk
#2. 检查是否有进程占用
sudo fuser -vm /mnt/udisk
#3. 文件复制完成，请求缓存同步（可选，不能替代umount）
sync
#4. 正常卸载
sudo umount /mnt/udisk
#5. 校验：无输出代表卸载成功
findmnt /mnt/udisk
```

### 案例 2：target is busy 挂载点被占用排错流程

```
# 查看目录下所有挂载，排查子挂载
findmnt -R /mnt/udisk
# 查看占用挂载点的进程
sudo fuser -vm /mnt/udisk
# 最常见原因：终端当前目录在挂载点内，先退出
cd ~
# 尝试正常卸载
sudo umount /mnt/udisk
```

> 排查顺序：退出终端目录 → 关闭占用文件的程序 → 正常 umount；不要上来就 kill 进程或`umount -f`。

## 面试对比表

表格

|对比项|umount 普通卸载|umount -l|umount -f|
|---|---|---|---|
|主要行为|正常卸载文件系统|立即从目录树分离挂载点，资源延后清理|请求强制卸载|
|进程仍占用时|直接报错失败|目录树看不见挂载点，但文件句柄仍可读写|行为依赖文件系统类型|
|典型用途|日常卸载 U 盘、本地磁盘|无法停进程场景下的应急处理|失联网络文件系统（NFS）|
|推荐程度|✅首选|⚠️谨慎使用|⚠️谨慎使用|

## ⚠️关键细节修正（面试高频坑）

1. **卸载成功 ≠ 硬件层面绝对落盘** 正常 umount 会将 OS 页面缓存刷入文件系统，但无法保证磁盘硬件缓存、固件缓存写入；极端断电场景依然存在风险。重要数据先确认拷贝完成，再卸载。

> sync 只是请求同步，**不能替代 umount**。

2. **`umount -l`不是 target busy 的首选方案** lazy 卸载只是把挂载点从目录树隐藏，**不会主动关闭打开的文件**，底层文件句柄还在读写。遇到挂载点占用优先排查进程，`-l`仅作应急。
3. **`umount -r`不会修复文件系统** 仅在卸载失败时尝试 remount 为只读模式，不执行 fsck 文件系统修复，且不一定成功。
4. **根文件系统卸载说明** 正在运行的 Linux 系统，**通常无法直接卸载正在使用的根文件系统**；但在 initramfs 维护环境、切换根文件系统场景下，是可以执行卸载操作的。

## 面试要点总结

1. `-R`递归卸载：一次性卸载父目录及其全部子挂载，**执行前必须 findmnt 检查挂载树**，防止误删。
2. target busy 优先排查：终端工作目录、打开文件、子挂载，不要直接使用强制卸载。
3. `-l`延迟卸载只是隐藏挂载入口，不会关闭文件句柄；`-f`强制卸载**本地磁盘严禁随便使用**，大概率损坏文件系统。
4. 优先用挂载点执行 umount，可读性更好。

# dd 命令笔记

`dd`：拷贝及转换文件，底层按块操作，常用于磁盘读写、镜像备份、生成测试文件；**操作块设备风险极高，if/of 写反会直接清空磁盘**。

## 作用

拷贝及转换文件

## 语法

```
dd if=源文件 of=目标文件 [其他参数]
```

## 核心参数

表格

|参数|含义|
|---|---|
|`if=文件名`|input file，输入源文件，默认标准输入|
|`of=文件名`|output file，输出目标文件，默认标准输出|
|`ibs=bytes`|一次读取的块大小（读块）|
|`obs=bytes`|一次写入的块大小（写块）|
|`bs=bytes`|同时设置 ibs 和 obs（读写块大小，最常用）|
|`cbs=bytes`|转换缓冲区大小，conv 行转换时使用|
|`skip=N`|从**输入**文件开头跳过 N 个块后开始读取|
|`seek=N`|在**输出**文件开头跳过 N 个块后开始写入|
|`count=N`|只拷贝 N 个输入块（块大小由 bs 决定）|
|`iflag=FLAG`|设置输入端特殊行为|
|`oflag=FLAG`|设置输出端特殊行为|
|`conv=关键字`|文件转换选项，多关键字逗号分隔|
|`status=progress`|实时打印拷贝进度（GNU dd）|

### 常用 iflag /oflag

表格

|参数|功能|
|---|---|
|`iflag=fullblock`|count=N 按完整输入块计数，适合管道短读场景|
|`oflag=direct`|绕过 OS 页缓存，需要缓冲区对齐，不一定提速|
|`oflag=append`|追加写入输出文件，不可随意和 seek 组合|

### conv 常用关键字

表格

|conv 选项|功能|
|---|---|
|`ascii`|ebcdic → ascii|
|`ebcdic`|ascii → ebcdic|
|`ibm`|ascii → alternate ebcdic|
|`block`|行转为 cbs 定长，不足补空格|
|`unblock`|cbs 定长行，去除末尾空格|
|`lcase`|大写转小写|
|`ucase`|小写转大写|
|`swab`|交换每一对字节（大小端转换）|
|`noerror`|读取出错继续执行（磁盘坏道备份）|
|`sync`|输入不足 ibs 块大小时补 NUL；坏盘场景维持块对齐，**不能恢复坏扇区原始数据**|
|`notrunc`|不截断已有输出文件，但仍从指定位置写入，**不是追加写入，仍可能覆盖内容**|
|`fsync`|命令结束前同步输出数据 + 元数据到存储|
|`fdatasync`|命令结束前仅同步输出文件数据|

## 实战案例

```
# 生成约500MiB零填充测试文件（推荐写法，bs不宜过大）
dd if=/dev/zero of=testfile bs=1M count=500 status=progress

# 拷贝文件前50字节
dd if=file2.txt of=dfile2.txt bs=50 count=1

# 文件小写全部转为大写输出
dd if=file3.txt of=dfile3.txt conv=ucase

# 标准输入转大写，Ctrl+D结束输入
dd conv=ucase

# 1. 生成100MiB零填充文件
dd if=/dev/zero of=testfile bs=1M count=100 status=progress

# 2. 截取源文件：跳过前1MiB，复制后续10MiB
dd if=input.img of=part.img bs=1M skip=1 count=10 status=progress

# 3. 磁盘顺序读性能测试（仅读，不写；替换/dev/sdX，谨慎执行）
sudo dd if=/dev/sdX of=/dev/null bs=4M count=256 status=progress

# 4. 安全写入镜像到磁盘，结束前刷数据+元数据
sudo dd if=disk.img of=/dev/sdX bs=4M status=progress conv=fsync

# 5. 全盘备份镜像
dd if=/dev/sdb of=/root/sdb.img bs=4M status=progress conv=fsync

# 6. 镜像恢复到磁盘 ⚠️高危！核对if/of，目标盘原有数据全部覆盖
dd if=/root/sdb.img of=/dev/sdb bs=4M status=progress conv=fsync

# 7. 生成随机数据测试文件
dd if=/dev/urandom of=randfile bs=1M count=10

# 8. 坏盘备份：遇到坏扇区继续复制，补齐块维持对齐
dd if=/dev/sdb of=/root/sdb_back.img bs=4M conv=noerror,sync status=progress
```

## ⚠️ 重点风险与修正细节（面试高频坑）

1. **if/of 顺序致命**：if 是源，of 是目标，写反直接覆盖磁盘数据，不可逆。块设备操作前反复核对。
2. `conv=notrunc`：**不是追加写入**，只是不截断原有文件，在 seek 指定位置写入，会覆盖对应位置内容；追加优先使用`oflag=append`。
3. `conv=sync`补齐单位是`ibs`；`conv=noerror,sync`坏盘备份只能维持镜像块对齐，**无法恢复坏扇区里丢失的数据**。故障磁盘数据恢复优先用`ddrescue`，支持断点续扫、优先读取健康扇区。
4. 大 bs 风险：`bs=500M`会一次性申请大量内存；推荐小一点的块如`bs=1M`做测试文件。**bs 越大不一定越快**，性能受存储介质、缓存影响，4M 是通用起点，不是万能最优值。
5. 特殊设备文件说明
    - `/dev/zero`：持续输出 0 字节；
    - `/dev/urandom`：内核密码伪随机流，日常随机测试首选；
    - `/dev/random`：现代 Linux 行为已改动，不要简单记为 “阻塞真随机”。
6. 整盘镜像注意事项
    - 源盘与目标盘容量必须确认，目标盘原有分区数据会被覆盖；
    - 源盘挂载使用中直接 dd，会得到不一致的文件系统镜像；尽量卸载或快照后备份；
    - 镜像恢复完成 ≠ 文件系统完好、磁盘可直接启动。
7. `conv=fsync`：命令结束前请求刷写数据 + 元数据，但**不能替代硬件断电保护，不能保证硬件无故障**。

## 参数速记表

表格

|参数|一句话记忆|
|---|---|
|if=|输入源|
|of=|输出目标|
|bs=|同时设置输入输出块大小|
|count=|复制多少个输入块|
|skip=|跳过输入前面若干块|
|seek=|跳过输出前面若干块|
|conv=noerror,sync|读取出错继续，补齐输入块维持对齐|
|conv=notrunc|不截断已有输出文件，不代表追加|
|conv=fsync|结束前同步输出数据及元数据|
|status=progress|实时显示拷贝进度|
|iflag=fullblock|管道场景，按完整输入块计数|

## 面试要点总结

1. dd 是原始字节流复制，不感知文件系统，直接按底层字节拷贝。
2. skip 作用于输入、seek 作用于输出，不要混淆。
3. 坏盘备份组合`conv=noerror,sync`；专业数据恢复优先 ddrescue。
4. `iflag=fullblock`解决管道场景短读导致 count 计数不准。
5. `conv=fsync`保证 dd 退出前数据落盘，提升镜像写入可靠性。
6. 块设备操作最高优先级：核对 if、of，防止写反。

# tar 命令笔记

`tar`：打包 / 解包工具，可结合 gzip、bzip2、xz 做压缩；**打包≠压缩**，tar 本身只做文件归档，压缩是调用外部压缩算法。

## 作用

打包、解包文件，支持联合 gzip/bzip2/xz 压缩。

## 语法

```
tar [主操作参数] [可选参数] -f 归档文件 [文件/目录]
```

> `-f`后**必须紧跟归档文件名**；GNU tar 中参数顺序灵活，推荐写在选项组合末尾，可读性更好。

## 核心参数

### 主操作（一次只能选 1 个）

表格

|参数|含义|
|---|---|
|`-c`|create，新建打包归档文件|
|`-x`|extract，解压 / 解包文件；搭配 `-C` 指定解压目录|
|`-t`|list，查看归档包内文件列表，不解压|

### 压缩算法参数

表格

|参数|含义|后缀|特点|
|---|---|---|---|
|`-z`|gzip 压缩 / 解压|`.tar.gz`|速度快，压缩率一般，最常用|
|`-j`|bzip2 压缩 / 解压|`.tar.bz2`|压缩率比 gzip 高，更耗 CPU|
|`-J`|xz 压缩 / 解压|`.tar.xz`|压缩率最高，耗时最长|

### 基础辅助参数

表格

|参数|含义|
|---|---|
|`-f`|指定归档文件，其后紧跟归档文件名|
|`-v`|verbose，显示操作过程，打印文件|
|`-C dir`|打包：先切换到 dir 目录再打包；解压：解压文件到 dir 目录|
|`-p`|解包时保留文件权限；归档时 tar 默认记录权限元数据，恢复权限取决于运行身份|
|`-P`|--absolute-names，保留绝对路径；解压风险高，归档内`..`或绝对路径可能覆盖外部文件，日常打包不推荐|
|`--exclude`|打包时排除指定文件 / 目录，建议写在待归档路径之前|

### 运维高频补充参数

表格

|参数|作用|示例|
|---|---|---|
|`-r`|向**未压缩 tar 包**追加文件（压缩包不可追加）|`tar -rvf files.tar new.txt`|
|`-u`|追加比归档内更新的文件|`tar -uvf files.tar data/`|
|`-k`|解包时**不覆盖已有文件**|`tar -xkvf files.tar`|
|`-O`|将文件输出到标准输出，不解写到磁盘|`tar -xOf files.tar config.txt`|
|`-m`|解包不恢复文件修改时间|`tar -xmvf files.tar`|
|`--strip-components=N`|解压去掉前面 N 层目录（最常用 N=1）|`tar -xvf app.tar -C /opt --strip-components=1`|
|`--numeric-owner`|使用数字 UID/GID 记录所有者，备份迁移场景||
|`--checkpoint`|每处理指定数量文件打印进度|`tar -cvf backup.tar data/ --checkpoint=1000`|

## 实战案例

```
# 1. 仅打包（不压缩），显示过程
tar -cvf files.tar *.txt

# 2. 打包 + gzip压缩（最常用）
tar -zcvf files.tar.gz *.txt

# 3. 查看压缩包里面的文件，不解压
tar -tf files.tar.gz

# 4. 解压tar.gz到当前目录（推荐显式写-z，兼容性更强）
tar -zxvf files.tar.gz

# 5. 解压tar.gz到指定目录dir
tar -zxvf files.tar.gz -C dir

# 6. bzip2打包压缩
tar -jcvf files.tar.bz2 *.txt
# bzip2解压
tar -jxvf files.tar.bz2 -C dir

# 7. xz打包压缩
tar -Jcvf files.tar.xz *.txt

# 8. 打包时排除目录，exclude放在路径前（推荐写法）
tar -zcvf backup.tar.gz --exclude='./data/tmp' ./data

# 9. 切换目录打包，归档只保存相对路径
tar -czvf backup.tar.gz -C /home user

#10. 解包，去掉第一层目录
tar -xvf app.tar -C /opt --strip-components=1

#11. 只提取归档中单个文件，不解写到磁盘
tar -xOf backup.tar app/config.txt

#12. 校验归档是否可读（遍历包内容）
tar -tzf backup.tar.gz > /dev/null

#13. 解压保留权限，使用sudo
sudo tar -xzvpf home.tar.gz -C /restore
```

## ⚠️ 面试高频易错细节修正

1. **`-f`不是强制写最后，只是习惯**`tar -cvf files.tar *.txt` 和 `tar -f files.tar -cv *.txt` GNU tar 都支持；核心要求：**`-f`后面紧跟归档文件名**，不要把文件名当成普通参数。
2. 自动识别压缩格式**存在版本差异** 新版 GNU tar `tar -xvf files.tar.gz` 可自动识别，但跨平台、老环境容易失效。面试 / 生产建议显式指定`-z/-j/-J`。
3. `-P`不是自动覆盖文件`-P`保留归档内绝对路径；风险：解压来源不明包时，归档内`/etc/passwd`或者`../`逃逸路径，会覆盖目标系统文件。GNU tar 打包时默认会剔除路径开头`/`。
4. `-p`作用时机：**解包阶段恢复权限** 打包时 tar 默认记录权限；解包时加`-p`才尝试恢复权限；完整系统备份还需要`--same-owner`、`--acls`、`--xattrs`等处理属主、ACL、扩展属性。
5. `--exclude`位置建议放在待归档路径前 避免路径匹配异常：`tar -zcvf xxx.tar.gz --exclude='tmp' data/`。

## tar 与压缩工具区分

表格

|工具|主要作用|常见用途|
|---|---|---|
|tar|归档多个文件和目录|服务器备份、批量打包|
|gzip|压缩单个数据流|`.tar.gz`|
|bzip2|压缩数据流|`.tar.bz2`|
|xz|高压缩率数据流压缩|`.tar.xz`|
|zip|归档 + 压缩一体|跨 Windows/Linux 交换文件|

> `.tar.gz`：tar 先归档 → gzip 压缩；zip 一步完成归档 + 压缩。

## 参数速记表

表格

## 推荐背诵 10 条命令

# 1. 创建 tar 归档

# 2. 创建 gzip 压缩归档

# 3. 创建 xz 压缩归档

# 4. 查看归档内容

# 5. 查看压缩归档内容

## 面试要点总结

1. tar = 归档工具，**打包不等于压缩**，压缩是外部程序实现。
2. `-f`核心：后面紧跟归档文件名，参数顺序 GNU tar 比较灵活。
3. `--strip-components=1`高频场景：解压源码包，消除多余顶层目录。
4. `-p`仅在解包时恢复权限；备份迁移还要考虑属主、ACL 扩展属性。
5. 来源不明压缩包，**先用 tar -tf 预览内容**，防止路径逃逸覆盖系统文件。

# zip /unzip 命令笔记

`zip`：**归档 + 压缩一体**工具，跨平台（Linux ↔ Windows）；`unzip`用于解压 zip 压缩包。

> 和 tar 区分：tar 是打包 + 外部压缩；zip 本身同时完成归档 + 压缩，Windows 原生支持 zip 格式。

## 作用

zip：创建 zip 压缩包；unzip：查看、校验、解压 zip 包。

## 核心参数

### zip（压缩命令）

表格

|参数|含义|
|---|---|
|`-r`|recursive，递归处理目录，包含子目录所有文件；压缩目录建议固定带上|
|`-v`|verbose，显示压缩执行过程、压缩率|
|`-d`|delete，删除压缩包内指定文件|
|`-u`|update，仅添加包内不存在文件，**或**更新比归档内版本更新的文件，不会无条件替换|
|`-q`|静默模式，不输出日志|
|`-0~9`|压缩等级，0 仅打包不压缩，9 最高压缩率（更耗 CPU，默认 6）|
|`-e`|创建加密 ZIP，交互式输入密码；传统 zip 加密强度有限，敏感数据不推荐|
|`-j`|不保存原有目录路径，仅保存文件名|
|`-m`|压缩成功后删除原文件，使用前务必确认备份|
|`-x`|压缩时排除匹配文件|
|`-F / -FF`|尝试修复损坏 zip，操作前建议备份原压缩包|

### unzip（解压命令）

表格

|参数|含义|
|---|---|
|`-l`|list，列出压缩包里文件，**不解压**|
|`-v`|列出文件，额外显示压缩比率、文件大小信息|
|`-t`|test，读取归档并校验 CRC 完整性，可发现损坏，但**不能修复文件，也无法保证业务内容正确性**|
|`-d <目录>`|指定解压目标目录|
|`-q`|静默解压，不打印信息|
|`-o`|解压**直接覆盖**已有文件，不弹窗询问|
|`-n`|解压**不覆盖**已有文件，跳过同名文件|
|`-j`|解压丢弃归档内目录层级，全部提取到目标目录|
|`-p`|将文件内容输出到标准输出，不写入磁盘，适合查看文本文件|
|`-x`|解压时排除指定文件|
|`-a`|文本文件换行符转换（Windows↔Linux）|
|`-O`|指定文件名编码，**仅部分 unzip 版本支持**，用来尝试解决 Windows 压缩包中文乱码|

## 实战案例

```
# zip压缩
# 1. 压缩多个文件
zip files.zip a.txt b.txt

# 2. 递归压缩整个目录（目录压缩推荐固定加 -r）
zip -r dir.zip dir/

# 3. 最高压缩等级压缩目录
zip -r -9 dir.zip dir/

# 4. 更新压缩包：仅新增/更新更新时间更新的文件
zip -u files.zip newfile.txt

# 普通zip命令也可添加/覆盖包内同名文件
zip files.zip newfile.txt

# 5. 删除压缩包内指定文件
zip -d files.zip newfile.txt

# 6. 加密压缩（交互输入密码）
zip -e secret.zip a.txt

# 7. 压缩，不保留目录结构
zip -j files.zip dir/a.txt

# 8. 压缩成功后删除原文件
zip -m files.zip a.txt

# 9. 压缩目录，排除日志和临时目录
zip -r backup.zip data/ -x '*.log' 'data/tmp/*'

# unzip解压、查看、校验
# 1. 查看包内文件列表（不解压）
unzip -l files.zip

# 2. 查看包详情，附带压缩率
unzip -v files.zip

# 3. 校验zip包CRC完整性（只校验，不解压）
unzip -t files.zip

# 4. 解压到当前目录
unzip files.zip

# 5. 解压到指定目录udir
unzip files.zip -d udir/

# 6. 解压，直接覆盖已有文件
unzip -o files.zip -d udir/

# 7. 解压，跳过同名文件，不覆盖
unzip -n files.zip -d udir/

# 8. 解压丢弃原有目录结构，全部放到目标文件夹
unzip -j files.zip -d output/

# 9. 只打印归档内config.txt内容，不解写到磁盘
unzip -p files.zip config.txt

# 10. 解压包，排除所有log文件
unzip files.zip -x '*.log'

# 11. 单独提取归档中指定文件
unzip files.zip app/config.txt
```

## ⚠️ 面试 & 实操易错细节修正

1. **`zip`不带 `-r`** 不会递归读取目录内部文件；不一定只生成空目录条目。**压缩目录固定使用`-r`**，是工程上的好习惯。
2. `zip -u`不是无条件替换 只会新增不存在文件，或者源文件 mtime 新于归档内文件才更新；普通`zip xxx.zip file`也可以新增 / 覆盖包内同名条目。
3. 中文文件名编码坑`unzip -O GBK`**不是所有 Info-ZIP unzip 版本都支持**。Windows 生成 zip 中文乱码成因复杂：GBK、UTF-8 标记、压缩软件差异。遇到乱码优先查看本机 unzip 版本帮助文档。
4. `unzip -t`仅 CRC 校验 能检测压缩包损坏，但**不能修复损坏数据，不能验证业务内容是否正确可信**。

## 安全提醒

1. 处理来源不明压缩包，**先 unzip -l 预览内容**，不要直接 root 解压。
2. 警惕压缩包路径穿越、炸弹文件（解压后体积暴涨，打满磁盘）。
3. `unzip -o`强制覆盖，批量脚本使用前确认目标目录。
4. `zip -e`传统加密安全性偏弱，高敏感数据不建议使用。
5. `zip -m`成功压缩后删除源文件，操作前做好备份。

# gzip /gunzip 命令笔记

`gzip`：**只压缩单个文件**，不能直接打包目录；`gunzip`是 gzip 套件提供的解压入口，功能等价于`gzip -d`，用于解压`.gz`文件。

> 重点区分：`gzip`只能压缩文件；想要压缩目录，必须先用 tar 打包，再交给 gzip 压缩，也就是`tar.gz`。

## 作用

gzip：压缩文件；gunzip：解压 gz 压缩包。

## 语法

```
gzip [参数] 文件
gunzip [参数] 压缩包
```

## 核心参数

表格

|参数|含义|
|---|---|
|`-d`|decompress，解压，功能等价 gunzip|
|`-k`|keep，**保留原文件**（默认压缩后删除原文件）|
|`-l`|list，列出 gz 压缩包信息：原始大小、压缩后大小、压缩率；大文件 / 拼接流场景原始大小可能不准|
|`-r`|recursive，递归目录：仅递归处理目录内普通文件，逐个生成独立`.gz`，**不会合并成单个归档包**；不处理符号链接、特殊文件|
|`-v`|verbose，显示执行过程、压缩率|
|`-t`|test，校验压缩包数据完整性，检测是否损坏，不解压|
|`-1 ~ -9`|压缩等级，-1 最快压缩率低；-9 最慢、压缩率最高；默认 - 6|
|`-c`|将压缩 / 解压结果输出到标准输出，**不改动原始文件**，管道高频参数|
|`-f`|force，强制操作，覆盖已有输出文件，支持压缩链接文件|
|`-n`|压缩时不保存原文件名、时间戳元数据|
|`-N`|解压时尝试恢复压缩包内记录的原文件名与时间戳|
|`-S`|指定自定义压缩后缀|

## 实战案例

```
# gzip 压缩
# 1. 压缩文件，默认删除原文件
gzip file.txt

# 2. 压缩文件，保留原文件
gzip -k file.txt

# 3. 标准输出重定向压缩（保留原文件，等价gzip -k）
gzip -c file.txt > file.txt.gz

# 4. 递归批量压缩目录内普通文件（⚠️不会生成单个归档，每个文件独立gz）
gzip -r dir

# 5. 最高压缩等级压缩
gzip -9k file.txt

# 解压
# 1. gzip方式解压
gzip -d file.txt.gz

# 2. gunzip解压入口，等价gzip -d
gunzip file.txt.gz

# 3. 解压并保留压缩包
gzip -dk file.txt.gz

# 4. 解压输出到标准输出，不落地，适合管道过滤
gzip -dc file.txt.gz

# 5. 递归解压目录下所有gz文件
gzip -dr dir
gunzip -r dir

# 6. 校验压缩包是否损坏
gzip -t file.txt.gz
gunzip -t file.txt.gz

# 管道组合实战
# 直接将命令输出压缩保存
dmesg | gzip -c > dmesg.txt.gz
# 不解压文件，直接搜索gz日志里的ERROR
gzip -dc app.log.gz | grep 'ERROR'
# 打包目录并gzip压缩（生成单个tar.gz归档）
tar -czf backup.tar.gz data/
```

|zless|分页查看压缩文本|

## ⚠️ 面试 & 实操易错细节修正

1. **gunzip**：不是 shell 别名，是 gzip 套件自带解压入口，**功能等价`gzip -d`**，两种写法都可用。
2. **gzip -l**：普通小文件查看大小没问题；超大文件、拼接 gzip 流场景，显示的原始大小**可能不准确**。 想要获取真实解压字节数，推荐管道方式：`gzip -dc file.txt.gz | wc -c`。
3. **gzip -r dir**：只递归处理目录内普通文件，每个文件单独生成`.gz`，**不会打包成单个归档**；符号链接、特殊文件不会被压缩。
4. 默认行为：不带`-k`，压缩成功删除原文件；解压成功默认删除`.gz`压缩包；需要保留文件必须加`-k`。
5. gzip 只能处理单个文件流，**不能存放多个文件**，这是和 zip/tar 最大区别。`.tar.gz`本质是 tar 先归档多个文件为单个 tar，再 gzip 压缩这个 tar 文件。
6. `gzip -t`仅校验压缩数据，能检测损坏，但**不能修复损坏数据**。
