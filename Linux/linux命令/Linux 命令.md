#### 用户
#####  id 查看用户 ID (UID)、组 ID (GID) 以及用户所属群组信息
`id [参数] [用户名]`
不写用户名时，默认查看**当前登录用户**信息

|参数|功能说明|示例命令|解释|
|---|---|---|---|
|`-g`|只显示用户**主组（初始组）**的 ID|`id -g alvin`|输出 alvin 主群组的数字 GID|
|`-G`|显示用户**所有附加附属组**的 ID（多个 ID 空格隔开）|`id -G alvin`|列出 alvin 全部附加组 ID，不含主组|
|`-n`|和`-g/-G/-u`搭配，**输出名称而不是数字 ID**|`id -ng alvin`|输出 alvin 主组名字，不是数字`id -nG alvin`：输出所有附加组名称|
|`-r`|显示**实际 ID (real ID)**，区别于有效 ID (effective ID)，多用于 sudo 切换身份场景|`id -r -u`|查看当前登录人的真实 UID，不是临时 sudo 的有效 UID|
|`-u`|只显示用户 UID（用户 ID 号）|`id -u alvin`|只打印 alvin 的 UID 数字|
```
id -nu alvin    # 输出用户名
id -ng alvin    # 输出主组名称
id -nG alvin    # 输出所有附加组名称
```
##### useradd 创建新用户账号，同时可以预先设置用户相关信息

`useradd [参数] 用户名`
⚠️ 必须 root 权限执行；useradd 新建用户默认**没有密码**，创建完需要用 `passwd 用户名` 设置密码才能登录。

|参数|功能说明|示例命令|解释|
|---|---|---|---|
|`-d <登入目录>`|指定用户家目录路径|`useradd -d /home/myhome user1`|指定家目录为`/home/myhome`，**不加 - m 不会自动创建这个文件夹**|
|`-g <群组>`|指定**初始主组**|`useradd -g dev user1`|user1 的主组设置为 dev 组|
|`-G <群组>`|指定**附加组（非初始组）**，多个组逗号分隔|`useradd -G test,ftp user1`|user1 额外加入 test、ftp 附属组|
|`-m`|**自动创建家目录**（最常用参数）|`useradd -m user1`|创建用户同时自动生成对应的家目录`/home/user1`|
|`-M`|**不创建家目录**|`useradd -M user1`|新建用户，不生成 /home 下的家目录，多用于程序账号|
|`-N`|不创建和用户名同名的私有组|`useradd -N user1`|默认 useradd 会自动新建一个和用户名一样的组做主组；-N 取消这个行为|
|`-s`|指定登录 shell|`useradd -s /bin/bash user1`|指定登录 shell 为 bash；`/sbin/nologin`代表禁止交互式登录|

**useradd 涉及 4 个核心用户配置文件**

1. `/etc/passwd`：**用户信息文件**，存放所有用户基本信息（UID、GID、家目录、shell 等），所有用户可读
2. `/etc/shadow`：**用户密码文件**，存放加密后的用户密码，只有 root 可读
3. `/etc/group`：**群组信息文件**，记录系统所有组，组 ID、组内成员
4. `/etc/gshadow`：**群组密码文件**，存放组管理员、组密码信息

**思维导图案例逐条解析**

1. `useradd user1`：直接创建用户。**默认不带 - m，不会自动创建家目录；自动新建同名主组**
2. `useradd -m -s /bin/bash user2`：生产常用创建方式。自动建家目录，指定登录 shell 为 bash，创建完可设置密码登录
3. `useradd -m username`：自动创建家目录
4. `useradd -m -d /new/dir username`：自定义家目录位置，-m 保证目录自动生成
5. `useradd -u 1500 username`：指定用户 UID 为 1500（UID 不能重复）
6. `useradd -g group username`：指定主组
7. `useradd -g group -G group1,group2 username`：指定主组，同时分配多个附加附属组
8. `useradd -s /bin/bash username`：指定登录 shell
9. `useradd -c "Test User Account" username`：添加用户备注信息（对应 usermod 的 - c 参数）

##### passwd 修改用户密码，也可以管理密码状态（锁定、过期、查询等）
`passwd [参数] [用户名]`
权限说明： 普通用户直接执行 `passwd`，只能修改**自己**的密码； root 管理员可以修改任意用户密码、锁定 / 解锁账号。

|参数|功能说明|示例命令|解释|
|---|---|---|---|
|`-d`|删除已有密码，账号变成无密码状态|`passwd -d liangxu`|清空 liangxu 的密码，登录时不需要密码（谨慎使用）|
|`-l`|锁定用户密码，用户无法用密码登录|`passwd -l liangxu`|在`/etc/shadow`密码字段前面加`!`，密码失效|
|`-u`|解锁用户密码，恢复密码登录|`passwd -u liangxu`|移除 shadow 里的`!`，解锁密码|
|`-e`|下次登录强制修改密码|`passwd -e liangxu`|用户 liangxu 再登录系统，立刻要求重置密码|
|`-k`|密码过期之后，仍然可以使用旧密码登录修改|`passwd -k liangxu`|密码到期后保留修改密码的权限|
|`-S`|查询密码状态（Status）|`passwd -S liangxu`|输出账号密码信息：用户名、密码状态、最后一次改密码时间、密码有效期等|
**思维导图案例逐条解析**

1. `passwd`：不带用户名，**修改当前登录用户自己的密码**
2. `passwd liangxu`：root 修改指定用户 liangxu 的密码
3. `passwd -l liangxu`：锁定 liangxu 密码，禁止密码登录
4. `passwd -u liangxu`：解锁 liangxu 密码
5. `passwd -e liangxu`：liangxu 下次登录，强制重置密码
6. `passwd -d liangxu`：删除 liangxu 的密码
7. `passwd -S liangxu`：查看 liangxu 账号密码状态

面试高频区分：`passwd -l` vs `usermod -L`

两者效果**几乎一样**，都是锁定密码，原理都是修改`/etc/shadow`：

- `passwd -l`：shadow 密码字段前加 `!!`
- `usermod -L`：shadow 密码字段前加 `!` 解锁对应：`passwd -u` / `usermod -U`

前面：`useradd` 创建用户，新建用户默认无密码，**必须用 passwd 设置密码**，账号才能登录。

> 小坑：普通用户不能执行 passwd -l /-u/-d，这些操作只有 root 有权限。


##### userdel 删除用户账户

|参数|功能|示例|解释|
|---|---|---|---|
|`-r`|删除用户账号，**同时删除用户家目录与里面所有文件**|`userdel -r liangxu`|不仅删掉 /etc/passwd 里的账号记录，同时把`/home/liangxu`整个目录全部删除|


1. `userdel liangxu` 只删除 liangxu 这个账号信息（清除`/etc/passwd`、`/etc/shadow`、`/etc/group`里的用户记录），**但是保留用户的家目录 `/home/liangxu`**。

> 场景：用户离职，需要保留家目录的数据备份，就不带`-r`。

2. `userdel -r liangxu` 删除用户账号信息 **并且连带删除家目录和里面全部文件**。

> 场景：测试账号，数据不需要保留，一次性清理干净。
 面试重点 & 坑点
1. 如果用户**处于登录状态**，直接`userdel`会报错，不能删除。需要先`kill`踢掉用户或者重启。
2. 不带`-r`删除用户后，家目录还残留在系统，目录文件的属主会变成数字 UID（用户名已经不存在）。
3. 完整用户管理闭环： `useradd`创建用户 → `passwd`设置密码 → `usermod`修改信息 → `id`查看信息 → `userdel`删除用户



##### su 切换用户身份
`su [参数] 用户名`
> 原理：切换到目标用户，需要输入**目标用户的密码**

|参数|作用|
|---|---|
|`-` / `-l`|完全身份变更：切换用户，**同时切换到对方家目录，加载目标用户完整环境变量**（工作最常用）|
|`-c`|执行完指定命令后，立刻切回原来用户身份，不长期停留在目标用户 shell|
|`-f`|csh/tsch 专用，shell 不读取启动配置文件|
|`-m`|切换身份，但**保留当前用户的环境变量，不更换**|
|`-s`|指定切换后使用的 shell|
思维导图案例解析

1. `su` 等价于 `su root` 切换到 root 用户，**但不会切换环境变量和家目录**（不完全登录 shell，不推荐）。
2. `su -c whoami alvin` 临时切换为 alvin 用户，执行`whoami`命令，执行结束自动退回当前用户。
> 适合脚本里临时用别的用户跑一条命令，不用手动切换来回。
3. `su alvin` 切换账号为 alvin，**但是保留当前所在工作目录，不加载 alvin 完整环境**（非登录 shell）。
4. `su - alvin`（最常用写法，`su -l alvin`等效） 切换为 alvin，**自动进入 alvin 家目录，加载 alvin 完整环境变量**，属于登录 shell。
`su` vs `su -`
- `su alvin`：只换用户身份，**环境变量、当前工作目录不变**，很多时候会出现环境异常。
- `su - alvin`：模拟完整登录，**环境变量、家目录全部切换成目标用户**，生产环境优先用这个。



##### sudo 以管理员（默认 root）身份执行指令
`sudo [参数] 命令`
> 要点：输入**当前用户自己的密码**，不是 root 密码；前提是当前用户在`sudoers`授权列表里。

| 参数        | 功能                               |
| --------- | -------------------------------- |
| `-l`      | 列出当前用户拥有哪些 sudo 权限               |
| `-u <用户>` | 以指定用户身份执行命令；不加 `-u` 默认使用 root 身份 |
配置文件

主配置文件：`/etc/sudoers`

> ⚠️ **推荐用 `visudo` 编辑，不要直接 vim 修改**。visudo 会自动检查语法，写错 sudoers 会导致 sudo 直接失效！

- `sudo visudo`：安全编辑 sudoers（首选）
- `sudo vim /etc/sudoers`：直接编辑（不推荐，语法错误会锁死 sudo）

sudoers 配置规则模板：

```
授权用户/组  主机=[(切换到哪些用户或组)] 命令
```

示例：`alvin ALL=(ALL) ALL` 含义：用户 alvin，在所有主机，可以切换到任意用户，执行所有命令。

思维导图案例解析

1. `sudo -l`：列出当前用户的 sudo 权限，查看能执行哪些命令
2. `sudo -u alvin whoami`：以 alvin 用户身份执行 whoami
3. `sudo !!`：**把上一条命令，用 root 权限重新执行**，非常常用。

> 场景：敲完命令提示权限不足，直接敲`sudo !!`，不用重复输入长命令。

面试重点：su 和 sudo 对比

|命令|密码|特点|
|---|---|---|
|su - root|需要输入**root 密码**|完整切换 root 身份，长期在 root shell|
|sudo cmd|需要输入**当前用户密码**|临时拿 root 权限跑单条命令，不切换 shell|

> 生产环境推荐 sudo，不需要把 root 密码分给所有人，权限可精细化管控。

sudo 默认密码有**5 分钟缓存**，5 分钟内再次 sudo 不需要重复输密码。

##### usermod 修改用户账号信息
语法 :`usermod [参数] 用户名`
前置说明：大部分 usermod 操作需要 root 权限，命令前面要加`sudo`，或者切换 root 用户执行。

| 参数           | 功能说明                                  | 示例命令                              | 解释                                                                                                          |
| ------------ | ------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `-c <备注>`    | 修改用户账号的备注文字                           | `usermod -c "测试用户alvin" alvin`    | 给 alvin 用户添加备注信息，信息会写入`/etc/passwd`                                                                         |
| `-d <登入目录>`  | 修改用户登录时的家目录                           | `usermod -d /home/hometest alvin` | 将 alvin 的家目录改成`/home/hometest`⚠️ 注意：这个命令**不会自动创建文件夹**，如需迁移旧家目录数据，搭配 `-m`：`usermod -md /home/hometest alvin` |
| `-e <有效期限>`  | 修改账号有效期，格式 YYYY-MM-DD                 | `usermod -e 2026-12-31 alvin`     | alvin 账号在 2026 年 12 月 31 日到期，到期账号无法登录                                                                       |
| `-f <缓冲天数>`  | 密码过期后，还能保留几天登录权限；0 = 过期立刻禁用，-1 = 永不禁用 | `usermod -f 7 alvin`              | alvin 密码过期之后，还允许 7 天内登录改密码                                                                                  |
| `-g <群组>`    | 修改用户**主组（初始组）**                       | `usermod -g group1 alvin`         | alvin 的主群组改为 group1，一个用户只能有 1 个主组                                                                           |
| `-G <群组>`    | 修改用户**附加群组（附属组）**，多个组用逗号隔开            | `usermod -G group2,group3 alvin`  | alvin 加入附加组 group2、group3；⚠️ 该参数会**覆盖原有附加组**，追加组用 `-aG`：`usermod -aG group4 alvin`                          |
| `-l <账号名称>`  | 修改用户名（login name）                     | `usermod -l harry alvin`          | 把用户名 alvin 修改为 harry                                                                                        |
| `-L`         | 锁定用户密码，密码失效，禁止密码登录                    | `usermod -L alvin`                | 锁定 alvin 账号密码，用户无法用密码登录；root 不受此限制                                                                          |
| `-s <shell>` | 修改用户登录使用的 shell                       | `usermod -s /bin/bash alvin`      | alvin 登录 shell 改为 bash；常用：`usermod -s /sbin/nologin alvin` 禁止交互式登录                                          |
| `-u <uid>`   | 修改用户 UID（用户 ID 号）                     | `usermod -u 1234 alvin`           | alvin 的 UID 修改为 1234，UID 在系统内不能重复                                                                           |
| `-U`         | 解除密码锁定                                | `usermod -U alvin`                | 解锁 alvin 账号，恢复密码登录                                                                                          |
|              |                                       |                                   |                                                                                                             |
 思维导图里自带案例汇总
1. 修改家目录：`usermod -d /home/hometest alvin`
2. 修改 UID：`usermod -u 1234 alvin`
3. 修改用户名：`usermod -l harry alvin`
4. 锁定账户：`usermod -L alvin`
5. 解锁账户：`usermod -U alvin`




##### groups 显示一个用户所加入的所有用户组
语法：`groups [用户名]`

`groups alvin` 查看用户 alvin 归属的全部用户组，输出中**第一个组是用户的主组（初始组），后面是附加组**。

1. 直接输入 `groups`（不带用户名）：查看**当前登录用户**属于哪些组
2. 和 `id` 命令对比： `id alvin` 也可以查看用户组信息，还附带 UID、GID，面试里两个都要记住。

> Linux 用户组概念回顾：
> - **主组（初始组）**：用户创建文件时，文件默认所属组；一个用户只能有**一个主组**
> - **附加组**：额外加入的组，用来共享目录权限；一个用户可以加入**多个附加组**


##### groupadd 创建新的用户组
语法：`groupadd [参数] 用户组名`
> 需要 root 权限执行；组信息写入 `/etc/group`

|参数|作用|
|---|---|
|`-g`|指定新建组的 GID（组 ID），GID 不能重复|
|`-r`|创建**系统用户组**，系统组 GID 默认小于 1000，用于服务进程，不给普通用户使用|

1. `groupadd work` 创建普通用户组，组名`work`，GID 由系统自动分配。
2. `groupadd -g 1234 family` 新建组`family`，**手动指定 GID=1234**，注意 GID 不能和已有组冲突。
3. `groupadd -r grouptest` 创建系统组`grouptest`，GID 自动分配在系统 ID 段（一般 < 1000）。

- 普通用户组 GID 默认≥1000；系统组给后台服务使用，一般不分配给登录用户。
- 查看所有组：`cat /etc/group`
- 组的信息文件：`/etc/group`（组名、GID、组内成员）


##### groupdel 删除用户组**

语法：`groupdel [参数] [群组名称]`

> 需要 root 权限，修改 `/etc/group` 文件


`groupdel family` 删除名为`family`的用户组。


1. **不能删除某个用户的主组** 如果还有用户把这个组作为**主组**，groupdel 会直接报错，必须先修改用户主组或者删除该用户。

> 附加组不受此限制，可以直接删掉。

2. 删除组**不会删除组内文件**，只是断掉用户和这个组的关联；文件的 GID 还保留，只是变成孤儿组 ID。
3. 一般无常用参数，最常用就是直接 `groupdel 组名`


#### 用户信息

##### w 显示当前已登录用户，附带系统负载、用户正在执行的进程
语法：`w [参数]`

|参数|作用|
|---|---|
|`-h`|不打印头部信息（系统负载那一行表头）|
|`-u`|计算进程 CPU 时间时忽略用户名|
|`-s`|短输出格式，精简字段|
|`-f`|显示登录来源（远程主机 / IP）|
|`-o`|老式输出格式|
|`-i`|尽可能直接显示 IP，不解析主机名|
 案例解析

1. `w` 直接执行，输出完整信息：系统当前时间、运行时长、登录用户数、平均负载；然后每个登录用户：用户名、终端、登录来源、登录时间、空闲时间、JCPU、PCPU、当前执行命令。
2. `w -h` 不输出表头，只输出用户条目。
3. `w -f` 开启 FROM 字段，查看用户从哪里远程登录。
4. `w -s` 短格式，精简部分字段，输出更简洁。
面试对比（必背）

- `users`：只输出登录用户名，信息最少
- `who`：用户名、终端、登录时间、来源 IP，中等信息
- `w`：在 who 基础上，增加**系统负载、空闲时间、CPU 占用、当前运行命令**，信息最全

##### who 查看当前登录用户信息
语法：`who [参数]`

|参数|作用|
|---|---|
|`-a`|输出全部完整信息（等价 `-b -d -l -p -r -t -u`）|
|`-b`|查看系统最近一次启动时间|
|`-l`|列出系统登录进程|
|`-H`|打印表头标题（列名）|
|`-t`|查看系统上次锁定时间|
|`-u`|列出已登录用户|
|`-q`|只列出登录用户名 + 总人数，精简输出|

1. `who` 基础用法：输出当前登录用户、终端、登录时间、远程来源。
2. `who -H` 查看登录信息，**带表头标题**，方便阅读。
3. `who -H -a` 展示完整全部登录相关信息。
4. `who -b` 查看系统最近开机时间。
5. `who -T -H` 显示终端属性（终端是否可写）+ 表头。
6. `who -q` 精简模式，只输出用户名和登录用户总数。

| 命令      | 信息丰富度 | 核心用途                                 |
| ------- | ----- | ------------------------------------ |
| `users` | 最少    | 只打印登录用户名                             |
| `who`   | 中等    | 用户、终端、登录时间、来源 IP                     |
| `w`     | 最全    | who 的全部信息 + **系统负载、空闲时间、CPU、用户当前命令** |
| `last`  | 历史    | 历史登录记录（包含重启记录）                       |

> 一句话记忆：users 看名字，who 看登录，w 看负载和正在干啥，last 看历史登录。
##### users **显示当前登录到系统的用户** 
语法：`users`（无参数） 
案例：`users`，直接输出当前已登录用户名列表。 

1. `users`：极简输出，只打印登录用户名，同一个用户多终端登录会重复显示。
2. `who`：信息更丰富，用户名 + 终端 + 登录时间 + 来源 IP。
3. `w`：最全，包含登录用户、终端、登录时间、空闲时间、当前执行命令、系统负载。

> 一句话记忆：users 看名字，who 看登录信息，w 看用户在干嘛

##### whoami 打印当前有效用户名
语法：`whoami`（无参数） 
案例：`whoami`，直接输出当前操作终端的用户名。


1. **whoami**：输出**当前有效用户**。`su`切换用户后，`whoami`会变成新用户。
    
    > 例：root 执行`su test`，再`whoami` → `test`
    
2. **who am i**（分开写）：输出**原始登录用户**，不会随 su 切换改变，记录最开始登录的账号。
3. `who` / `w`：查看系统上**所有登录用户**，不是只看自己。

##### last 查看用户 / 终端历史登录记录**（读取 `/var/log/wtmp` 日志） 
语法：`last [选项]`

| 参数                  | 作用                         |
| ------------------- | -------------------------- |
| `-R`                | 省略主机名 (hostname) 那一列，输出更简洁 |
| `-a`                | 将登录来源的主机名 / IP 放到最后一列      |
| `-n <数字>` / `-<数字>` | 指定显示多少行记录                  |
| `-i`                | 显示 IP 地址，不解析为主机名           |
1. `last` 直接执行，输出全部近期登录、重启记录，从最新到最旧排序。
2. `last -n 5 -R` / `last -5 -R` 只显示最近 5 条记录，并且省略主机名字段。
3. `last -n 5 -a -i` 显示最近 5 条记录，来源 IP 放在末尾，直接展示 IP 不解析主机名。
要点
- `last`：**历史登录记录**（包括系统重启记录）
- `lastlog`：查看所有用户**最近一次登录**
- `lastb`：查看登录失败记录（需要 root 权限，读取`/var/log/btmp`）




### 文件及目录
#### 创建和删除
##### touch 
1. 创建新的空文件
2. 修改已有文件的时间戳属性

> ⚠️ 注意：修改文件时间属性，需要是文件属主或者具备写权限

**语法**：`touch [OPTION]... FILE...`

|参数|作用|
|---|---|
|`-a`|只修改访问时间 access (atime)|
|`-m`|只修改修改时间 modify (mtime)|
|`-r`|参考指定文件的时间戳，复制给目标文件|
|`-c` / `--no-create`|文件不存在时，**不创建新文件**|
|`-d`|使用字符串指定时间（例如 tomorrow）|
|`-t`|自定义时间戳，格式和 date 命令一致|
案例解析

1. `touch file.txt` 文件不存在：创建空文件；文件已存在：把文件 atime、mtime 更新为当前系统时间。
2. `touch file1.txt file2.txt file3.txt` 一次性创建多个空文件。
3. `touch file{1..3}.txt` 批量创建 file1、file2、file3。
4. `touch -a file.txt` 仅更新文件**访问时间 atime**。
5. `touch -m file.txt` 仅更新文件**修改时间 mtime**。
6. `touch -c nofile.txt` / `touch --no-create nofile.txt` 文件不存在时，不会新建文件，只尝试修改时间。
7. `touch file.txt -r ref_file.txt` 把 ref_file.txt 的时间戳复制给 file.txt。
8. `touch -d "tomorrow" file.txt` 将文件时间修改为明天。
9. `touch -t 2201011030.55 file.txt` 自定义时间：2022 年 01 月 01 日 10:30:55

面试必背：Linux 文件三个时间
- **atime access**：访问时间，读取文件内容时更新
- **mtime modify**：修改时间，文件**内容**改动时更新（`ls -l` 默认看到的时间）
- **ctime change**：状态变更时间，文件**元信息**（权限、属主、大小）改动更新，touch 无法直接单独修改 ctime
小提示：`ls -lu` 查看 atime；`ls -l` 查看 mtime；`ls -lc` 查看 ctime

##### mkdir 

**作用：创建目录（文件夹）**
> ⚠️ 注意：默认情况下目录已存在会报错；同目录下，目录名不能和文件名重名。 语法：`mkdir [OPTION]... DIRECTORY...`

|参数|作用|
|---|---|
|`-p`|递归创建多级目录；父目录不存在自动创建；目录已存在也不会报错|
|`-m`|创建目录同时直接指定权限|
|`-v`|显示创建过程，打印日志|
案例解析

1. `mkdir dir1` 在当前目录创建 dir1 子目录。
2. `mkdir dir2 dir3 dir4` 一次性创建多个同级目录。
3. `mkdir dir{5..7}` 批量创建 dir5、dir6、dir7。
4. `mkdir -p dir7/dir8/dir9` 递归创建多级目录，父目录不存在自动创建。**面试高频参数 -p**
5. `mkdir -m 700 dir1/dir10` 创建 dir10 目录，权限直接设为 700。
6. `mkdir -v dir{11..13}` 创建目录并打印创建详情。
面试小要点
- `mkdir` 默认只能创建**一级目录**，多层必须加 `-p`
- `-p` 非常适合脚本里使用，防止目录已存在导致脚本异常退出

##### rm 

**作用：删除文件或目录** 
语法：`rm [OPTION]... [FILE]...`

|参数|作用|
|---|---|
|`-f`|强制删除；文件不存在也不报错、无警告|
|`-i`|删除前交互式询问确认（y 删除，n 取消）|
|`-r / -R`|递归删除，**可删除目录以及目录内所有内容**|
|`-v`|显示删除详细过程|
 案例解析

1. `rm file.txt` 删除单个文件；只读文件会弹出确认提示。
2. `rm -r dir` 递归删除目录 dir（目录里面有文件也一并删除）。
3. `rm -f file.txt` 强制删除文件，**不弹出任何确认提示**。
4. `rm -rf *` 删除当前目录下所有文件与子目录。

> ⚠️ **高危命令！严禁执行 rm -rf /**，会删除根目录，系统直接崩溃。

5. `rm -i file1.txt file2.txt file3.txt` 逐个询问，确认后才删除。
📌 面试重点
6. rm 默认**不能直接删文件夹**，删目录必须加 `-r`
7. `-rf` 组合：递归 + 强制，生产环境脚本常用，但**极其危险**
8. 没有回收站，rm 删除后很难恢复，操作前务必确认路径


##### rmdir 

**作用：删除空目录** 语法：`rmdir [OPTION]... DIRECTORY...`

| 参数   | 作用                          |
| ---- | --------------------------- |
| `-p` | 递归删除路径上所有父空目录；**目录非空就报错停止** |
| `-v` | 显示命令详细执行过程                  |
 案例解析

1. `rmdir dir` 删除单个空目录；目录里面有文件会报错无法删除。
2. `rmdir -p dir1/dir2/dir3` 递归删除多级空目录：先删 dir3，dir2 变空就删 dir2，dir1 变空就删 dir1；**任意一层不为空，命令终止**。
3. `rmdir -v dir` 删除空目录并打印执行详情。

面试对比（rmdir vs rm -r）

- `rmdir`：**只能删空目录**，不能删文件；安全，不会误删数据。
- `rm -r`：不管目录是否为空，递归删除目录 + 里面全部文件；高危。

> 一句话记忆：rmdir 只删空文件夹，rm -r 不管里面有啥全部删掉。'


##### mv 
**作用**
1. 移动文件 / 目录
2. 重命名文件 / 目录

**语法**

```
mv [OPTION]... [-T] SOURCE DEST
mv [OPTION]... SOURCE... DIRECTORY
mv [OPTION]... -t DIRECTORY SOURCE...
```

|参数|作用|
|---|---|
|`-i`|目标存在同名文件，交互式询问是否覆盖|
|`-f`|直接覆盖已有文件，**不提示**|
|`-b`|覆盖文件前，自动给原文件创建备份|
|`-u`|仅当源文件更新，或者目标不存在时，才执行移动|
 案例解析

1. `mv file.txt /dir` 将 `file.txt` 移动到 dir 目录。
2. `mv file.txt newfile.txt` 文件**重命名**（目标不存在，就是改名）。
3. `mv dir1 dir2` 如果 dir2 已存在：把 dir1 移动到 dir2 里面； 如果 dir2 不存在：将 dir1 重命名为 dir2。
4. `mv -i file1.txt file2.txt` 如果 file2.txt 存在，询问是否覆盖。
5. `mv -f file1.txt file2.txt` 目标存在，**直接强制覆盖，无提示**。
6. `mv -b file1.txt file2.txt` 覆盖前自动备份原文件（备份文件后缀 `~`）。
7. `mv -u file1.txt file2.txt` 源文件更新时间更新，或者目标不存在，才移动。
8. `mv * ../` 把当前目录下所有文件移动到上一级目录。
9. `mv dir3/* dir2` 将 dir3 目录下全部文件移动到 dir2。

 📌 面试要点

- `mv` 本质：**同一分区移动，只是修改文件目录项，不拷贝数据；跨分区移动，是拷贝 + 删除源文件**。
- 区分：目标是**已存在目录** → 移入目录；目标**不存在** → 源文件改名。


##### cp 

**作用：复制文件或目录**

```
cp [OPTION]... [-T] SOURCE DEST
cp [OPTION]... SOURCE... DIRECTORY
cp [OPTION]... -t DIRECTORY SOURCE...
```

|参数|作用|
|---|---|
|`-f`|目标文件存在，直接覆盖，无提示|
|`-i`|目标文件存在，交互式询问是否覆盖|
|`-a`|归档复制；复制目录时保留链接、权限、时间等全部属性，递归复制所有内容（生产备份常用）|
|`-r`|递归复制文件和目录；复制目录必须加该参数|
|`-b`|覆盖前自动备份目标文件，备份文件后缀 `~`|
|`-v`|可视化输出，打印复制过程|
 案例解析

1. `cp file1.txt file2.txt` 复制文件 file1.txt，新文件名为 file2.txt。
2. `cp -r dir1 dir2` 递归复制目录 dir1 到 dir2。
3. `cp -i file1.txt file2.txt` 目标存在，询问是否覆盖。
4. `cp -f file1.txt file2.txt` 目标存在，直接强制覆盖。
5. `cp -b file1.txt file2.txt` 覆盖前自动备份原目标文件。
6. `cp -a dir1 dir2` 归档复制目录，**完整保留源文件 / 目录所有属性（权限、属主、时间戳）**，企业备份首选。
📌 面试重点

7. cp 默认**不能直接复制目录**，复制目录必须 `-r`；`-a` ≈ `-dr --preserve=all`，比 `-r` 更强。
8. mv 是移动（同分区不拷贝数据）；cp 是新建一份副本，源文件保留。
9. 脚本中用 `-a` 做目录备份；交互式操作可用 `-i` 防止误覆盖

#### 目录操作
##### cd 
**作用：切换目录** 
语法：`cd [参数] 目录`

|符号|含义|
|---|---|
|`~`|当前用户家目录|
|`.`|当前目录|
|`..`|当前目录的上一级目录|
|`/`|根目录|
|`-`|上一次所在目录|
绝对路径 vs 相对路径

- **绝对路径**：以 `/` 开头，从根目录开始定位，任何位置都能使用。例：`cd /home/user`
- **相对路径**：不以 `/` 开头，相对于**当前所在目录**定位。例：`cd dir`
案例解析

1. `cd dir`：切换到当前目录下的 dir 子目录
2. `cd ../..`：切换到**上两级目录**
3. `cd ~`：切换到用户家目录
4. `cd`：不带参数，默认直接回到家目录（等价 `cd ~`）
5. `cd -`：切换回上一次所在目录（来回切换目录非常好用）
📌 面试要点

1. cd 是**shell 内置命令**，不是独立程序（`type cd` 可查看）。
2. `cd -` 切换后会打印出目标目录路径。
3. 路径区分：绝对路径不受当前位置影响；相对路径依赖当前所在目录。


##### pwd

**作用：显示当前所在目录的绝对路径** 
语法：`pwd`

|参数|作用|
|---|---|
|`-L`|显示逻辑路径（默认，软链接目录，输出链接路径）|
|`-P`|显示物理真实路径（解析软链接，输出原始真实目录）|
案例
1. `pwd` 直接打印当前目录绝对路径。
2. `pwd -P` 如果当前目录是软链接，输出**真实物理路径**。
面试要点

1. pwd 是 shell **内置命令**（`type pwd` 查看）。
2. `-L` 和 `-P` 的区别：软链接目录场景下容易出题。

> 举例：`/link` 指向 `/real`，进入 `/link`
> - `pwd` / `pwd -L` → `/link`
> - `pwd -P` → `/real`


##### ls 
**作用：列出目录内容，查看文件 / 目录信息** 语法：`ls [OPTION]... [FILE]...`

|参数|作用|
|---|---|
|`-a`|显示全部文件，包含`.`开头的隐藏文件|
|`-l`|长格式展示，权限、属主、大小、时间等详细信息|
|`-r`|逆序输出（默认按英文字母升序）|
|`-t`|按**修改时间**排序，最新的在前|
|`-h`|人类可读单位展示大小（KB/MB/GB），常搭配 `-l` → `ls -lh`|
|`-A`|类似 `-a`，但不显示 `.`（当前目录）和 `..`（上级目录）|
|`-S`|按文件**大小**降序排序|
|`-R`|递归列出所有子目录内容|
|`-F`|文件名称末尾标记类型：目录加`/`，可执行文件加`*`|
案例

1. `ls -a`：列出当前目录所有文件（含隐藏文件）
2. `ls -l`：列出当前目录文件详细信息
3. `ls /`：查看根目录下文件
4. `ls -lR`：递归查看当前目录及所有子目录详细信息
5. `ls -l f*`：列出当前目录所有以`f`开头文件的详细信息
6. `ls -ltr`：按修改时间**倒序**（旧文件在前）
7. `ls -AF`：展示所有文件，自动标记目录 / 可执行文件类型
8. `ls -lh`：长格式 + 可读单位显示文件大小

📌 面试重点

1. `ls -l` 第一列字符含义：`-`普通文件、`d`目录、`l`软链接、`b`块设备、`c`字符设备。
2. 组合参数可以合并简写：`ls -l -h` = `ls -lh`。
3. `ls -t` 是 mtime（修改内容时间）；`ls -r`反转排序。

##### tree 

**作用：以树形结构列出目录内容** 语法：`tree [参数]`

> 注意：tree 不是系统自带默认命令，Ubuntu/CentOS 需要单独安装（`apt install tree` / `yum install tree`）


|参数|作用|
|---|---|
|`-a`|显示所有文件和目录（包含隐藏文件）|
|`-L`|限制显示层级，后面跟数字，常用 `-L 2` 只看两层|
|`-t`|按文件 / 目录修改时间排序（新的在前）|
|`-r`|按修改时间倒序排序（旧的在前）|
|`-f`|在每个条目前面，显示完整相对路径|
|`-d`|**只显示目录，不展示文件**|
|`-p`|同时显示文件权限信息|
 案例

1. `tree`：显示当前目录下树形结构
2. `tree -a`：树形展示所有文件（含隐藏文件）
3. `tree -d`：只打印目录树，不显示文件
4. `tree -L 2`：只展示 2 级目录（高频使用，防止递归输出刷屏）
5. `tree -p`：树形输出并附带权限
6. `tree -t`：按修改时间排序
7. `tree -r`：修改时间逆序
8. `tree -f`：每条前面带上完整相对路径

 📌 面试要点

1. tree 属于外部命令，系统最小化安装时没有，需要单独安装。
2. `-L` 限制层级，工作中查看项目目录结构最常用。
3. `-d` 只看文件夹，快速梳理目录架构。


#### 查找目录/文件
##### find 

**作用：在指定路径下搜索文件，功能强大，可以按文件名、大小、时间、权限、类型等多条件查找** 
语法：`find [路径] [参数] [条件]`

| 参数               | 作用                                             |
| ---------------- | ---------------------------------------------- |
| `-name`          | 按文件名匹配，区分大小写；`-iname` 忽略大小写                    |
| `-perm`          | 按权限匹配，`-perm mode` 完全匹配；`-perm -mode` 包含该权限即可  |
| `-user`          | 匹配文件属主（所有者）                                    |
| `-group`         | 匹配文件属组                                         |
| `-mtime`         | 文件**内容修改时间**；`-n` n 天内，`+n` n 天以前              |
| `-atime`         | 文件**访问读取时间**                                   |
| `-ctime`         | 文件**元数据 / 权限修改时间**                             |
| `-nouser`        | 查找没有属主的文件                                      |
| `-nogroup`       | 查找没有属组的文件                                      |
| `-newer f1 !f2`  | 比 f1 新，但比 f2 旧的文件                              |
| `-type`          | 文件类型：`b`块设备，`d`目录，`c`字符设备，`p`管道，`l`软链接，`f`普通文件 |
| `-size`          | 按文件大小查找；`+50k`大于 50KB，`-50k`小于 50KB            |
| `-prune`         | 忽略、跳过某个目录（搜索时排除目录）                             |
| `-exec 命令 {} \;` | 对搜索到的结果执行后续命令；`{}`代表找到的文件，`\;`结尾               |

 案例

1. `find / -name *.conf`：全盘搜索系统中所有以`.conf`结尾的文件
2. `find /etc -size +1k`：在`/etc`目录搜索大于 1k 的文件
3. `find /home -user liangxu`：`/home`目录查找属主为 liangxu 的文件
4. `find . -type f`：当前目录递归查找所有普通文件
5. `find . -perm 664 -exec ls -l {} \;`：查找权限 664 的文件，并执行 ls 列出详情
6. `find .`：列出当前目录及子目录全部文件
7. `find . -iname "*.txt"`：查找 txt 后缀，**忽略大小写**
8. `find . ! -name "*.txt"`：查找后缀**不是 txt**的文件（! 取反）
9. `find . -mtime -7 -exec rm -i {} \;`：查找 7 天内修改过的文件，交互式删除

 📌 面试高频考点

1. find 是**磁盘实时遍历**，速度比 locate 慢，但结果最新；locate 查数据库，速度快但不是实时。
2. mtime/atime/ctime 三者区分是高频面试题：
    - mtime：文件内容改动
    - atime：文件被读取访问
    - ctime：文件属性（权限、属主）改动
3. `-exec {} \;` 批量处理文件；`{}`是占位符，`\;`是结束标记。
4. `!` 代表条件取反；`-prune`用于搜索时排除目录，减少扫描范围。


##### which 
**作用：查找外部命令的可执行文件所在路径，从 PATH 环境变量的目录中搜索** 语法：`which [-a] filename ...`
- `-a`：列出**所有**匹配的可执行文件（默认只输出第一个找到的）
 案例
1. `which bash`：查看 bash 命令所在路径
2. `which ls`：查看 ls 命令所在路径
3. `which fdisk`：查看 fdisk 命令所在路径

 📌 面试重点

1. **只能查找 PATH 里的外部命令，找不到 shell 内置命令**（cd、pwd 这种内置命令用 which 查不到）
2. 原理：遍历`$PATH`环境变量中的目录，匹配可执行程序
3. 和 find/whereis 区别：
    - which：只查可执行命令，速度快
    - find：全盘遍历，所有文件都能搜，慢
    - whereis：查找命令、源码、man 手册位置

##### whereis 

**作用：查找命令对应的二进制程序、源代码、man 手册页等相关文件路径** 
语法：`whereis [options] [-BMS directory... -f] name...`

|参数|作用|
|---|---|
|`-b`|只查找二进制程序 / 可执行命令|
|`-B`|在指定目录下查找二进制程序|
|`-m`|只查找 man 手册文件|
|`-M`|在指定目录下查找 man 手册文件|
|`-s`|只查找源代码文件|
|`-S`|在指定目录下查找源代码文件|
 案例

1. `whereis ls`：查找 ls 命令的二进制程序路径 + man 手册位置
2. `whereis -b ls`：仅查找 ls 命令的二进制程序路径
3. `whereis -m ls`：仅查找 ls 命令的 man 手册路径

📌 面试重点

1. whereis 不是全盘搜索，在系统预设的数据库目录查找，速度快。
2. 对比区分：
    - `which`：只找 PATH 里的**可执行二进制**
    - `whereis`：二进制 + man 手册 + 源码，一次性输出
    - `find`：磁盘实时遍历，任何文件都能搜，最慢
3. 同样无法查找 shell 内置命令（cd、pwd 等）。

##### locate 
**作用：快速查找文件 / 目录，检索系统预建的文件数据库，速度远快于 find** 语法：`locate [参数] [文件]`

- `-i`：搜索时**忽略大小写**
 案例

1. `locate file.txt`：查找系统内所有名为 file.txt 的文件
2. `locate /etc/sh`：匹配路径中包含 `/etc/sh` 的全部文件
3. `locate whereis`：查找所有文件名包含 whereis 的相关文件
4. `locate -i locate/f`：查找指定目录下以 f 开头的文件，忽略大小写
📌 面试高频考点

1. 原理：读取`mlocate`数据库（`/var/lib/mlocate/mlocate.db`），**不是实时扫描磁盘**；数据库系统每日自动更新。
2. 缺点：新建文件不会立刻被搜到；手动更新数据库命令：`updatedb`。
3. 对比四兄弟（查找命令）

| 命令      | 查找对象         | 数据源         | 速度  |
| ------- | ------------ | ----------- | --- |
| which   | 可执行命令        | PATH 环境变量   | 快   |
| whereis | 命令二进制、man、源码 | 预设系统目录      | 快   |
| locate  | 任意文件         | mlocate 数据库 | 很快  |
| find    | 任意文件         | 实时磁盘遍历      | 慢   |
4. 最小化系统默认不带 locate，需要安装：`yum install mlocate` / `apt install plocate`





#### 文件操作

##### stat 

**作用：查看文件或文件系统的详细元数据信息（大小、权限、inode、三种时间等）** 
语法：`stat [OPTION]... FILE...`

|参数|作用|
|---|---|
|`-L`|跟随符号链接，显示链接指向的真实文件信息|
|`-f`|不看文件本身，查看该文件所在**文件系统**信息|
|`-t`|简洁模式输出（单行，适合脚本解析）|
 文件三种时间（面试重点）

1. **atime（access time，访问时间）**：文件被读取（cat/more/less/tail）时更新
2. **mtime（modify time，修改时间）**：**文件内容**被编辑修改（vim/nano 写入）时更新
3. **ctime（change time，状态改变时间）**：文件元数据变化（内容修改、chmod/chown 改权限属主）都会更新

> 注意：ctime 不是 “创建时间”，Linux 默认不保存文件创建时间。

 案例

1. `stat file.txt`：查看 file.txt 文件完整元信息
2. `stat -f file.txt`：查看 file.txt 所在文件系统的信息
3. `stat -t file.txt`：单行简洁输出，方便 shell 脚本截取字段
 📌 面试要点

- stat 可以直观看到 atime/mtime/ctime，正好对应 find 的 `-atime/-mtime/-ctime` 参数
- 很多系统挂载参数开启 `noatime`，读取文件时不再更新 atime，用来提升磁盘性能
- `-L` 参数：不加 - L 时，stat 软链接，只会显示链接文件本身信息；加 - L 追踪到源文件



##### rename 

**作用：通过字符串替换批量修改文件名（Perl 版本 rename，支持正则替换）** 
语法：`rename 's/old-name/new-name/' files`

- `old-name`：文件名中待替换原字符串
- `new-name`：替换后的目标字符串
- `files`：要重命名的文件列表
 通配符

- `?`：匹配**单个**任意字符
- `*`：匹配**多个**任意字符

|参数|作用|
|---|---|
|`-n`|模拟试运行，**不会真的修改文件名**，推荐先加 - n 测试|
|`-v`|详细输出，打印每一条重命名执行信息|
|`-f`|强制覆盖，目标文件名已存在时直接覆盖|
 案例

1. `rename 's/.txt/.doc/' myfile.txt` 把 myfile.txt 修改为 myfile.doc
2. `rename -n 's/file/file0/' *.txt` 模拟：将 file1.txt、file2.txt → file01.txt、file02.txt，只预览，不改动
3. `rename -v 's/file/file0/' *.txt` 真实执行批量改名，同时打印修改详情
 📌 面试重点

> ⚠️ Linux 有两个版本 rename，坑点高频考点

1. **Perl 版（常用，支持正则`s///`）**：Ubuntu 默认；就是上面思维导图的用法，支持批量正则替换。
2. **C 语言版（CentOS 旧版默认）**：语法完全不一样：`rename 原字符 新字符 文件`，**不支持正则**。

- 小技巧：执行 `rename --version` 看版本；批量改名优先 `-n` 预览，防止改错文件。
- 对比：`mv` 只能单个文件改名；`rename` 适合批量大量文件重命名。


##### basename
**作用：从完整路径字符串中，提取文件名 / 目录名（剥离前面的目录路径），shell 脚本高频工具** 
语法：

```
basename NAME [SUFFIX]
basename OPTION... NAME...
```


|参数|作用|
|---|---|
|`-a`|一次性处理多个路径，批量提取|
|`-s`|删除指定后缀名|

案例

1. `basename /etc/passwd` 输出：`passwd`，提取路径末尾文件名
2. `basename /usr/local/` 输出：`local`，自动去掉末尾 `/`，提取目录名
3. `basename -a /etc/passwd /usr/local/` 同时处理多个路径，分别输出结果
4. `basename /etc/sysctl.conf .conf` 输出：`sysctl`，直接指定后缀，自动切掉`.conf`
5. `basename -s .conf /etc/sysctl.conf` 等价上面，用 `-s` 参数删除后缀

 📌 面试重点

1. 配套命令：`dirname`，作用相反 —— 提取**目录部分**，丢掉文件名
    - `dirname /etc/passwd` → `/etc`
    - `basename /etc/passwd` → `passwd`
2. 典型场景：shell 脚本里拿到脚本自身名字 `basename $0`
3. 只做字符串处理，**不会去磁盘检查文件是否真实存在**，纯文本切割。

##### dirname 

**作用：去除路径里最后的文件名 / 目录名，只保留目录路径部分；和 basename 成对使用，shell 脚本高频** 语法：

```
dirname [OPTION] NAME...
```
案例

1. `dirname /usr/bin/cat` 输出：`/usr/bin`，提取文件所在目录路径
2. `dirname /home/liangxu/commands/` 输出：`/home/liangxu`，路径末尾带`/`也会自动剥离最后一级目录

📌 面试重点

1. 对比记忆：
    
    - `dirname`：拿**目录**，丢掉末尾文件 / 文件夹名
    - `basename`：拿**文件名**，丢掉前面目录
    
    ```
    path="/etc/passwd"
    dirname $path   # /etc
    basename $path  # passwd
    ```
    
2. 特性：**纯字符串切割，不校验磁盘上文件是否真实存在**
3. 典型脚本场景：获取当前脚本所在目录
    
```
script_dir=$(cd $(dirname $0); pwd)
```



##### chattr /lsattr 

**作用：chattr 修改文件 / 目录的扩展属性；lsattr 查看扩展属性（底层文件系统属性，比 chmod 权限更强）** 语法：

```
chattr [-RVf] +-=[aAcCdDeijsStTu] files...
```

|参数|含义|
|---|---|
|`-R`|递归处理目录下全部文件|
|`-v`|设置文件版本号|
|`-V`|显示命令执行详情|
|`+`|**增加**某项属性|
|`-`|**移除**某项属性|
|`=`|**仅保留**指定属性，清空其他|
核心扩展属性（面试高频两个）

1. **i 属性（immutable，不可变）** 文件被设置 `+i`：**不能修改、删除、重命名、创建硬链接**，root 也无法改动，用来保护关键配置文件。
2. **a 属性（append only，仅追加）** 设置 `+a`：**只能追加写入内容，不能修改原有内容、不能删除**，非常适合日志文件。

> 其他属性了解即可：`A`不更新 atime、`S`同步写入磁盘等。
案例

```
chattr +i file.txt      # 锁定文件，禁止修改删除
chattr -i file.txt      # 解锁，移除不可变属性
chattr +a file.txt      # 设置仅追加，日志专用
chattr -R +i dir        # 递归给目录下所有文件加不可变属性
lsattr file.txt         # 查看文件扩展属性
```
📌 面试重点

1. **chattr 是文件系统扩展属性，chmod 是传统 rwx 权限，两者独立！** 即使权限是 777，只要 `+i`，root 也删不掉文件；
2. 解除 `+i` / `+a` 依然需要 root；
3. 适用文件系统：ext2/ext3/ext4；xfs 部分支持；tmpfs 不支持；
4. 排查场景：文件明明权限足够，但是无法删除 / 修改，优先 `lsattr` 检查是否加了 i 属性。

##### file 

**作用：识别文件类型，不靠后缀名，读取文件头部的魔数 (magic number) 判断真实类型**
语法：`file [参数] 文件`

|参数|作用|
|---|---|
|`-b`|只输出文件类型，不打印文件名|
|`-c`|详细输出命令执行调试过程|
|`-f`|读取文件内的文件名列表，批量识别多个文件|
|`-L`|跟随软链接，直接显示**链接指向的真实文件**类型|
|`-m`|指定自定义魔法数字库文件|
|`-z`|尝试解析压缩包内部文件类型|
|`-i`|输出 MIME 类型（常用于脚本）|
 案例

```
file file.txt          # 查看文件类型
file dir               # 查看目录类型
file /dev/sda          # 查看块设备文件类型
file -b file.txt       # 只输出类型，不带文件名
file -i file.txt       # 输出MIME类别，如 text/plain; charset=utf-8
file /dev/cdrom        # 默认查看软链接本身
file -L /dev/cdrom     # 跟随软链接，查看目标真实文件类型
```

 📌 面试重点

1. **判断依据：文件头部魔数，不是文件名后缀** Linux 不依赖后缀识别文件，改后缀不会改变文件真实类型；`file` 读取文件头部魔数识别。
2. 区分：不加 `-L` 时，软链接会显示 `symbolic link to xxx`；`-L` 解引用，看目标。
3. 常见输出类型：`regular file`普通文件、`directory`目录、`block special`块设备、`character special`字符设备、`symbolic link`软链接。


##### md5sum 

**作用：生成、校验文件 MD5 哈希值，用于验证文件完整性（传输 / 拷贝后判断文件是否损坏、篡改）** 
语法：

```
md5sum [OPTION]... [FILE]...
```


|参数|作用|
|---|---|
|`-b`|二进制模式读取文件（Windows 文件常用）|
|`-t`|文本模式读取文件（Linux 默认）|
|`-c`|读取 md5 记录文件，对现有文件做校验|
|`--status`|校验时不输出文字结果，靠命令返回码判断，适合脚本|
 案例

```
md5sum file.txt                  # 生成 file.txt 的MD5哈希值
md5sum -b file.txt               # 二进制模式计算MD5
md5sum -t file.txt               # 文本模式计算MD5
md5sum file.txt > file.md5       # 将MD5结果重定向保存到文件
md5sum -c file.md5               # 根据md5文件校验，输出OK/FAILED
md5sum -c --status file.md5      # 静默校验，无输出；$?为0=成功，非0=失败
echo $?                          # 查看上一条命令返回码
```
📌 面试重点

1. MD5 是**哈希摘要算法**，相同文件一定得到相同 md5；文件哪怕改动 1 字节，md5 值完全变化。
2. 安全层面：MD5**存在碰撞漏洞**，只能做文件完整性校验，**不能用于安全签名**；安全场景改用 sha256sum。
3. 脚本用法：`--status` + `echo $?` 是 shell 自动化校验常用写法。
4. 对比同类命令：`sha1sum`、`sha256sum`，用法和 md5sum 几乎完全一致。


#### 权限操作
##### chown 命令详解

**作用：修改文件 / 目录的所属用户（属主）和所属用户组；修改属主一般需要 root/sudo 权限** 语法：

```
chown [参数] 所属主:所属组 文件
```

| 参数   | 作用                       |
| ---- | ------------------------ |
| `-R` | 递归修改目录及其内部所有文件、子目录的属主和属组 |
| `-c` | 只打印发生变更的文件信息，无变化不输出      |
 案例

```
sudo chown alvin:alvin file.txt    # 同时修改属主、属组为 alvin
sudo chown alvin file.txt          # 只修改属主，属组保持不变
sudo chown :alvin file.txt         # 只修改属组，属主保持不变
sudo chown -c liangxu:liangxu file.txt # 修改属主属组，并打印变更信息
sudo chown -R alvin:alvin dir      # 递归修改目录dir下全部内容的属主属组
```
 📌 面试重点

1. **chown 修改归属人；chmod 修改 rwx 权限，两个命令不要混淆。**
2. 格式 `user:group`；冒号不能少，只写 `:group` 代表仅修改组。
3. `-R` 递归使用场景：解压项目包后，把整个目录归属改成业务用户；**慎用在根目录 /**，会直接破坏系统文件归属。
4. 查看文件属主属组：`ls -l`，第三列是属主，第四列是属组。
5. 普通用户**不能**把自己文件的属主改成别的用户，只有 root 可以。

> 配套命令：`chgrp` 只修改用户组，功能等价于 `chown :group`。

##### chgrp 命令详解

**作用：只修改文件 / 目录的所属用户组，不修改属主；等价于 `chown :组名 文件`** 语法：

```
chgrp [参数] 用户组 [文件/目录]
```

|参数|作用|
|---|---|
|`-v`|显示命令执行详细过程|
|`-R`|递归修改目录及其下所有文件、子目录的用户组|
|`--reference=reffile`|把目标文件的用户组设置成和参考文件 reffile 的用户组一致|
 案例

```
sudo chgrp alvin file.txt                # 修改 file.txt 的所属组为 alvin
sudo chgrp -v alvin file.txt             # 修改组，并打印执行详情
sudo chgrp --reference=reffile.txt file.txt # 参照 reffile.txt 的用户组设置 file.txt
sudo chgrp -R alvin dir                  # 递归修改 dir 目录下全部内容的用户组
```
📌 面试重点

1. chgrp 只改**用户组**，不能修改文件属主；`chown` 可以同时改属主 + 属组。
2. 权限：修改文件所属组一般需要 root/sudo。
3. `-R` 递归：目录操作常用，注意不要对 `/` 递归操作，会破坏系统权限。
4. 查看所属组：`ls -l` 的第 4 列。

> 一句话区分：
> 
> - chown：属主 + 属组
> - chgrp：仅属组
> - chmod：仅 rwx 权限

##### chmod 命令详解

**作用：修改文件 / 目录的 rwx 访问权限；只有文件属主或 root 可以执行** 语法：

```
chmod [OPTION]... MODE[,MODE]... FILE...
chmod [OPTION]... OCTAL-MODE FILE...
chmod [OPTION]... --reference=RFILE FILE...
```

 两种权限写法：符号模式 & 数字（八进制）模式

 1. 符号模式 `[ugoa][+-=][rwx]`

- 对象
    - `u` user：文件属主
    - `g` group：所属用户组
    - `o` others：其他用户
    - `a` all：全部用户（等价 ugo）
- 操作符
    - `+`：增加权限
    - `-`：移除权限
    - `=`：直接设置权限，清空原有权限
- 权限位
    - `r` 读 (4)
    - `w` 写 (2)
    - `x` 执行 (1)

 2. 数字模式（八进制，面试重点）

r=4，w=2，x=1；三组分别对应 u g o 示例：

- 7 = 4+2+1 → rwx
- 6 = 4+2 → rw-
- 5 = 4+1 → r-x
- 4 = 4 → r--

表格

|权限|数字|
|---|---|
|rwx|7|
|rw-|6|
|r-x|5|
|r--|4|
|---|0|
参数

- `-R`：递归修改目录及其所有子文件、子目录权限

 案例

```
chmod a+r file.txt          # 所有用户增加读权限
chmod -R a+r *              # 递归当前目录所有文件，全部增加读权限
chmod u+x file.txt          # 给属主增加执行权限
chmod ug+w,o-w file.txt     # 属主、组增加写；其他人移除写权限
chmod a+r,a+w,a+x file.txt  # 所有人可读可写可执行
chmod 777 file.txt          # u=rwx,g=rwx,o=rwx（全部权限）
chmod 755 file.txt          # u=rwx,g=r-x,o=r-x（常用目录/程序权限）
chmod u=rw,go= file.txt     # 属主rw；组和其他用户无任何权限
```
 📌 面试重点

1. **文件 vs 目录 x 权限含义不一样**
    - 文件 x：代表可以运行这个程序脚本
    - 目录 x：代表**可以进入目录、访问目录内文件**，只有 r 没有 x，只能看文件名，无法读取文件内容
2. 权限修改对象：`chmod` 改 rwx 权限；`chown/chgrp` 修改归属，不要混淆。
3. 777 尽量不要随便用，安全风险高；web 项目常用 755 (目录)、644 (普通文件)。
4. `--reference=ref.txt target.txt`：把 target 权限设置和 ref.txt 完全一致。

> 快速记忆：
> 
> - 文件推荐：644（rw-r--r--）
> - 目录 / 脚本推荐：755（rwxr-xr-x）



### 文本处理
#### 文件内容处理
##### wc 
**作用：统计文本信息（行数、单词数、字节、字符、最长行长度）** 语法：

```
wc [OPTION]... [FILE]...
```
参数

|参数|作用|
|---|---|
|`-l` / `--lines`|统计行数|
|`-w` / `--words`|统计单词，单词以空格 / 制表符 / 换行分隔|
|`-c` / `--bytes`|统计字节数|
|`-m` / `--chars`|统计字符数（中文一个字符占多个字节，和 `-c` 有区别）|
|`-L`|输出文件中**最长一行**的字符长度|
 案例

```
wc file.txt                # 默认输出：行数 单词数 字节数
wc -w file.txt             # 统计单词数量
wc -m file.txt             # 统计字符数量
wc -c file.txt             # 统计字节数量
wc -l file.txt             # 统计行数
wc -L file.txt             # 获取最长行的长度
cat file.txt | wc -l       # 管道方式统计文本行数（面试高频）
```
 📌 面试重点

1. **`-c`字节 vs `-m`字符**：UTF-8 中文，1 个汉字 = 3 字节，`-c`统计字节，`-m`统计字符个数。
2. 管道用法：`cat xxx | wc -l`，也常搭配 `grep` 统计匹配行数：`grep "abc" test.txt | wc -l`，统计匹配到多少行。
3. wc 默认输出顺序：**行、词、字节**。
4. 统计行数的坑：文件末尾没有换行符时，wc -l 不会计入最后一行。


##### split 

**作用：文件分割，把大文件按行数 / 大小切分成多个小文件** 
语法：
```
split [OPTION]... [FILE [PREFIX]]
```
参数

|参数|作用|
|---|---|
|`-l <行数>`|按行数分割，每 N 行生成一个小文件；简写直接 `-行数`|
|`-b <字节>`|按字节大小分割，支持单位 k (KB)、m (MB)|
|`-d`|使用数字后缀（默认是字母 aa,ab,ac…）|
|`-a <数字>`|指定后缀字符长度，默认是 2 位|
|PREFIX|分割后文件名称前缀|
 案例

```
split -2 file1.txt                     # 每2行切割成1个小文件，默认字母后缀 xaa、xab
split -b 10k file2.txt                 # 每10KB切割一个文件
split -b 10k -d -a 3 file2.txt         # 10KB每份，数字后缀，后缀长度3位：000,001,002
split -b 10k -d -a 3 file2.txt split_file # 指定前缀 split_file，生成 split_file000 split_file001
```
 📌 面试重点

1. 默认后缀是字母 `xaa xab xac`；加 `-d` 才变成数字 `000 001`。
2. `-a` 控制后缀位数，当分片数量很大时，需要加大 `-a`。
3. 合并分割后的文件：`cat split_file* > file2.txt`。
4. 适用场景：超大日志拆分、传输限制（上传附件大小限制）。

> 配套：合并用 `cat`，不需要额外命令。


##### cut 

**作用：从文件 / 管道流中截取文本片段（按字节、字符、分隔字段截取）** 语法：

```
cut OPTION... [FILE]...
```
参数

|参数|作用|
|---|---|
|`-b`|按**字节**截取|
|`-c`|按**字符**截取（中文多字节场景优先用 `-c`）|
|`-d`|自定义字段分隔符，默认是制表符`TAB`|
|`-f`|配合 `-d`，提取指定**字段（列）**|
|`-n`|不分割多字节字符，防止中文乱码，常和 `-b` 一起|
|`--complement`|取反：输出**除选中字段以外**的所有内容|
|`--output-delimiter`|设置输出时字段之间的分隔符|

> 下标写法：
> 
> - `2,4,6`：第 2、4、6 项
> - `2-4`：2 到 4 连续
> - `4-`：第 4 项一直到末尾

 案例

```
cut -f2 file1.txt                  # 提取文件第2列（默认TAB分隔）
cut -f2 --complement file1.txt     # 提取除第2列之外所有列
cut -f2 -d":" file2.txt            # 分隔符为冒号，提取第2列（解析/etc/passwd高频）
cut -b 2-4,6 file3.txt             # 提取第2~4、第6字节
cut -c1-3 file3.txt                # 提取第1～3字符
cut -c2 file3.txt                  # 提取第2个字符
cut -c4- file3.txt                 # 提取第4个字符及后面全部
```
 📌 面试重点

1. **`-d`只能指定单个字符分隔符**，不能支持多字符分隔；多字符分割一般用 `awk`。
2. `/etc/passwd` 经典示例：`cut -d: -f1 /etc/passwd`，提取系统所有用户名。
3. `-b`字节 vs `-c`字符：UTF8 汉字占 3 字节，`-b`容易把汉字截断乱码，中文文本优先 `-c`。
4. `--complement` 取反，面试偶尔会问到。
5. cut 适合简单分列；复杂文本处理优先 awk。

##### paste 

**作用：横向合并多个文件（按行并排拼接，不是上下追加；cat 是上下追加，paste 是左右并排）** 语法：

```
paste [OPTION]... [FILE]...
```
参数

|参数|作用|
|---|---|
|`-d`|指定分隔符，默认是制表符`TAB`|
|`-s`|串行合并：把**单个文件所有行合并成一行**|
|`-`|代表从标准输入读取数据|
 案例

```
paste file1.txt file2.txt                # 左右并排合并两个文件，同行拼接，TAB分隔
paste file2.txt file1.txt                # 文件顺序不同，输出结果不同
paste file1.txt file2.txt file3.txt      # 同时横向拼接3个文件
paste -d":" file1.txt file2.txt          # 使用冒号作为拼接分隔符
paste -d":" -s file1.txt file2.txt       # -s：每个文件内部多行合并为一行，文件之间用冒号分隔
ls | paste -d" " - - - -                 # 管道读取输入，每行输出4个文件名（4个减号代表4列）
```
 📌 面试重点

1. **paste vs cat（高频区分）**
    - `cat a.txt b.txt`：**纵向拼接**，b 的内容追加在 a 的末尾（上下）
    - `paste a.txt b.txt`：**横向拼接**，a 的第 1 行和 b 的第 1 行拼在一起（左右）
2. `-s`：不是多文件横向拼，而是**单个文件多行压缩成一行**。
3. `-` 代表 stdin，`ls | paste - -` 常用来把单列输出转为双列。
4. 分隔符 `-d` 只支持单个字符。

> 小例子： file1： a b file2： 1 2 paste file1 file2 → `a\t1`，`b\t2`


##### sort 

**作用：对文本文件内容进行排序** 语法：

```
sort [参数] 文件
```

参数

|参数|作用|
|---|---|
|`-n`|按**数值大小**排序（不加 - n 默认按字符字典序，会出现 10 排在 2 前面）|
|`-t <分隔符>`|指定字段分隔符|
|`-k`|指定用第几列（栏位）排序|
|`-r`|反向（降序）排序|
 案例

```
sort file1.txt                # 默认按字母字典序升序排序
sort -r file1.txt             # 反向（降序）排序
sort -n file2.txt             # 按数字大小升序排序
sort -t: -k3 -n file3.txt     # 分隔符为冒号，取第3列，按数字排序（经典：/etc/passwd 按UID排序）
```
 📌 面试重点

1. **字典序 vs 数值序（高频坑）**
    - 不加 `-n`：`10` < `2`，因为逐字符比较 `'1' < '2'`
    - 加 `-n`：按真实数字大小，`2 < 10`
2. `-k` 可以写范围：`-k2,3` 代表从第 2 列开始到第 3 列作为排序 key
3. `-o file`：把排序结果写入文件（可以原地覆盖原文件 `sort file.txt -o file.txt`，重定向 `>` 原地写会清空文件）
4. 组合：`sort -t: -k3 -nr /etc/passwd` 按 UID 数字降序排列

> 扩展：`sort -u` 去重，等价 sort + uniq


##### uniq 

**作用：去除连续重复行；只对相邻重复行生效（面试高频坑点）** 语法：

```
uniq [OPTION]... [INPUT [OUTPUT]]
```

 参数

|参数|作用|
|---|---|
|`-c`|在每行开头打印该行出现的次数|
|`-d`|只显示存在重复的行，每组重复行只输出 1 次|
|`-u`|只显示没有重复、唯一的行|
 案例

```
uniq file.txt        # 删除**连续**的重复行，非连续重复不会去除
uniq -c file.txt     # 统计每行出现次数
uniq -d file.txt     # 只输出有重复的记录，每种重复行只展示一次
uniq -u file.txt     # 只输出只出现一次的行
```
📌 面试重点

1. **uniq 只能去连续重复！** 如果重复行分散在文件各处，必须先 `sort` 排序，再管道交给 uniq：

```
sort file.txt | uniq       # 全局去重（最常用组合）
sort file.txt | uniq -c    # 全局统计每行出现次数
```

2. 区分：
    - `-c`：计数，所有行都输出，前面带次数
    - `-d`：只保留重复行
    - `-u`：只保留不重复行
3. 场景：日志统计、统计 IP 访问次数。

示例： 原始文本

```
apple
apple
banana
apple
```

直接 `uniq` 结果：

```
apple
banana
apple
```

> 第三行的 apple 和第四行不相邻，不会被去重。

##### diff /patch 

**作用：diff 对比两个文件差异；patch 使用 diff 生成的补丁文件更新原文件** 语法：

```
diff [OPTION]... FILES
```
 参数

|参数|作用|
|---|---|
|`-y`|并列左右分栏显示异同|
|`-c`|上下文格式，输出全部内容并标记差异|
|`-u`|统一格式（最常用，补丁首选）|
|`-W`|搭配 `-y`，设置并列显示的宽度|
diff 标记含义

- `a` add：新增行
- `c` change：内容修改
- `d` delete：删除行
- `|` 两个文件该行内容不同
- `<` 后面文件比前面文件**少 1 行**
- `>` 后面文件比前面文件**多 1 行**
- `+` 后者相比前者新增一行（`-u`格式）
- `-` 后者相比前者删除一行（`-u`格式）
- `!` 两行内容存在差别（`-y`并列模式）
 案例

```
diff file1.txt file2.txt                # 比较两个文件，默认输出
diff -y -W 50 file1.txt file2.txt       # 左右并列输出，宽度50字符
diff -c file1.txt file2.txt             # 上下文格式输出差异
diff -u file1.txt file2.txt             # 统一格式输出（推荐做补丁）
diff file1.txt file2.txt > file.patch   # 将差异保存为补丁文件
patch file1.txt file.patch              # 给file1打补丁，更新成file2内容
```
📌 面试重点

1. `-u` 统一格式是开发最常用，可读性强，git 底层 diff 也是类似思路。
2. patch 回滚：打补丁时加 `-R` 可以撤销补丁：`patch -R file1.txt file.patch`
3. 对比目录：`diff -r dir1 dir2` 递归对比目录内所有文件。
4. 注意：diff 是**按行对比文本**，二进制文件默认无法对比。


##### join 

**作用：按关键字段连接两个文件（类似数据库内连接，前提：文件必须提前按匹配字段排序）** 语法：

```
join [OPTION]... FILE1 FILE2
```
 参数

|参数|作用|
|---|---|
|`-a1` / `-a2`|`-a1`：输出文件 1 全部行（匹配 + 不匹配）；`-a2`：输出文件 2 全部行；`-a1 -a2` 全连接|
|`-o`|指定输出字段格式，写法 `1.2` 代表文件 1 第 2 列|
|`-t`|设置字段分隔符|
|`-v1` / `-v2`|不输出共同匹配行；`-v1` 只输出文件 1 独有的行；`-v2` 只输出文件 2 独有的行|
|`-j`|指定用来匹配的列，`-j 2` 代表两个文件都用第 2 列做关联 key|
 案例

```
join file1.txt file2.txt                # 默认：以第1列为key，内连接，只输出匹配行
join -a1 file1.txt file2.txt            # 左连接：保留文件1全部记录
join -a2 file1.txt file2.txt            # 右连接：保留文件2全部记录
join -a1 -a2 file1.txt file2.txt        # 全连接：两边所有记录都展示
join -o 1.2 1.3 2.3 file1.txt file2.txt # 指定输出：文件1第2、3列 + 文件2第3列
join -t ':' file1.txt file2.txt         # 指定分隔符为冒号
join -v1 file1.txt file2.txt            # 只输出文件1独有、无法匹配的行
join -j 2 file1.txt file2.txt           # 使用两个文件的第2列作为匹配关键字段
```
 📌 面试重点

1. **硬性前提：两个文件必须先按匹配字段 sort 排序，否则 join 结果会出错！**

```
sort file1.txt > s1.txt
sort file2.txt > s2.txt
join s1.txt s2.txt
```

1. 本质：文本版 SQL join，默认是**内连接**，只输出两边 key 相同的行。
2. `-v` 和 `-a` 的区别：
    - `-a`：保留全部行，**同时包含匹配行**
    - `-v`：只保留不匹配行，**过滤掉匹配行**


##### tr 

**作用：字符转换、删除、压缩重复字符；只处理标准输入，不直接操作文件** 语法：

```
tr [OPTION]... SET1 [SET2]
```

|参数|作用|
|---|---|
|`-c`|反选字符集：对**不在 SET1**里的字符做处理|
|`-d`|删除 SET1 中匹配到的所有字符|
|`-s`|压缩连续重复字符，只保留 1 个|

> 字符类：`[:lower:]`小写、`[:upper:]`大写、`[:digit:]`数字等
 案例

```
# 大小写转换
tr "[a-z]" "[A-Z]" < file.txt
cat file.txt | tr a-z A-Z
echo "hello world" | tr [:lower:] [:upper:]
echo "Hello World" | tr '[A-Za-z]' '[a-zA-Z]'  # 大小写互换

# 删除字符
echo "abcABdefCD" | tr -d "[a-z]"         # 删除小写字母
echo "abc123def888hello" | tr -d 0-9      # 删除数字
echo " Hello World " | tr -d '[ \t]'      # 删除空格和tab
echo -e "abc123*\ndef888" | tr -d -c '0-9\n' # 只保留数字和换行（-c反选）

# 压缩连续重复字符
echo -e "\n\nn2\n\nn\nn3" | tr -s '\n'    # 压缩连续空行
echo "Hellooo  Linuxxxxxx" | tr -s "[xo]" # 压缩连续x、o为单个
echo "2022  05  16" | tr -s ' ' '-'       # 多个连续空格合并并替换成-
echo -e "hello\tworld" | tr '\t' ' '      # tab转为空格
```
📌 面试重点

1. tr **不能直接跟文件名作为输入**，要用管道`|`或者重定向`<`
2. `-s`：压缩，不是删除；把一串连续相同字符缩成 1 个
3. `-d`：直接删掉匹配字符；`-d -c` 组合常用于**保留指定字符**
4. 适用场景：日志清洗、字符格式化、批量替换简单字符；**tr 不支持正则表达式**（这点常考，复杂替换用 sed）

##### sed 
**作用：流式文本编辑器，批量编辑文本，常用于增删改查文本行，支持正则** 语法：

```
sed [选项] [动作] 文件名
```

|参数|作用|
|---|---|
|`-n`|只输出经过 sed 处理匹配到的行（默认会输出全部）|
|`-e`|执行多个脚本表达式，多个编辑动作|
|`-i`|**直接修改原文件**，生产慎用，建议先不带 - i 预览|
 动作指令

|指令|含义|
|---|---|
|`a`|append：在指定行**后面新增一行**|
|`c`|change：整行替换|
|`d`|delete：删除行|
|`i`|insert：在指定行**前面插入一行**|
|`p`|print：打印输出，一般搭配 `-n` 使用|
|`s`|substitute：字符串替换，格式 `s/旧/新/g`；`g`= 全局替换|
案例

```
# 输出内容
sed -n '2p' file.txt           # 仅输出第2行
sed -n '3,5p' file.txt         # 输出3~5行
sed -n '/an/p' file.txt        # 搜索包含an关键字的行并打印

# 删除内容
sed '2,4d' file.txt            # 删除第2-4行（只输出结果，不改原文件）
sed '/an/d' file.txt           # 删除包含an关键字的行

# 新增/插入/整行替换
sed '2a nice' file.txt         # 在第2行后面追加 nice
sed '2i 123456789' file.txt    # 在第2行前面插入一行
sed '2c asdfgh' file.txt       # 替换第2行整行内容
sed '2,5c data changed' file.txt # 2~5行全部替换成这一行

# 字符串替换
sed 's/liangxu/alvin/g' file.txt # 全局替换，liangxu → alvin
sed '3s/liangxu/alvin/g' file.txt# 只替换第3行
sed -e 's/liangxu/alvin/g;s/a/b/g' file.txt # 多个替换条件
sed -i 's/liangxu/alvin/g' file.txt # -i 直接写入原文件，修改磁盘文件
```
📌 面试重点

1. `-i` 危险：直接修改源文件；测试时**先去掉 - i 预览**，确认无误再加`-i`。可以备份：`sed -i.bak 's/xx/yy/g' file.txt`，自动生成`file.txt.bak`备份。
2. `s///g`：末尾`g`代表**当前行全局替换**；不加 g 只替换每行第一个匹配。
3. 寻址：数字指定行号；`/关键词/`正则匹配行；`3,5`范围。
4. 单引号包裹脚本，防止 shell 解析特殊字符。

##### awk 
**作用：文本 / 数据处理编程语言，按行、按列解析文本，适合格式化输出、统计、过滤，支持变量、判断、循环** 语法：

```
awk '条件1 {动作1} 条件2 {动作2} ...' file.txt
```

|参数|作用|
|---|---|
|`-F`|指定输入字段分隔符|
|`-v`|自定义变量|
|`-f`|从脚本文件读取 awk 代码|
|`-m`|对值设置内存限制|
内置变量

|变量|含义|
|---|---|
|`ARGC`|命令行参数个数|
|`ARGV`|命令行参数数组|
|`ENVIRON`|读取系统环境变量|
|`FILENAME`|当前正在处理的文件名|
|`FNR`|当前文件的行号（多个文件时会重置）|
|`FS`|输入字段分隔符，等价 `-F`|
|`NF`|当前行的字段总数（列数）|
|`NR`|已读取的总行数（多个文件持续累加，不重置）|
|`OFS`|输出字段分隔符|
|`ORS`|输出记录分隔符|
|`RS`|输入记录分隔符（默认换行）|
案例

```
df -h | awk '{print $1 "\t" $3}'                  # 打印第1列、第3列
awk -F: '{print $1 "\t" $3}' /etc/passwd          # 分隔符冒号，输出用户名、UID
awk -F: '$3>=500' /etc/passwd                     # 过滤UID大于等于500的行
awk -F: '/liangxu/' /etc/passwd                   # 匹配包含liangxu的所有行
awk -F: '/liangxu/{print $7}' /etc/passwd         # 匹配liangxu，输出第7列shell
head /etc/passwd | awk -F: 'BEGIN{print "name\tuid"} {print $1 "\t" $3} END{print "from file /etc/passwd"}'
# BEGIN 开头预处理；END全部行处理完之后执行
```
📌 面试重点

1. `$0` 代表**整行文本**；`$1 $2 ... $NF` 代表第 1、2、最后一列。
2. `BEGIN{}`：读取文件**之前**执行（一般用来打印表头、初始化变量）；`END{}`：全部读取完成**之后**执行（汇总统计）。
3. `NR` vs `FNR`：单文件下两者一样；**多文件处理时，NR 持续累加，FNR 每个文件重新从 1 开始**，高频面试题。
4. 支持数学运算、if 判断、for 循环，适合日志统计、流量计数。
5. `-F` 可以写正则分隔符，例如 `-F "[,;]"` 用逗号或分号分割。

> 简单替换优先 tr/sed；**按列提取、统计、数值判断优先 awk**。



#### 查找文本内容
##### grep 
**作用：文本搜索工具，查找匹配正则 / 字符串的行** 语法：

```
grep [参数] [匹配内容] 文件
```

|参数|作用|
|---|---|
|`-i`|忽略大小写|
|`-c`|只输出匹配行的数量，不输出内容|
|`-l`|只列出**匹配的文件名**，不打印匹配行|
|`-n`|输出匹配行，同时显示行号|
|`-h`|多文件查找时，**不显示文件名**|
|`-s`|屏蔽文件不存在、无匹配的错误信息|
|`-v`|反向匹配，输出**不包含**关键词的行|
|`-w`|整词匹配（单词完全一致，部分匹配不算）|
|`-x`|整行完全匹配|
|`-r`|递归搜索目录及其子目录|
|`-q`|静默模式，无任何输出；依靠退出码判断结果：0 = 找到，1 = 未找到，脚本常用|
|`-b`|打印匹配内容距离文件开头的字节偏移量|
|`-o`|只打印**匹配到的字符串本身**，而不是整行|
|`-F`|把匹配内容当成固定字符串，**不解析正则**（等价 fgrep）|
|`-E`|支持扩展正则表达式（等价 egrep）|
 案例

```
grep liangxu /etc/passwd                    # 在单个文件搜索关键词
grep liangxu /etc/passwd /etc/shadow        # 在多个文件搜索关键词
grep -h liangxu /etc/passwd /etc/shadow     # 多文件搜索，不显示文件名
grep -rl hello *                            # 递归搜索目录，只输出匹配的文件名
grep -c root /etc/passwd /etc/shadow        # 统计匹配行数量
grep -i LIANGXU /etc/passwd                 # 忽略大小写搜索
grep -n liangxu /etc/passwd                 # 搜索并显示行号
grep -v liangxu /etc/passwd                 # 反向查找，输出不包含关键词的行
grep -l hello *                             # 只输出存在匹配内容的文件名
grep -x hello file1.txt                     # 整行精准匹配
grep -q hello file1.txt                     # 静默查找，脚本判断用
```
📌 面试重点

1. `grep -q`：脚本里最常用，`if grep -q "xxx" file; then ...`，只看返回码，不输出内容。
2. `-o`：只提取匹配字符串，常用来提取数字、关键字。
3. `-r`：递归检索目录；`-rl` 组合：递归 + 只输出文件名，排查日志很常用。
4. `-F`：不需要正则的时候用，避免 `.*[]()` 等特殊字符被解析。
5. 三兄弟区分：
    - `grep`：基础正则
    - `grep -E` / `egrep`：扩展正则（`+ ? | ()` 不用转义）
    - `grep -F` / `fgrep`：纯字符串，关闭正则

> 组合使用高频：`grep -rn "keyword" ./` 递归当前目录搜索关键词 + 行号。

##### egrep

**作用：查找字符串，支持扩展正则表达式；等价于 `grep -E`** 语法：

```
egrep [参数] [匹配模式] [文件]
```

> 参数：和 grep 完全一致（`-i/-n/-v/-r/-o` 等通用）

 扩展正则元字符（egrep 不用反斜杠转义）

|符号|含义| |
|---|---|---|
|`+`|前面字符 / 分组，**1 次或多次**||
|`|`|或，多条件任选其一|
|`()`|分组，把多个字符当成整体||
|`?`|前面单元出现 0 次或 1 次||
|`{m}`|前面单元**连续 m 次**||
|`[]`|字符集，匹配括号内任意单个字符||
|`^`|行开头；`$` 行结尾||


 案例

```
egrep 'a+' file.txt                # 查找包含1个及以上连续a的行
egrep 'linux|666' file.txt         # 查找包含 linux 或者 666 的行
egrep '(linux)' file.txt           # 分组匹配 linux 整体
egrep '(linux)+' file.txt          # 匹配1次或多次连续linux
egrep '^#' file.txt                # 查找以 # 开头的行（注释行）
egrep 'linux$' file.txt            # 查找以 linux 结尾的行
egrep '(ab){3}' file.txt           # 查找连续出现3次ab：ababab
egrep 'ab[cd]' file.txt            # 匹配 abc 或者 abd
```

📌 面试重点
1. `egrep = grep -E`，生产推荐写 `grep -E`，可移植性更好；egrep 是历史别名。
2. 基础 grep（不带 - E）使用 `+ | () {}` 时**需要加反斜杠转义** `\+ \| \(\)`，egrep 不需要，写正则更简洁。
3. 边界：`^` 行首，`$`行尾，常用于过滤配置文件空行、注释行。 示例：过滤配置文件非空且非注释行：`egrep -v '^$|^#' /etc/profile`

#### 查看文本内容
##### cat 命令详解

**作用：读取文件内容并输出到终端；常用于查看小文件、拼接文件、配合重定向创建 / 覆盖文件** 语法：

```
cat [OPTION]... [FILE]...
```

|参数|作用|
|---|---|
|`-n`|显示行号，**空行也会编号**|
|`-s`|压缩连续多个空行，只保留 1 个空行（去除重复空行）|
|`-b`|显示行号，**空行不编号**|
|`-E`|在每行末尾显示 `$` 符号，用来判断行尾隐藏字符|
|`-T`|将 Tab 制表符显示为 `^I`，区分空格与 Tab|
 案例

```
cat file.txt                     # 查看单个文件内容
cat file1.txt file2.txt          # 查看多个文件，顺序输出
cat -n file.txt                  # 查看文件并显示行号（空行编号）
cat -s file.txt                  # 去除连续重复空行

# 重定向
cat file.txt > file1.txt         # 覆盖输出；不存在则新建，存在直接清空写入
cat file.txt >> file1.txt        # 追加输出；内容写到文件末尾，不覆盖原有内容
cat file1.txt file2.txt > combinedfile.txt # 合并多个文件到新文件

cat > file.txt                   # 新建文件，键盘输入内容；输入完成按 Ctrl+D 保存退出
```
📌 面试重点

1. cat 适合**小文件**；大文件不要用 cat 直接刷屏，改用 `less/more`。
2. `>` 覆盖，`>>` 追加，高频笔试题。
3. `-n` vs `-b`：最常考区别：`-n` 空行也带行号；`-b` 只给非空行编号。
4. `cat > file.txt` 是利用标准输入创建文件；`cat >> file.txt` 追加录入。
5. 管道经典组合：`cat file.txt | grep xxx`（不过很多时候可以直接 `grep xxx file.txt`，少一层进程）。

##### more 
**作用：分页查看文本文件，只支持向下浏览，不能回滚（老牌分页工具）** 语法：

```
more [options] file...
```
基本操作快捷键

- 回车：向下滚动**一行**
- 空格：向下翻**一整页**

 参数

|参数|作用|
|---|---|
|`-num`|指定每页显示多少行|
|`+num`|从第 num 行开始显示文件|
|`-p`|先清屏，再展示剩余文本|
|`-c`|和 - p 类似，不滚屏；先显示新内容再清除旧内容|
|`-s`|多个连续空行压缩为一行展示|
案例

```
more ~/.bashrc                  # 分页查看 .bashrc
more -c -10 ~/.bashrc           # 清屏模式，每页10行
more -s ~/.bashrc               # 压缩连续空行为一行
more +10 ~/.bashrc              # 从第10行开始分页查看
```
📌 面试重点

1. **more 只能往下翻，不能向上回退**；`less` 是升级版，支持上下滚动、搜索，工作中优先用 less。
2. 管道联用示例：`cat /var/log/messages | more` 分页输出命令结果。
3. 退出：按 `q` 退出 more。


##### less

**作用：分页查看文本，more 的增强版；支持上下滚动、搜索、多文件浏览，生产环境首选** 语法：

```
less [参数] 文件
```
快捷操作

|按键|功能|
|---|---|
|空格|下翻一页|
|回车|下滚一行|
|j|下滚一行|
|k|上滚一行|
|b|回翻一页|
|f|下翻一页|
|q|退出 less|
|`/word`|向下搜索 word 关键词；`n`下一个匹配，`N`上一个匹配|

> 多文件内部切换：
> 
> - `:n` 浏览下一个文件
> - `:p` 浏览前一个文件
案例

```
less ~/.bashrc                     # 分页查看单个文件
less ~/.bashrc ~/.bash_history     # 同时打开多个文件，内部切换
history | less                     # 把命令输出通过管道交给less分页
```
📌 面试重点

1. `more` 只能向下翻；**less 支持上下双向滚动**，还支持文本搜索，日常看日志优先 less。
2. 日志查看常用：`less /var/log/messages`，搜索关键词 `/error`。
3. 管道组合非常高频：`dmesg | less`、`df -h | less`。
4. 退出按 `q`；搜索 `/关键词`，`n` 跳到下一处匹配。

##### head 

**作用：查看文件开头部分内容，默认输出前 10 行** 语法：

```
head [OPTION]... [FILE]...
```
 参数

| 参数        | 作用                                       |
| --------- | ---------------------------------------- |
| `-n <数字>` | 指定显示行数；数字为负：代表**除去最后 N 行，输出剩下全部内容**      |
| `-c <数字>` | 指定显示头部字符数；数字为负：代表**除去最后 N 个字符，输出剩下全部内容** |
案例

```
head ~/.bashrc                # 默认显示文件前10行
head -n 5 ~/.bashrc           # 显示文件前5行
head -n -6 ~/.bashrc          # 输出文件全部内容，但剔除最后6行
head -c 20 ~/.bashrc          # 显示文件前20个字符
head -c -30 ~/.bashrc         # 输出全部内容，剔除末尾30个字符
```
📌 面试重点

1. 默认：head 不加参数，输出**前 10 行**。
2. `-n 正数`：取开头 N 行；`-n -正数`：去掉末尾 N 行，保留前面所有。
3. `-c` 按字符（字节）截取，不是按行，适合看二进制 / 短文本。
4. 经典管道组合：`ps aux | head -n 5`，查看进程列表前 5 行。

> 配套记忆：head 看**头部**，接下来就是 tail 看**尾部**。


##### tail 

**作用：查看文件尾部内容，日志排查高频命令；默认输出最后 10 行** 语法：

```
tail [OPTION]... [FILE]...
```
 参数

|参数|作用|
|---|---|
|`-c N`|输出文件尾部 N 个字节内容|
|`-f`|实时跟踪，持续显示文件新追加内容（看日志神器）|
|`-n N`|输出文件尾部 N 行内容|
案例

```
tail file.txt                # 默认显示文件最后10行
tail -n 20 file.txt          # 显示文件最后20行
tail +20 file.txt            # 从文件第20行开始，一直显示到末尾
tail -c 10 file.txt          # 显示文件最后10个字符
tail -f file.txt             # 动态实时跟踪文件末尾新增内容
```
📌 面试重点

1. 默认输出**最后 10 行**；`tail -f` 是线上查看实时日志最常用。
2. `tail +20`：**+ 号代表从第 20 行开始往后全部输出**，和 head `-n -6` 容易混淆。
3. 生产常用组合：`tail -f /var/log/messages | grep error`，实时过滤日志关键词。
4. 退出 `tail -f`：按 `Ctrl + C`。
5. 拓展：`tail -F` 比 `-f` 更强，文件被删除重建后依然可以跟踪日志。

head + tail 组合示例：取文件第 10~20 行

```
head -n 20 file.txt | tail -n 11
```


##### tac 

**作用：反向显示文件内容（cat 的倒序版本，cat 从上到下，tac 从下到上输出）** 语法：

```
tac [参数] [文件]
```
 案例

```
tac file.txt          # 将文件行顺序反转，最后一行最先输出，第一行最后输出
```
📌 面试重点

1. 名字记忆：`cat` 正向，`tac` 就是 cat 反过来写，功能也是反向输出行。
2. 适用场景：日志文件从末尾往前检索，不想用 tail 多次翻页。
3. 管道联用示例：`tac /var/log/messages | grep error`，倒序查找日志，优先看到最新报错。
4. 原理：默认以换行符作为行分隔符；可以用 `-s` 指定自定义分隔符。

> 小例子： file.txt：
> 
```
line1
 line2
 line3
```
`tac file.txt` 输出：

```
line3
line2
line1
```

##### nl 

**作用：给文件内容添加行号并输出（和 `cat -n` 类似，但行号格式控制更丰富）** 语法：

```
nl [OPTION]... [FILE]...
```
 参数

|参数|说明|
|---|---|
|`-b a`|所有行（包含空行）都添加行号，等价 `cat -n`|
|`-b t`|默认值，**空行不显示行号**|
|`-n ln`|行号靠左对齐|
|`-n rn`|行号右对齐，前面不补 0|
|`-n rz`|行号右对齐，前面补 0 填充|
|`-w`|设置行号栏占用宽度|
 案例

```
nl file.txt                      # 列出file.txt内容，空行不编号（默认）
nl -b a file.txt                 # 列出内容，空行也加上行号
nl -b a -n rz file.txt           # 空行编号，行号右对齐并补0
nl -b a -n rz -w 3 file.txt      # 行号栏宽度设为3位，补0对齐
nl -b t file.txt                 # 空行不显示行号
```
📌 面试重点

1. `nl` 默认：**空行不加行号**；`cat -n` 空行会加行号，这是二者核心区别。
2. `-n rz` 格式化输出，打印脚本、配置清单时，行号等宽整齐。
3. 管道用法示例：`ps aux | nl`，给进程列表加上行号。

###  网络工具
#### **网络操作**
##### host 

`host` 是 Linux 下 **DNS 域名查询工具**，用来解析域名、查看 DNS 记录。

 作用 :域名查询（域名 ↔ IP 解析，查询 DNS 记录）
语法

```
host [参数] [域名]
```
参数

- `-a`：显示详细的 DNS 信息（相当于查询所有类型 DNS 记录）
- `-v`：显示指令执行的详细信息（verbose，打印查询全过程）
案例
1. `host www.baidu.com` 查询域名对应的 IP 地址（最简用法）
2. `host -v www.baidu.com` 显示域名查询执行的详细过程信息
3. `host -a www.baidu.com` 查询该域名全部详细 DNS 记录信息
补充小知识点（面试常用）

- 和`nslookup`功能类似，host 输出更简洁；
- 底层都是向 DNS 服务器发送 DNS 请求；
- 可以反向解析：`host IP`，通过 IP 查域名。

##### tcpdump 

**作用：抓包工具，监视网络流量，捕获网卡数据包，网络排错必备；需要 root 权限** 语法：

```
tcpdump [参数] [过滤表达式]
```
 常用参数

|参数|说明|
|---|---|
|`-i`|指定网卡，`-i any` 监听所有网卡|
|`-c N`|捕获 N 个包之后自动停止|
|`-q`|精简输出模式，信息简短|
|`-A`|以 ASCII 文本打印数据包内容（查看明文）|
过滤表达式

- `host x.x.x.x`：过滤指定主机 IP / 域名
- `port 22`：过滤指定端口
- 支持组合：`and`、`or`、`not`
 案例

```
tcpdump                     # 监视第一个网卡上所有流过的数据包（root）
tcpdump -i ens33            # 监视ens33网卡数据包
tcpdump -c 20               # 捕获20个包就退出
tcpdump -c 10 -q            # 精简模式捕获10个包
tcpdump host www.baidu.com  # 捕获和百度主机通信的包
tcpdump host 192.168.107.133 # 捕获和192.168.107.133通信的包
tcpdump -i any port 22 -A   # 监听所有网卡22端口，文本形式展示包内容
```
📌 面试重点

1. **必须 root 权限**才能抓包；不加 `-i` 默认选用编号最小的网卡。
2. 过滤语法：host /port/src /dst 可以组合，例如：

```
tcpdump -i ens33 src 192.168.1.100 and port 80
```

3. `-w xxx.pcap`：把数据包保存成文件，后续可用 wireshark 打开分析（高频考点）

```
tcpdump -i ens33 -w test.pcap
```

4. `-r test.pcap`：读取 pcap 抓包文件。
5. 终止抓包：`Ctrl + C`。

> 对比记忆：tcpdump 命令行抓包；Wireshark 图形化分析 pcap 文件。


##### nc（netcat）

**作用：网络瑞士军刀，端口扫描、端口监听、TCP/UDP 连接测试、数据传输；图上标注 “设置路由器” 不准确，nc 核心是网络读写** 语法：

```
nc [参数] IP/主机名 端口
```
常用参数

|参数|说明|
|---|---|
|`-v`|verbose，显示执行详细过程|
|`-w N`|设置连接超时秒数|
|`-z`|零 IO 模式，**仅端口扫描，不传输数据**|
|`-n`|直接使用 IP，不做 DNS 域名解析|
|`-u`|使用 UDP 协议（默认 TCP）|
|`-l`|listen 监听模式，作为服务端等待接入|
 案例

```
nc -v -z -w2 192.168.107.133 1-100        # 扫描指定IP TCP端口 1~100，超时2秒
nc -u -z -w2 192.168.107.133 1-100        # 扫描指定IP UDP端口 1~100
nc -nvv 192.168.107.133 22                # 单独扫描22端口，详细输出
nc -l 1234                                # 本机监听1234端口（服务端）
nc 192.168.107.133 1234                   # 客户端连接目标1234端口
```
📌 面试重点

1. 两大核心用途：**端口连通性测试、端口监听**；`-z` 只用于端口扫描。
2. TCP/UDP 区分：不带 `-u` = TCP；加 `-u` = UDP。
3. 简易文件传输示例：

```
# 接收端（监听）
nc -l 1234 > recv.txt
# 发送端
nc 192.168.107.133 1234 < send.txt
```

4. 注意：部分系统新版 nc 不支持 `-z` 端口扫描。
5. 关闭：`Ctrl + C`


#### 网络路由
##### route 

**作用：查看、添加、删除内核路由表（管理路由），ip route 是现代推荐命令，route 属于老式工具** 语法：

```
route [-f] [-p] [Command [Destination] [mask Netmask] [Gateway] [metric Metric]] [if Interface]
```
 常用参数

|参数|说明|
|---|---|
|`-n`|不做域名解析，直接显示 IP，速度更快（面试高频）|
|`-net`|目标是一个网段|
|`-host`|目标是单个主机|
|`netmask`|指定子网掩码|
|`gw`|指定下一跳网关 IP|
|`dev`|指定从哪个网卡转发（如 ens33、eth0）|
 flag 路由标志位

|flag|含义|
|---|---|
|U|Up，路由启用状态|
|H|Host，目标是单台主机|
|G|Gateway，需要经过网关（路由器）转发|
|R|Reinstate Route，动态路由恢复|
|D|动态写入的路由|
|M|路由被守护进程 / 路由器动态修改|
|!|路由关闭状态|
案例

```
route                                  # 查看路由表（会反向解析域名，慢）
route -n                               # 查看路由表，只显示IP，推荐日常使用
route add -net 224.0.0.0 netmask 240.0.0.0 dev ens33   # 添加网段路由，从ens33网卡出去
route add -net 224.0.0.0 netmask 240.0.0.0 reject      # 添加屏蔽路由，拒绝访问该网段
route del -net 224.0.0.0 netmask 240.0.0.0             # 删除指定网段路由
route del -net 224.0.0.0 netmask 240.0.0.0 reject       # 删除reject屏蔽路由
```
📌 面试重点

1. `route` 是旧版路由命令；现在 Linux 优先使用 `ip route`。
2. `route -n` 一定要记住：排查网络故障必用，省去 DNS 解析延迟。
3. 默认网关：`0.0.0.0` 那条路由，就是默认路由。
4. 添加 / 删除路由需要 root 权限；临时路由重启后失效，永久路由需要修改网卡配置文件。
5. reject 路由：本机收到去往该网段的包直接拒绝返回；常用于黑名单。

> 补充常用：添加默认网关

```
route add default gw 192.168.1.1 dev ens33
```


##### ping 

**作用：基于 ICMP 协议，测试主机之间网络连通性，查看时延、丢包率** 语法：

```
ping [参数] 目标主机
```
 常用参数

| 参数   | 说明                                         |
| ---- | ------------------------------------------ |
| `-c` | 指定发送 ICMP 报文次数，Linux ping 默认无限发包，必须靠`-c`限制 |
| `-i` | 设置报文发送间隔（单位秒，root 可小于 0.2s）                |
| `-s` | 设置数据包的数据部分大小（不含 ICMP 头部）                   |
| `-t` | 设置 TTL（存活时间）                               |
TTL 默认值（面试常考）

- Linux：64 / 255
- Windows NT/2000/XP：128
- Windows 98：32
- UNIX 主机：255

> 注意：TTL 每经过一台路由器会减 1，可粗略判断目标操作系统，但**只能作为参考，可人为修改**。
案例

```
ping www.baidu.com                  # 测试和百度连通性，Linux下会持续发包，Ctrl+C停止
ping -c 4 www.baidu.com             # 发送4个包后自动停止
ping -c 4 -i 3 www.baidu.com        # 发送4个包，包之间间隔3秒
ping 192.168.107.128                # 测试局域网主机连通性
ping -s 1024 -t 255 www.baidu.com   # 数据部分1024字节，TTL=255
```
📌 面试重点

1. ping 使用 **ICMP 协议**，属于网络层；很多防火墙会禁 ICMP，**ping 不通 ≠ 端口不通**。
2. Linux ping 默认持续发包，Windows ping 默认只发 4 个包，这是两者行为差异。
3. TTL 不是目标主机原始值，沿途路由会递减，不能 100% 依靠 TTL 判断系统。
4. 输出指标：`time` 往返时延；`packet loss` 丢包率。

##### ifconfig 

**作用：查看 / 配置网卡网络设备（传统命令，现代 Linux 推荐 ip 命令）** 语法：

```
ifconfig [-v] [-a] [-s] [interface]
ifconfig [-v] interface [aftype] options | address ...
```

常用参数

|参数|说明|
|---|---|
|`add <地址>`|给网卡添加 IPv6 地址|
|`del <地址>`|删除网卡 IPv6 地址|
|`down`|关闭指定网卡|
|`up`|启用指定网卡|
|`IP地址`|设置网卡 IPv4 地址|
案例

```
ifconfig                                 # 显示所有已启用网卡信息
ifconfig eth0 down                       # 关闭eth0网卡
ifconfig eth0 up                         # 启用eth0网卡

# 配置IPv4地址
ifconfig eth0 192.168.1.56
ifconfig eth0 192.168.1.56 netmask 255.255.255.0
ifconfig eth0 192.168.1.56 netmask 255.255.255.0 broadcast 192.168.1.255

# 添加/删除IPv6地址
ifconfig eth0 add 33ffe:3240:800:1005::2/64
ifconfig eth0 del 33ffe:3240:800:1005::2/64

# 修改MAC地址
ifconfig eth0 down
ifconfig eth0 hw ether 00:AA:BB:CC:DD:EE
ifconfig eth0 up

# 开启/关闭ARP协议
ifconfig eth0 arp
ifconfig eth0 -arp

# 设置MTU最大传输单元
ifconfig eth0 mtu 1500
```
📌 面试重点

1. `ifconfig` 属于 net-tools 工具包，很多新版系统默认不预装；**现代标准推荐 ip addr /ip link**。
2. `up/down`：网卡开关；修改 MAC 地址必须先 down 网卡，修改完再 up。
3. MTU：最大数据包，以太网默认 1500 字节。
4. 临时生效：ifconfig 配置 IP、MAC，**重启网卡 / 服务器就失效**；永久配置需要改网卡配置文件。
5. arp：开启后网卡支持地址解析协议；关闭 arp 后该网卡不响应 arp 请求。

##### traceroute

**作用：追踪数据包从本机到目标主机经过的完整路由跳数（路径），排查网络在哪一跳中断 / 延迟高** 语法：

```
traceroute [参数] [域名或者IP]
```
 常用参数

|参数|说明|
|---|---|
|`-m`|设置最大 TTL（最大跳数），超过就停止探测|
|`-n`|只显示 IP，不反向解析域名，速度更快|
|`-p`|指定 UDP 探测端口（traceroute 默认用 UDP）|
|`-q`|每一跳发送探测包数量|
|`-r`|绕过本机路由表，直接发包到远端主机（直连场景）|
|`-w`|设置等待远端响应的超时时间（秒）|
 案例

```
traceroute www.baidu.com          # 追踪本机到百度的传输路径
traceroute -m 7 www.baidu.com     # 最大跳数设置为7
traceroute -n www.baidu.com       # 只显示IP，不解析主机名
traceroute -q 4 www.baidu.com     # 每一跳发送4个探测包
traceroute -w 3 www.baidu.com     # 等待响应超时3秒
traceroute -p 6888 www.baidu.com  # 使用UDP端口6888探测
traceroute -r www.baidu.com       # 绕过路由表直接发包
```
📌 面试重点

1. Linux traceroute 默认使用 **UDP 报文**；Windows 对应的命令 `tracert` 使用 **ICMP**，这个差异经常问到。
2. 原理：从小到大依次设置 TTL（1,2,3…），每经过一跳 TTL 减 1，路由器返回 ICMP 超时包，从而拿到每一跳 IP。
3. 出现 `* * *`：代表该路由器不返回 ICMP 超时报文，无法获取信息，**不代表链路一定断了**。
4. 现代很多系统也提供 `mtr`，结合 ping+traceroute，持续看每一跳丢包，排障更推荐 mtr。
5. 不需要 root（部分版本需要）。

> 小对比：ping 看连通性；traceroute 看路径定位故障节点。



##### ifup /ifdown

**作用：激活 / 禁用网络接口，读取网卡配置文件来启用、关闭网卡（传统工具，现代系统推荐 ip link）** 语法：

```
ifup [网络接口]
ifdown [网络接口]
```
案例

```
sudo ifup ens33     # 启用ens33网卡
sudo ifdown ens33   # 关闭ens33网卡
```
📌 面试重点

1. 需要 root 权限执行；依赖 `/etc/network/interfaces` 网卡配置文件，没有配置文件时无法使用。
2. 新旧差异：在 CentOS7+/Ubuntu20+ 这类使用 NetworkManager 的系统，`ifup/ifdown` 已经逐步弃用，推荐使用：

```
ip link set ens33 up    # 启用网卡
ip link set ens33 down  # 关闭网卡
```

1. 区分：`ifdown` 是**优雅关闭**，会释放 IP、停止相关服务；`ip link down` 直接切断链路。
2. 常见坑：如果网卡是 NM 托管，ifdown 可能失效，要用 `nmcli`。

##### netstat

**作用：显示网络状态，查看端口、TCP/UDP 连接、路由表、网卡统计、进程占用端口（老式工具，现代推荐 ss）** 语法：

```
netstat [参数]
```
常用参数

|参数|说明|
|---|---|
|`-a`|显示所有 Socket，包含监听、已建立连接|
|`-p`|显示占用 Socket 的 PID 与程序名（root 才可以看到全部进程）|
|`-l`|仅列出处于监听状态的服务|
|`-t`|显示 TCP 协议连接|
|`-u`|显示 UDP 协议连接|
|`-i`|显示网卡接口信息|
|`-r`|显示路由表信息|
|`-n`|直接显示 IP 和端口号，不做域名解析，速度更快|
|`-s`|显示各协议收发数据包统计|
|`-x`|显示 Unix 域套接字|
案例

```
netstat -a                  # 显示所有连接信息
netstat -at                 # 显示所有TCP连接
netstat -au                 # 显示所有UDP连接
netstat -p                  # 输出带上PID和进程名称
netstat -l                  # 只显示监听端口
netstat -lt                 # 只列出监听TCP端口
netstat -lu                 # 只列出监听UDP端口
netstat -lx                 # 列出所有监听UNIX域端口
netstat -s                  # 所有端口协议统计信息
netstat -st                 # TCP协议统计
netstat -su                 # UDP协议统计
netstat -apu                # 显示UDP端口+进程信息
netstat -i                  # 网卡状态信息
netstat -r                  # 查看路由表
netstat -ap | grep ssh      # 查找ssh相关连接
```
📌 面试重点

1. netstat 属于**废弃工具**，新版 Linux 默认不装，推荐替代品：`ss`（socket statistics），速度更快、信息更全。
2. `-n` 参数排查网络必用，避免 DNS 反向解析拖慢输出。
3. 查看哪个进程占用端口：`netstat -tlnp`，root 权限才能看到 PID。
4. TCP 常见状态：LISTEN 监听、ESTABLISHED 已建立、TIME_WAIT、CLOSE_WAIT。
5. 管道搭配 grep 过滤端口 / 服务是高频操作。


##### ss

**作用：Socket Statistics，查看套接字 / 网络连接信息，netstat 的现代替代品，性能更强、信息更丰富，是当前 Linux 首选查看端口连接工具** 语法：

```
ss [参数]
```

常用参数

|参数|说明|
|---|---|
|`-n`|不解析服务名称，直接以数字显示 IP 和端口|
|`-a`|显示所有套接字（监听 + 已建立）|
|`-l`|仅显示监听状态套接字|
|`-o`|显示计时器信息|
|`-e`|显示套接字详细信息|
|`-m`|显示套接字内存占用|
|`-p`|显示占用套接字的进程 PID / 程序名（root 看全量）|
|`-i`|显示 TCP 内部详细信息|
|`-s`|套接字整体使用统计概况|
|`-4`|仅展示 IPv4 套接字|
|`-6`|仅展示 IPv6 套接字|
|`-O`|显示 PACKET 套接字|
|`-t`|只显示 TCP 套接字|
|`-u`|只显示 UDP 套接字|
|`-d`|只显示 DCCP 套接字|
|`-w`|只显示 RAW 套接字|
|`-x`|只显示 Unix 域套接字|
|`-D`|将原始 TCP 套接字信息转储到文件|
 案例

```
ss -at                     # 显示TCP套接字
ss -au                     # 显示UDP套接字
ss -s                      # 套接字整体使用概况
ss -l                      # 列出所有打开的监听端口
ss -pl                     # 查看进程使用的socket
ss -lp | grep 6010         # 查找占用6010端口的程序
ss -tnl                    # 查看本机监听端口（最常用组合）
ss -tlr                    # 解析IP和端口号（带域名解析）
```
 📌 面试重点

1. ss 替代 netstat：netstat 读取 `/proc/net/tcp` 遍历所有连接，大量并发时很慢；ss 直接读取内核 tcp_diag 模块，性能远高于 netstat。
2. 高频命令组合：`ss -tnlp` 查看 TCP 监听端口 + 进程，面试排查端口占用必写。
3. 支持过滤语法，可直接过滤状态、IP、端口，无需 grep：例如 `ss state ESTABLISHED`。
4. `-p` 参数：非 root 用户只能看到自己进程的 socket，root 权限才能看到全部进程 PID。
5. TCP 状态同样支持：LISTEN、ESTABLISHED、TIME_WAIT、CLOSE_WAIT 等。


#### 数据传输
##### telnet 

**作用：远程登录服务器；也常用来测试 TCP 端口连通性。明文传输，生产环境禁止用于远程登录，仅用于端口调试** 语法：

```
telnet [参数] [主机] [端口]
```

案例

```
telnet 192.168.107.133          # 登录远程主机（默认23端口）
telnet 192.168.107.133 6379     # 连接指定IP+端口，测试6379端口是否开放
```
📌 面试重点

1. telnet 使用 **TCP**，端口默认 **23**；**所有数据明文传输**，账号密码裸奔，不安全，生产环境远程登录改用 ssh。
2. 核心使用场景现在不是登录，而是**快速验证 TCP 端口通不通**：能连上 = 端口开放；连接超时 / 拒绝 = 端口不通。
3. 局限：只能测 TCP，不能测 UDP；很多新版 Linux 默认不安装 telnet 客户端。
4. 替代工具：`nc`(netcat)，功能更强，可同时测 TCP/UDP 端口。


##### ssh 

**作用：安全远程连接工具，加密传输，替代 telnet，用于远程登录主机、远程执行命令、端口转发等** 语法：

```
ssh [参数] [主机]
```
 常用参数

|参数|说明|
|---|---|
|`-l <登录名>`|指定远程服务器登录用户名|
|`-p <端口>`|指定远程 ssh 服务端口（默认 22）|
配置文件

`/etc/ssh/sshd_config`：sshd 服务端主配置文件（修改后需要重启 sshd 服务生效）

 案例

```
ssh 192.168.0.10                     # 登录远程服务器，使用当前本地用户名
ssh -l liangxu 192.168.0.10          # 以liangxu身份登录远程服务器
ssh liangxu@192.168.0.10             # 等价上面写法，更常用
ssh -p 2222 liangxu@192.168.0.10     # 指定端口2222 + 用户登录
ssh 192.168.0.10 date                # 远程主机上直接执行date命令，执行完返回本地
```
📌 面试重点

1. ssh 默认端口 **22**，基于 TCP，全程加密，对比 telnet 明文，安全性高。
2. 区分：`ssh` 是客户端命令；`sshd` 是服务端进程，负责监听 22 端口。
3. 免密登录原理：ssh-keygen 生成密钥对，公钥放到远端`~/.ssh/authorized_keys`，私钥保存在本地。
4. `/etc/ssh/sshd_config` 常见安全配置：禁止 root 登录、修改默认 22 端口、关闭密码认证只允许密钥登录。
5. 远程执行命令常用于脚本批量运维，不需要交互式 shell。

##### ftp 

**作用：文件传输协议客户端，用于 FTP 服务器文件上传下载；FTP 明文传输，生产环境推荐 sftp 替代** 语法：

```
ftp [参数] [主机名或IP]
```
 常用 ftp 内部命令

|命令|说明|
|---|---|
|help/?|列出所有可用 FTP 内部命令|
|cd|切换远程服务器目录|
|lcd|切换**本地**计算机目录|
|ls|列出远程目录文件|
|mkdir|在远程创建目录|
|pwd|打印远程当前工作目录|
|delete|删除远程文件|
|rmdir|删除远程目录|
|get|单个文件：远程下载到本地|
|mget|批量下载多个远程文件到本地|
|put|单个文件：本地上传到远程|
|mput|批量上传多个本地文件到远程|
 vsftpd 增加 ftp 写权限步骤

1. `sudo gedit /etc/vsftpd.conf`
2. 去除`#write_enable=YES`前面的注释`#`
3. `sudo service vsftpd restart` 重启服务生效
案例

```
sudo apt install vsftpd          # 安装vsftpd服务端
ftp 192.168.107.133              # 建立ftp连接
get file.txt                     # 下载单个文件
mget file1.txt file2.txt         # 下载多个文件
put newfile.txt                  # 上传单个文件
mput newfile1.txt newfile2.txt   # 上传多个文件
bye                              # 退出ftp会话
quit                             # 退出ftp会话
```
📌 面试重点

1. FTP 默认端口：**21 端口（控制连接）**；数据端口主动模式 20。账号密码、数据全部明文传输，不安全。
2. 区分：`ftp`客户端；`vsftpd`是 Linux 常用 FTP 服务端程序。
3. lcd 是容易混淆点：cd 操作远端，lcd 操作本地当前目录。
4. 替代方案：**sftp**，基于 ssh 加密，无需额外开放端口 21，推荐生产使用。
5. mget/mput 批量操作时，默认会逐个询问确认，可以使用`prompt`命令关闭交互确认。

##### lftp 
**作用：功能强大的文件传输客户端，支持 ftp、sftp、http 等多种协议；支持断点续传、目录镜像批量同步** 语法：

```
lftp(选项)(参数)
```
案例

```
lftp liangxu@192.168.107.133        # 登录远程服务器
help / ?                            # 查看lftp内部支持命令
get file.txt                        # 下载单个文件
mget file*.txt                      # 批量下载匹配通配符的文件
mget -c *.txt                       # 批量下载，开启断点续传
mirror dir                          # 将远程dir目录完整下载到本地
put newfile.txt                     # 上传单个文件
mput newfile*.txt                   # 批量上传文件
mirror -R newdir                    # 镜像上传：把本地newdir目录完整上传到远程
bye                                 # 退出lftp会话
exit                                # 退出lftp会话
```
📌 面试重点

1. lftp 是多协议客户端，不仅支持 ftp，**sftp**也可以用，生产常用。
2. `-c`：断点续传参数，网络不稳定场景很实用。
3. `mirror` 是 lftp 王牌命令：不带 - R 是远程→本地下载目录；`mirror -R` 本地→远程上传整个目录，自动递归同步子目录。
4. 对比普通 ftp：原生支持目录递归同步、断点续传、多线程传输，比 ftp 客户端强大很多。
5. 内部交互命令风格和 ftp 很像，cd/lcd/ls/pwd 都通用，上手简单。


##### wget 

**作用：文件下载工具，支持 HTTP/HTTPS/FTP，非交互式，适合脚本里自动下载文件** 语法：

```
wget [option]... [URL]...
```
常用参数

|参数|说明|
|---|---|
|`-i`|下载指定文件里列出的地址（批量下载）|
|`-O`|下载后重命名文件|
|`-c`|开启断点续传|
|`-b`|启动后转入后台执行|
|`-P`|指定文件保存路径|
|`--limit-rate`|限制下载速度|
案例

```
# 下载单个文件
wget https://cn.wordpress.org/latest-zh_CN.zip

# 下载多个文件：先把URL写入urllist.txt，再执行
vim urllist.txt
wget -i urllist.txt

# 下载并重命名为 wp.zip
wget -O wp.zip https://cn.wordpress.org/latest-zh_CN.zip

# 下载保存到 dir 目录
wget -P dir https://cn.wordpress.org/latest-zh_CN.zip

# 限速300k下载
wget --limit-rate=300k https://cn.wordpress.org/latest-zh_CN.zip

# 断点续传下载
wget -c https://cn.wordpress.org/latest-zh_CN.zip

# 后台下载，用tail看日志进度
wget -b https://cn.wordpress.org/latest-zh_CN.zip
tail -f wget-log
```
📌 面试重点

1. wget 不需要交互式会话，很适合写 shell 脚本自动拉取资源。
2. `-c` 断点续传：网络中断后重新执行，接着上次位置继续下，大文件必备。
3. `-O` 大写 O，重命名；小写 `-o` 是输出日志文件，不要记混。
4. `-b` 后台下载，默认日志写入 `wget-log`。
5. 对比 curl：wget 主打下载文件；curl 更灵活，可发送各类 HTTP 请求、上传、获取响应内容。


##### scp

**作用：远程拷贝文件 / 目录，底层基于 SSH 加密传输，用于本地和远程主机之间互传文件** 语法：

```
scp [参数] source ... target
```
常用参数

表格

|参数|说明|
|---|---|
|`-r`|递归复制整个目录（文件夹必须加 - r）|
|`-p`|保留原文件修改时间、访问时间、权限模式|
|`-P`|指定 SSH 端口号（大写 P，默认 22）|
 案例

```
# 从远程复制文件到本地
scp liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~

# 从远程复制目录到本地（-r递归）
scp -r liangxu@192.168.107.128:/home/liangxu/commands/scp/dir/ ~

# 上传本地文件到远程机器指定目录
scp ~/newfile.txt liangxu@192.168.107.128:/home/liangxu/commands/scp/

# 上传本地目录到远程机器指定目录
scp -r ~/newdir liangxu@192.168.107.128:/home/liangxu/commands/scp/

# 指定端口2222传输文件
scp -P 2222 liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~

# 保留文件修改时间、访问时间、权限
scp -p liangxu@192.168.107.128:/home/liangxu/commands/scp/file.txt ~
```
📌 面试重点

1. scp 底层依赖 SSH 协议，**加密传输**，端口默认 22；`-P`大写指定端口，和 ssh 命令`-p`小写区分，容易踩坑。
2. 拷贝目录**必须带 `-r`**，否则会报错。
3. 缺点：scp 是全量复制，每次传输全部文件；大量文件 / 增量同步优先用`rsync`。
4. 方向记忆：`scp 源 目标`，源和目标可以是本地或者远程（`user@ip:路径`代表远端）。
5. 免密：配置 ssh 密钥免密登录后，scp 传输也不需要输入密码，适合脚本自动化。


##### curl

**作用：网络请求 / 文件传输工具，支持 HTTP、HTTPS、FTP 等协议；可发请求、查看响应、上传下载，常用于接口调试** 语法：

```
curl [参数] 网址
```
常用参数

|参数|说明|
|---|---|
|`-o`|指定新的本地文件名保存|
|`-O`|大写 O，自动保留远程文件原始名称|
|`-u`|配置用户名：密码做授权访问|
|`-I`|只打印 HTTP 响应头信息，不下载正文|
|`-A`|设置 User-Agent 用户代理|
|`-b`|设置 cookie 信息|
|`-C`|断点续传|
|`-s`|静默模式，不输出进度、错误信息|
|`-T`|上传文件|
案例

```
# 获取网站网页源码，直接输出到终端
curl www.baidu.com

# 保存网页为 baidu.html
curl -o baidu.html www.baidu.com

# 下载文件，使用远程原始文件名
curl -O https://cn.wordpress.org/latest-zh_CN.zip

# 下载文件并重命名为 wp.zip
curl -o wp.zip https://cn.wordpress.org/latest-zh_CN.zip

# 断点续传下载
curl -C - -O https://cn.wordpress.org/latest-zh_CN.zip

# 仅打印HTTP响应头
curl -I https://cn.wordpress.org/latest-zh_CN.zip

# FTP下载，带账号密码
curl -u liangxu:123456 ftp://www.baidu.com/file.txt

# FTP上传文件
curl -T newfile.txt -u 用户名:密码 ftp://www.baidu.com/dir/
```
📌 面试重点

1. 区分 `-o` 和 `-O`：小写 `-o` 自定义文件名；大写 `-O` 自动沿用远程文件名，非常高频考点。
2. `-I` 只拿响应头，用来快速看状态码、服务器信息，做接口连通性测试。
3. curl 和 wget 对比：curl 擅长**接口调试、发送各类请求（POST / 带 header/cookie）**；wget 更适合单纯批量文件下载。
4. `-s` 静默模式常用于 shell 脚本，屏蔽多余输出。
5. `-T` 上传，支持 ftp/http put 上传文件。
