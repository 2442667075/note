## 一、芯片整体类型（已覆盖，优化表述）

|类型|全称|一句话定义|典型代表|跑什么系统|
|---|---|---|---|---|
|**SoC**|System‑on‑Chip（片上系统）|单颗芯片集成 CPU + 内存控制器 + 各类外设 + 硬件加速器，外接 DDR/Flash 工作|骁龙、RK3568、全志 H618|Linux、Android|
|**MPU**|Microprocessor Unit（微处理器）|仅含处理器核心，**必须**外接 DDR、Flash 才能工作；日常与 SoC 混用|Cortex‑A 单芯片、RK3588（本身也是 SoC）|Linux|
|**MCU**|Microcontroller Unit（微控制器/单片机）|片内自带 RAM 和 Flash，无需外接内存即可独立工作|STM32、GD32、AT32|裸机、FreeRTOS|
|**MPO**|Multi‑fiber Push‑On|❌ **不是芯片**，是多芯光纤连接器，用于光通信|数据中心光模块|与嵌入式开发无关|

> **修正原始资料**：原文件写“MPO 是光纤接头”，表述正确，但建议加上“不是芯片类型”的明确标注。

## 二、SoC 内部硬件加速器/处理单元（已覆盖，补充层级关系）

|单元|全称|核心职能|典型应用场景|是否通常集成在 SoC 内|
|---|---|---|---|---|
|**CPU**|Central Processing Unit|通用逻辑控制、操作系统调度|所有嵌入式设备|是（SoC 一定有）|

## 四、系统软件与启动概念（已覆盖，补充层级关系图文字版）

原始资料已包含 BSP、uboot、Kernel、rootfs，补充一个**嵌入式 Linux 软件栈分层**：

text

应用层     → QT/LVGL/业务程序
        ↓
根文件系统 → rootfs（命令、库、配置）
        ↓
操作系统内核 → Linux Kernel（调度/内存/驱动框架）
        ↓
引导程序   → uboot（初始化硬件，加载内核）
        ↓
硬件层     → SoC + DDR + Flash + 外设

**MCU 侧对应（简化分层）**：

text

应用层     → 业务逻辑（main.c）
        ↓
HAL/LL库  → STM32 HAL 库（硬件抽象层）
        ↓
硬件层     → STM32 芯片 + 片内 Flash/RAM

> **注意**：MCU 没有 uboot、Kernel、rootfs 这三层，直接上电执行片内程序。

## 五、补充原始资料缺失的重要概念（★新增）

### 1. 存储类概念

|概念|全称|说明|
|---|---|---|
|**eMMC**|Embedded Multi‑Media Card|嵌入式闪存存储芯片，相当于焊在板子上的 SD 卡，常用作 Linux 系统的根文件系统存储介质|
|**NAND Flash**|NAND 型闪存|原始闪存颗粒，需要 ECC 校验和坏块管理，常用于低成本嵌入式 Linux 系统|
|**SPI NOR Flash**|SPI 接口 NOR 型闪存|小容量（几 MB~几十 MB），常用于存储 uboot 和 kernel，可直接 XIP（片内执行）|
|**DDR**|Double Data Rate SDRAM|系统运行内存，SoC 外接，Linux 内核在此运行，相当于电脑的内存条|

### 2. 总线与互联概念

|概念|全称|说明|
|---|---|---|
|**总线**|Bus|芯片内部或芯片间传输数据的通道，常见 AHB/APB（MCU）、AXI（高性能 SoC）|
|**NoC**|Network‑on‑Chip（片上网络）|高端 SoC 内部互联架构，替代传统总线，支持多核/多加速器高效通信|

### 3. 封装与产品形态概念

|概念|说明|
|---|---|
|**SiP**|System‑in‑Package（系统级封装）——将多颗芯片（SoC + DDR + Flash）封装在一个壳体内，外部看像一颗芯片，但内部是多颗 die|
|**核心板**|将 SoC + DDR + eMMC + PMIC 焊在小 PCB 上，做成邮票孔或金手指模块，用户只需设计底板|
|**开发板**|核心板 + 底板接口 + 外设插座，用于评估和原型开发，如正点原子、野火 Linux 开发板|

> **面试常见混淆点**：SoC（单芯片设计）vs SiP（多芯片封装）——面试官可能会问“把 DDR 和 SoC 封在一起是 SoC 吗？”答案：**不是 SoC，是 SiP**。

### 4. 电源管理概念

|概念|全称|说明|
|---|---|---|
|**PMIC**|Power Management IC（电源管理芯片）|为 SoC 的各路电源（核心电压 0.8V、IO 电压 1.8V/3.3V、DDR 电压 1.2V）提供稳压供电，是 SoC 系统的“标配搭档”|
|**LDO**|Low Dropout Regulator（低压差线性稳压器）|简单稳压，效率低，适合小电流场景|
|**DCDC**|DC‑DC 转换器|开关电源，效率高，适合大电流供电，SoC 核心电压常用 DCDC|

### 5. 调试与烧录概念

|概念|说明|
|---|---|
|**JTAG/SWD**|MCU 调试接口，用于在线仿真和程序烧录|
|**烧录**|将固件写入 Flash 或 eMMC 的过程，MCU 用烧录器，Linux SoC 通常用 SD 卡启动后 dd 写入 eMMC，或使用烧录工具（如 RK 的 upgrade tool）|
|**串口控制台**|Linux SoC 调试最常用方式，uboot 和内核打印通过 UART 输出，用户通过串口终端操作 Linux 命令行|

### 6. 虚拟化与安全概念（中高端嵌入式面试进阶）

|概念|全称|说明|
|---|---|---|
|**TEE**|Trusted Execution Environment（可信执行环境）|SoC 内部的安全隔离区（如 ARM TrustZone），运行安全 OS（如 OP‑TEE），与普通 OS（Linux）隔离，用于指纹支付、DRM 等安全场景|
|**Hypervisor**|虚拟化管理器|在单颗 SoC 上同时运行多个 OS（如 Linux + RTOS），常用于车载中央计算平台|
|**Secure Boot**|安全启动|从 boot ROM 开始逐级校验 uboot→kernel→rootfs 的数字签名，防止恶意固件篡改|

## 六、一句话面试回答（优化版，覆盖核心）

> **问：什么是 SoC？**
> 
> SoC 即片上系统，单颗芯片集成了 CPU、内存控制器、GPU 以及各类高速外设接口，可外接 DDR 和 Flash，能够运行完整 Linux 或 Android 操作系统。与 MCU（片内自带小容量 RAM/Flash，跑裸机/RTOS）相比，SoC 算力更强、外设更丰富，常见于嵌入式 Linux 人机界面、多媒体网关和智能手机。

> **问：SoC 和 MCU 的核心区别？**
> 
> MCU 片内自带 RAM 和 Flash，无需外部内存即可工作，跑裸机或 RTOS；SoC 需要外接 DDR 和 Flash，跑完整 Linux 系统。SoC 内部还常集成 NPU/GPU/ISP 等硬件加速单元。

> **问：Linux 系统在 SoC 上的启动流程？**
> 
> 上电 → BootROM（片内固件）初始化基础硬件 → 加载 uboot（初始化 DDR/串口，拷贝内核到 DDR）→ uboot 跳转到 Kernel → Kernel 启动并挂载 rootfs 根文件系统 → 系统就绪，运行应用。
