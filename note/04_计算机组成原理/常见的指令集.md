# 1.1.1 常见 CPU 指令集架构

## 一、什么是 CPU 指令集？

CPU 要执行程序，本质上就是不断执行一条条**机器指令（Instruction）**。

**指令集架构（ISA，Instruction Set Architecture）**可以理解为：

> 软件与 CPU 硬件之间约定的一套“语言”和规则。

ISA 主要规定：

- CPU 支持哪些指令
    
- CPU 有哪些寄存器
    
- 指令如何操作数据
    
- 如何访问内存
    
- 数据类型和数据宽度
    
- 异常、中断等机制
    
- 函数调用相关约定
    

程序从 C 语言最终变成 CPU 可以执行的机器指令：

```text
C语言源代码
    ↓
编译器 GCC
    ↓
汇编代码
    ↓
汇编器
    ↓
机器指令
    ↓
CPU执行
```

---

# 二、CISC：复杂指令集

## 2.1 基本概念

**CISC（Complex Instruction Set Computer）**

中文：

> 复杂指令集计算机

典型代表：

```text
x86
x86-64
```

主要代表厂商：

```text
Intel
AMD
```

主要应用：

```text
PC
服务器
工作站
```

---

## 2.2 CISC 的主要特点

### ① 指令数量较多

CISC 通常提供大量不同功能的指令。

一条指令可以完成相对复杂的操作。

例如概念上：

```text
读取数据
    ↓
进行计算
    ↓
写回数据
```

可以通过比较复杂的一条指令完成。

---

### ② 指令长度通常可变

x86 指令属于典型的**变长指令**。

不同指令占用的字节数可能不同：

```text
指令A → 1字节
指令B → 3字节
指令C → 7字节
```

因此 CPU 的取指和译码相对复杂。

---

### ③ 指令功能比较复杂

CISC 的设计思想之一：

> **让一条指令完成更多工作。**

可以简单理解成：

```text
CISC：

一条复杂指令
      ↓
完成多个相关操作
```

而 RISC 更倾向于：

```text
RISC：

LOAD
 ↓
ADD
 ↓
STORE
```

使用多条简单指令完成操作。

---

### ④ 内存访问方式比较灵活

以传统 x86 为例，很多指令可以直接操作内存中的数据。

因此指令的寻址方式比较丰富。

---

## 2.3 CISC 的典型代表

```text
x86
x86-64
```

例如：

```text
Intel Core
Intel Xeon
AMD Ryzen
AMD EPYC
```

都属于 x86/x86-64 指令集生态。

---

# 三、RISC：精简指令集

## 3.1 基本概念

**RISC（Reduced Instruction Set Computer）**

中文：

> 精简指令集计算机

典型代表：

```text
ARM
RISC-V
MIPS
PowerPC
```

对于嵌入式 Linux 来说，最重要的是：

```text
ARM
RISC-V
```

---

# 四、RISC 的核心思想

RISC 并不是简单地：

> “指令越少越好”。

更准确的理解是：

> **使用相对简单、规则的指令，使 CPU 更容易进行流水线执行和高效实现。**

复杂操作可以拆分成多条简单指令：

```text
复杂操作
   ↓
拆分成多个简单指令
   ↓
CPU执行
```

例如：

```text
LOAD
 ↓
ADD
 ↓
STORE
```

---

# 五、RISC 的主要特点

## 5.1 指令相对简单

典型指令：

```text
LOAD
STORE
ADD
SUB
AND
OR
JUMP
```

每条指令通常完成比较明确的功能。

---

## 5.2 通常采用 Load/Store 架构

这是理解 ARM、RISC-V 非常重要的概念。

典型 RISC CPU 通常：

> **只有 Load / Store 指令直接访问内存。**

数据计算主要在寄存器之间进行。

典型过程：

```text
内存
 ↓
LOAD
 ↓
寄存器
 ↓
ALU进行计算
 ↓
寄存器
 ↓
STORE
 ↓
内存
```

例如 ARM 汇编：

```asm
ldr r0, [r1]       // 从内存加载数据
add r0, r0, r2     // 寄存器之间进行加法
str r0, [r1]       // 将结果写回内存
```

可以抽象成：

```text
Memory
   ↓
Register
   ↓
ALU
   ↓
Register
   ↓
Memory
```

---

## 5.3 指令格式通常比较规则

传统 RISC 设计倾向于使用规则的指令格式。

例如：

```text
32 bit
32 bit
32 bit
32 bit
```

这样有利于：

```text
取指
 ↓
译码
 ↓
执行
```

但是要注意：

> **不能简单认为 RISC 的指令一定等长。**

例如：

- ARM 有 ARM 指令和 Thumb/Thumb-2
    
- RISC-V 有压缩指令扩展 C
    

所以现代 RISC 架构也可能存在不同长度的指令。

---

## 5.4 通用寄存器通常比较多

RISC 架构通常倾向于提供较多的通用寄存器。

原因：

> 尽可能把数据放在 CPU 寄存器中，减少频繁访问内存。

例如：

```text
内存
 ↓
Register
 ↓
运算
 ↓
Register
```

寄存器之间的操作通常比访问 RAM 更高效。

---

# 六、为什么 RISC 非常适合嵌入式？

RISC 的设计通常有利于实现：

```text
简单指令
   ↓
规则译码
   ↓
流水线执行
   ↓
较高的能效
```

因此 ARM 等 RISC 架构广泛应用于：

```text
MCU
手机
平板
嵌入式设备
汽车电子
网络设备
AI设备
嵌入式Linux
```

---

# 七、ARM 是什么？

这是嵌入式 Linux 学习中非常容易混淆的概念。

> **ARM 不是一颗具体的 CPU。**

ARM 是一套处理器架构和指令集生态。

例如：

```text
ARM
│
├── Cortex-M
│   ├── Cortex-M0
│   ├── Cortex-M3
│   ├── Cortex-M4
│   └── Cortex-M33
│
└── Cortex-A
    ├── Cortex-A7
    ├── Cortex-A9
    ├── Cortex-A53
    ├── Cortex-A55
    ├── Cortex-A72
    └── Cortex-A76
```

其中：

```text
Cortex-M
    ↓
主要用于 MCU
```

而：

```text
Cortex-A
    ↓
主要用于高性能应用处理器
    ↓
可以运行 Linux
```

# 八、结合嵌入式 Linux 理解 ARM

## 8.1 i.MX6ULL

你的 i.MX6ULL 可以理解成：

```text
NXP
 ↓
i.MX6ULL
 ↓
Cortex-A7
 ↓
ARMv7-A
 ↓
ARM ISA
 ↓
Linux
```

也就是说：

```text
i.MX6ULL
```

是 SoC 型号。

而：

```text
Cortex-A7
```

是 CPU 内核。

而：

```text
ARMv7-A
```

属于 ARM 架构版本。

---

## 8.2 RK3568

RK3568：

```text
Rockchip
 ↓
RK3568
 ↓
Cortex-A55
 ↓
ARMv8-A
 ↓
ARM64 / AArch64
 ↓
Linux
```

---

## 8.3 RK3588

RK3588：

```text
Rockchip
 ↓
RK3588
 ↓
Cortex-A76 + Cortex-A55
 ↓
ARMv8-A
 ↓
ARM64
 ↓
Linux
```

# 九、RISC-V

## 9.1 什么是 RISC-V？

RISC-V 是一种现代的 RISC 指令集架构。

最大的特点之一：

> **RISC-V ISA 是开放标准。**

ARM：

```text
ARM
 ↓
商业授权
 ↓
芯片厂商实现
```

RISC-V：

```text
RISC-V ISA
 ↓
开放标准
 ↓
不同厂商实现
 ↓
形成不同CPU
```

所以：

> **RISC-V 不是一颗 CPU，而是一套 ISA。**

---

# 十、RISC-V 指令集扩展

RISC-V 采用模块化设计。

例如：

```text
RV32
RV64
```

代表：

```text
32位
64位
```

常见扩展：

```text
I → 基础整数指令集
M → 乘法和除法
A → 原子操作
F → 单精度浮点
D → 双精度浮点
C → 压缩指令
```

例如：

```text
RV64GC
```

可以理解为：

```text
RV64
+
G（常见基础扩展组合）
+
C（压缩指令）
```

# 十一、CISC 与 RISC 对比

|对比|CISC|RISC|
|---|---|---|
|中文|复杂指令集|精简指令集|
|英文|Complex Instruction Set Computer|Reduced Instruction Set Computer|
|代表|x86/x86-64|ARM、RISC-V、MIPS|
|指令数量|通常较多|通常较精简|
|指令复杂度|较复杂|相对简单|
|指令长度|通常变长|通常更加规则|
|内存访问|比较灵活|通常采用 Load/Store|
|通用寄存器|相对较少/设计复杂|通常较多|
|译码|相对复杂|相对简单|
|流水线|可以非常复杂|传统设计更容易流水线化|
|应用|PC、服务器|MCU、手机、嵌入式、SoC|

---

# 十二、几个常见误区

## 误区1：RISC 一定比 CISC 快

错误。

不能简单认为：

```text
RISC = 快
CISC = 慢
```

现代 CPU 性能取决于：

```text
CPU微架构
主频
IPC
流水线
缓存
分支预测
乱序执行
执行单元
制程
功耗
编译器
```

等很多因素。

---

## 误区2：RISC 指令一定等长

错误。

传统 RISC 倾向于使用规则、固定长度的指令，但现代架构也可以支持不同长度。

例如：

```text
ARM Thumb-2
RISC-V C扩展
```

---

## 误区3：ARM 就是一种 CPU

错误。

ARM 是架构/指令集体系。

例如：

```text
Cortex-A7
Cortex-A53
Cortex-A55
Cortex-A76
```

是不同的 CPU 核心。

而：

```text
i.MX6ULL
RK3568
RK3588
```

是具体 SoC。

---

## 误区4：RISC-V 就是一颗 CPU

错误。

RISC-V 是：

```text
ISA
```

不同公司可以基于 RISC-V 设计不同的 CPU。

---

# 十三、最重要的层次关系

学习嵌入式 Linux 时一定要建立下面这个概念：

```text
                 ISA
                  ↓
              CPU微架构
                  ↓
               CPU核心
                  ↓
                 SoC
                  ↓
                开发板
                  ↓
              Bootloader
                  ↓
              Linux Kernel
                  ↓
                Driver
                  ↓
              Application
```

例如你的开发板：

```text
ARMv7-A
   ↓
Cortex-A7
   ↓
i.MX6ULL
   ↓
I.MX6U-ALPHA开发板
   ↓
U-Boot
   ↓
Linux Kernel
   ↓
设备树 / 驱动
   ↓
Linux应用程序
```


# 十五、一句话总结

> **CISC 通过较复杂、功能丰富的指令完成操作；RISC 倾向于使用简单、规则的指令，并通过大量寄存器、Load/Store 架构和流水线等方式实现高效执行。**

对于嵌入式 Linux：

```text
x86
 ↓
PC / Server

ARM
 ↓
i.MX6ULL / RK3568 / RK3588
 ↓
嵌入式Linux

RISC-V
 ↓
新兴开放ISA
 ↓
嵌入式 / MCU / Linux / AI等
```
