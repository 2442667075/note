## 1. 嵌入式系统整体结构

嵌入式系统可以简单理解为：

> **以特定硬件为基础，运行专用软件，实现特定功能的计算机系统。**

典型嵌入式 Linux 系统：

```
┌──────────────────────────────┐
│          Application         │
│       C/C++ / Qt / App       │
├──────────────────────────────┤
│       Library / API          │
│      libc / POSIX / Qt       │
├──────────────────────────────┤
│       Linux Kernel           │
│ Process / Memory / Network   │
│ FileSystem / Driver / IPC    │
├──────────────────────────────┤
│       BSP / Device Tree      │
├──────────────────────────────┤
│       Bootloader             │
│          U-Boot              │
├──────────────────────────────┤
│        Hardware              │
│ CPU / RAM / Flash / UART     │
│ GPIO / SPI / I2C / CAN / USB │
└──────────────────────────────┘
```

---

# 2. CPU

CPU：

> Central Processing Unit，中央处理器。

主要负责：

- 执行指令
- 数据运算
- 控制系统运行
- 访问内存
- 控制外设

典型结构：

```
CPU
├── ALU
├── Register
├── Control Unit
├── Cache
└── MMU
```

---

# 3. Register —— 寄存器

## 3.1 什么是 Register？

Register：

> **寄存器是 CPU 或外设内部用于保存数据、控制信息和状态信息的高速存储单元。**

CPU 寄存器例如：

```
R0
R1
R2
...
PC
SP
```

不同 CPU 架构的寄存器名称和数量不同。

---

## 3.2 Register 的特点

|特点|Register|
|---|---|
|位置|CPU/外设内部|
|速度|非常快|
|容量|很小|
|主要作用|运算、控制、保存状态|
|访问|CPU直接使用|

---

## 3.3 外设寄存器

GPIO、UART、SPI、I2C、CAN 等外设内部也存在寄存器。

例如 GPIO：

```
GPIO
├── DATA Register
├── Direction Register
├── Pull-up Register
├── Pull-down Register
└── Interrupt Register
```

软件修改寄存器：

```
CPU
 ↓
写 Register
 ↓
GPIO Controller
 ↓
GPIO Pin
 ↓
LED
```

所以：

> **嵌入式底层开发的本质之一，就是通过寄存器控制硬件。**

---

# 4. ROM

ROM：

> Read Only Memory，只读存储器。

传统 ROM：

> 数据写入以后，正常工作时只能读取。

但是现代嵌入式开发中，“ROM”经常被泛指：

```
Flash
EEPROM
NOR Flash
NAND Flash
```

等非易失性存储器。

---

# 5. RAM

RAM：

> Random Access Memory，随机存取存储器。

特点：

- CPU运行程序时使用
- 读写速度快
- 掉电后数据通常丢失
- 用来保存运行中的程序和数据

例如：

```
RAM
├── Kernel
├── Application
├── Stack
├── Heap
├── Buffer
└── Cache相关数据
```

可以简单理解：

```
Flash ≈ 长期存储
RAM   ≈ 运行内存
```

---

# 6. SRAM

SRAM：

> Static Random Access Memory，静态随机存取存储器。

特点：

- 速度快
- 不需要周期性刷新
- 成本较高
- 容量通常较小

常见于：

```
MCU内部 SRAM
CPU Cache
SoC片上RAM
```

例如 MCU：

```
MCU
├── Flash
└── SRAM
```

---

# 7. DRAM

DRAM：

> Dynamic Random Access Memory，动态随机存取存储器。

特点：

- 容量大
- 成本低
- 需要刷新
- 速度通常低于 SRAM

嵌入式 Linux 开发板常见：

```
DDR3
DDR4
LPDDR
```

例如：

```
i.MX6ULL
   │
   └── DDR
```

Linux 系统运行时的大量数据就在 DDR 中。

---

# 8. Flash

Flash：

> 一种非易失性存储器。

特点：

- 掉电不丢数据
- 可以擦除
- 可以重新写入
- 用于保存程序和系统数据

常见：

```
NOR Flash
NAND Flash
SPI NOR
SPI NAND
eMMC
```

例如嵌入式 Linux：

```
Flash / eMMC / SD
├── Bootloader
├── Linux Kernel
├── Device Tree
├── RootFS
└── Application
```

---

# 9. NOR Flash

NOR Flash：

特点：

- 可以随机读取
- 读取速度快
- 可以直接执行程序（XIP）
- 容量通常比 NAND 小

常用于：

```
Bootloader
Firmware
配置数据
```

---

# 10. NAND Flash

NAND Flash：

特点：

- 容量大
- 成本低
- 适合大量数据存储
- 需要考虑坏块、ECC 等问题

常用于：

```
Linux系统
RootFS
大量数据
```

---

# 11. EEPROM

EEPROM：

> Electrically Erasable Programmable Read-Only Memory。

特点：

- 掉电不丢数据
- 可以电擦除
- 可以保存少量配置数据

例如：

```
设备参数
MAC地址
校准参数
配置数据
```

---

# 12. Cache

Cache：

> CPU 与 RAM 之间的高速缓存。

结构：

```
CPU
 ↓
Register
 ↓
L1 Cache
 ↓
L2 Cache
 ↓
L3 Cache
 ↓
RAM
 ↓
Flash / Storage
```

规律：

> **越靠近 CPU，速度越快，容量越小，成本越高。**

---

# 13. Memory Map

Memory Map：

> **内存地址空间映射表。**

CPU通过地址访问不同硬件。

例如：

```
0x00000000
    ↓
Boot ROM

0x08000000
    ↓
Flash

0x20000000
    ↓
SRAM

0x80000000
    ↓
DDR

0x40000000
    ↓
Peripheral
```

具体地址取决于芯片。

核心思想：

> **不同地址对应不同硬件资源。**

---

# 14. MMIO

MMIO：

> Memory Mapped I/O，内存映射 I/O。

核心思想：

> **把外设寄存器映射到 CPU 的地址空间中。**

例如：

```
CPU
 ↓
访问 0x40000000
 ↓
GPIO Register
 ↓
GPIO Hardware
```

所以 CPU 看起来是在访问一个地址：

```
*(volatile unsigned int *)0x40000000
```

实际上操作的是：

```
GPIO硬件寄存器
```

# 24. Bootloader

```

- 加载 Kernel

# 27. HAL

HAL：

> **屏蔽底层硬件差异。**

例如底层：

```

 ↓

 ↓
Driver
 ↓

# 30. BSP 和 SDK 的区别

简单记：

```
SDK
→ 给开发者开发软件使用

BSP
→ 给某个平台/开发板提供底层支持
```

例如：

```
SDK
├── API
├── Library
├── Example
└── Tool

BSP
├── Bootloader
├── Kernel
├── Device Tree
└── Driver
```

实际厂商资料中两者经常会混合打包。
